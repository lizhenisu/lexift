# PixPin 刷新截图研究与 Lexift 选择

## 实测与静态证据

对象为 PixPin 3.5.5.1，SHA256 `6dca2e4f183c02d02cb42c0756643cf525fd4c18ad1ff93727e815558da9416d`。使用已知颜色夹具进行实际操作：单击刷新后，421×281 选区和红色新增标注保留，底图由蓝变绿；撤销移除新增标注，底图仍为绿色。按住刷新时观察到桌面变化，松开后冻结。这些运行观察不能说明底层采集 API 或全部缓存策略。

IDA Free 9.4 的汇编证据：`0x1402CF190` 的按下路径传入 true；`0x1402CF1D0` 的松开路径传入 false 后调用 `0x1402C3F60`。后者保存可见性、隐藏交互 UI，经约 150ms 的 QTimer singleShot 到 `0x1402BEC80`、`0x1402BA980`，再由 `0x1402C7DC0` 更新各屏底图并恢复 UI。`0x1402C79D0` 内实际采集通过间接调用，尚未确认具体 API。`ScreenShotView::refreshScreenShot`（`0x1402C43F0`）属于初始化／重置，不能把同名符号当作用户刷新实现。

使用 IDA 原生 MCP 读取汇编；REA 桥接访问失败，没有反编译器证据。实测截图、汇编导出及摘要留在忽略目录 `target/pixpin-refresh-research/`，不提交程序副本或数据库。

## Lexift 实现选择

首版仅单击刷新一次。复用所属窗口挂起确认及 GDI／WGC 像素采集，不复制固定 150ms 等待，不重新枚举窗口或查询 UIA。候选采集、编辑反馈和 App 底图提交分阶段验证身份；完成前禁止输出，失败恢复旧帧。底图刷新不进入标注撤销栈，仍保留旧文档及原截图来源。

功能行为见[截图模式](../features/screenshot-mode.md)，实际通过项与未覆盖范围见[验证记录](../releases/screenshot-refresh.md)。
