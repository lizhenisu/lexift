# PixPin 长图结果编辑器研究

研究日期：2026-10-20。范围：长截图点击“编辑”后的独立图片编辑窗口，包括图片平移、缩放、标注输入、窗口和工具条。本轮仅研究，没有修改 Lexift 编辑器源码。

## 1. 证据与结论边界

- 安装版 PixPin 3.5.5.1；分析副本 SHA-256：`6dca2e4f183c02d02cb42c0756643cf525fd4c18ad1ff93727e815558da9416d`。
- REA 接入 IDA，检查 EXE 内编辑器构造、事件过滤、图片安装、视图缩放及工具条定位。反编译是当前分析数据库的解释，不是原始源码；未解析的间接调用不作确定推断。
- 实机从自建 Tk 行号文档进入长截图，得到 **701×2087** 图片，再点击编辑。当前实测显示器为 **1920×1080、DPI 120（125%）**。
- 实测包括：默认图片拖动、无修饰滚轮、空格切换、绘制后再次缩放、100% 停靠、图片向左平移、标题栏拖动及工具条跟随。
- 全部反编译 JSON、过程图片和脚本存于忽略目录 `target/pixpin-editor-research/`。`clean-selection.png` 起为本轮成功链路；此前的 `selection.png`、`long-start*.png` 等诊断图不是成功交接证据。最终使用编辑器局部截图，避免展示其他应用内容。

**核心结论**：PixPin 将结果作为独立图片场景编辑。背景、原图和标注通过共同的场景坐标呈现；图片浏览由视口平移与缩放完成。大范围场景允许图片离开居中位置。Lexift 当前使用有边界的 ScrollView，禁用了图片拖动，也没有鼠标锚点缩放，因此缺少用户要求的自由浏览体验。

## 3. 对象与处理链路

### 3.1 从长图到独立编辑器

此前已定位 `LongShotWidget::edit`（`0x140211220`）：取得长图结果后调用编辑器构造 `0x1401FA330`，随后退役长截图组件。编辑器继承 `PixDialog`，使用 `:/qss/ImageEditWindow` 样式资源。

主要链路：

```text
长截图结果 QImage
  → 独立 ImageEditWindow / PixDialog
  → QPixmap 原图项 + 标注场景
  → PixImageView / QGraphicsView 子类
  → 视口变换、输入路由、底部状态
  → 独立 ActionsBar 跟随编辑窗口
```

这解释了完成后能够继续平移、缩放、画图，且浏览范围不再受桌面选区限制。此处没有证据证明它采用特殊 GPU 渲染器、瓦片解码或特定超长图分块方案，不作此类推断。

### 3.2 图片场景与层次

`0x1402008B0` 初始化视图，`0x140201F70` 安装图片：

- 视图为自定义 `PixImageView`，基于 `QGraphicsView`；场景范围设为 **`(-100000,-100000,200000,200000)`**。
- 点阵背景项 Z 为 **−2000**，原图项 Z 为 **−1000**；原图项不直接接收鼠标按钮或 hover。
- 原图同时交给标注场景管理器；原图有效范围从图片逻辑尺寸构造，而非使用窗口大小。
- 水平和垂直滚动条均隐藏。视图内建 dragMode 设置为 NoDrag，但编辑器自己处理拖动事件，因此不能从这一设置推断“不能拖图片”。
- 变换锚点及窗口缩放锚点设为 NoAnchor；鼠标锚点缩放通过显式调用实现。

大场景提供图片外的移动空间，点阵背景清楚区分图像边缘与工作区。这里仍是有限场景，不应描述成数学意义的无限画布。

### 3.3 图片拖动

事件过滤器 `0x1401FE0B0` 在没有活动绘图工具时接管左键：

1. 按下：保存视口鼠标位置，进入拖动，光标切换为握住的手。
2. 移动：将前一次和当前视口位置分别 `mapToScene`，取场景差值，再对视图执行 `translate`。
3. 松开：清除拖动状态，恢复张开的手；离开事件也有清理分支。
4. 每次更新背景与视口相关反馈。

它移动的是观察图像的变换，原图尺寸及标注坐标不随拖动修改。按键切换后的工具状态决定鼠标交给浏览还是绘图。

### 3.4 滚轮与锚点缩放

同一事件过滤器在无活动绘图工具时读取纵向 angleDelta，必要时回退 pixelDelta：

- 向上乘 **1.15**，向下除 **1.15**。
- 缩放限制 **0.1～10.0**；跨越 1.0 时停靠到精确 100%。
- 缩放变化过小时跳过更新。
- 将鼠标视口位置及目标比例传给 `0x140201E90`，后者调用 **`PixImageView::scaleAtPoint`**，再更新标注反馈、背景及缩放状态。

`scaleAtPoint` 的具体函数体在 PixWidget.dll，本轮未继续恢复其内部实现。不过 EXE 的调用参数、函数名和实测均支持鼠标锚点缩放。不要将下式当成恢复的 PixPin 源码；它是实现同类交互的等价视口约束：

```text
视口位置 p = 图片位置 q × 缩放 s + 平移 t
鼠标锚点 m 对应 q = (m - t) / s
缩放到 s' 后，t' = m - q × s'
```

只修改比例、不修正平移，会导致鼠标所指内容跳动；这是 Lexift 当前按钮缩放之外还需要补全的行为。

### 3.5 编辑与拖动模式

`0x140201310` 的空格分支在两种状态间切换：存在活动工具时清除工具，没有活动工具时恢复保存的工具名（初值为 Pencil）。本轮实测是**按一下切换，松手后保持**，不应误写为“按住空格临时拖动”。

绘图工具有效时，编辑器不执行自己的浏览拖动／滚轮分支，让事件进入工具或基类。撤销／重做路由 `0x1401FF4B0` 另检查场景焦点项，避免在文字输入拥有焦点时误操作文档。

本轮没有完整验证所有工具的滚轮语义、空格按住重复、输入法和触控板手势，后续设计不能据此直接照搬全部快捷键。

## 4. 窗口、布局与 UI 组件

- **标题栏**：应用图标、标题及空格操作说明，右侧置顶、最小化和关闭；标题拖动与图片拖动是两个不同入口。
- **主体**：大面积图片视口，圆角边界、点阵背景；没有固定常驻的大排浏览按钮占据上方内容区。
- **底部状态**：缩放百分比与原图尺寸，本轮 `100% / 701×2087`；视图变化更新比例，原图尺寸保持不变。
- **标注工具条**：独立 ActionsBar，与原有标注能力共用；工具参数按需出现。不能将整个工具条误认为编辑器内部布局的一行。
- **初始大小**：`0x1401FC810` 依据鼠标所在屏幕工作区，按约 1000×800 内容尺度及边距限制尺寸并居中；本轮实际外框为 1310×1020 物理像素。不可脱离 DPI、阴影和工作区将原生外框直接写成逻辑尺寸。
- **初始图片位置**：`0x140201F70` 根据宽高两个约束计算整图适应比例，限制范围后重置变换并居中。PixPin 也会把长图缩成窄图，优势来自随后能自然平移和缩放，而非默认始终显示可读的原尺寸。
- **工具条跟随**：`0x1401FC030` 更新编辑主体的全局参考矩形及所属工作区，刷新工具条 DPI，重定位并抬起；窗口移动与缩放回调均调用它。
- **关闭**：`0x1401FCD50` 清理拖动、工具状态、场景焦点和事件过滤器，关闭并 deleteLater 所属工具条。

## 5. Lexift 当前实现对照

以本轮工作树源码为准，历史验证记录不能替代实际输入能力。

| 项目 | PixPin 证据 | Lexift 当前状态 |
| --- | --- | --- |
| 图片平移 | 自定义按下／移动／松开，场景变换 | `annotation-canvas.slint` 明确 `mouse-drag-pan-enabled: false`；`screenshot.rs` 的 image editing 鼠标模式直接消费输入，没有平移 |
| 图片外移动空间 | 大场景、背景与图片分离 | ScrollView 范围由图片尺寸决定，小图强制居中，滚动偏移夹紧，无法任意移动 |
| 滚轮浏览 | 拖动模式围绕鼠标缩放 | 当前仅修改 content-x/y，没有缩放及鼠标锚点 |
| 模式切换 | 空格切换浏览／上次绘图工具 | 没有对应浏览手势状态或空格分支 |
| 缩放状态 | 视图统一变换、100% 停靠 | 有适应宽度／整图／100%／加减按钮，但加减只改比例，没有锚点修正 |
| 窗口移动 | 标题移动，图片状态保留，工具条跟随 | 已有标题拖动与工具条跟随；此前测试的窗口拖动不能证明图片可平移 |
| 图片与输出坐标 | 原图场景与视口分离 | 已有原图坐标映射、DPI 换算和原分辨率输出，应保留 |

主要文件：`crates/lexift-ui/ui/annotation-canvas.slint`、`crates/lexift-ui/src/annotation/screenshot_long_editor.rs`、`crates/lexift-ui/src/annotation/screenshot.rs`、`crates/lexift-ui/src/annotation/pin_editor.rs`。

后续重做应先建立 UI 所属的统一图片视口状态：物理缩放、平移、视口大小和浏览手势；绘制、命中、文字输入及光标使用同一正反变换。无需为了这一视图能力新增 Core Port，也不应把视口平移写入标注文档或撤销历史。具体交互选择和实施步骤另行制定，本研究不自动变更实现。

## 7. 未覆盖范围

- 本轮实机为 125% 单屏；100%、跨屏切 DPI、窗口边缘缩放及触控板不作为通过项。
- 没有对极限长图的内存、瓦片化、GPU 路径或渲染耗时作结论。
- 没有完整验证所有工具下的滚轮、对象选择、文字输入、撤销和输出；红线随视图对齐只是本次局部观察。
- 此前完成画面研究主要验证了窗口可移动及工具条跟随，漏测了图片本身的平移、鼠标锚点缩放与模式切换。本记录补足该差距，不将已有 Lexift 视口坐标测试误写成自由图片拖动验收。
