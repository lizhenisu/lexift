# PixPin 长截图链路与交互研究

研究日期：2026-10-20。目的：解释 Lexift 首版长截图在采集范围、预览和完成画面上的差距，作为下一轮设计依据。本轮仅研究与整理文档，没有修改长截图实现。

## 1. 依据与边界

- **实机观察**：本机已安装 PixPin，文件元数据版本 3.5.5.1；使用自建 Tk 行号文档，不使用用户正文。执行框选、手动滚动、超长预览、进入编辑、移动编辑窗口、直接复制。
- **静态分析**：通过 REA 连接 IDA，检查实际二进制的相关调用链。安装程序及分析副本 SHA-256 为 `6dca2e4f183c02d02cb42c0756643cf525fd4c18ad1ff93727e815558da9416d`。反编译是当前 IDA 数据库的解释，不是恢复的原始源码；间接调用、线程归属和未解析函数不作确定推断。
- **官方资料**：[长截图教程](https://pixpin.cn/docs/capture/long-capture)说明区域框、方向、开始／停止、裁剪、直接输出与绿色匹配框；与本机界面存在版本差异。官方功能说明不能替代本机操作证据。
- 全部脚本、截图、GIF、窗口快照及 REA JSON 位于忽略目录 `target/pixpin-long-research/`。没有登录、购买或绕过会员限制，没有更改项目依赖与配置。

## 2. 实际交互链路

### 2.1 从静态选区进入长截图

1. Ctrl+1，自由框选 `(300,260)` 至 `(1000,810)`；PixPin 标签显示 **701×551**，此路径包含两个端点。
2. 点击长截图按钮，出现实时采集区、区域外灰色遮罩、下方紧凑操作条及右侧独立预览。本次路径自动开始并产生首帧。
3. **蓝色采集边框始终保留**，区内显示真实应用，滚轮实际到达原 Tk 控件；静态编辑时的八个调整点不继续显示。
4. 操作条显示不断增长的输出尺寸，提供方向、滚动相关控制、裁剪、编辑、OCR、贴图、保存、关闭和复制等入口。并非把说明、状态、按钮和缩略图都放入一个大卡片。

证据：`03-long-initial.png`、`03-long-initial-windows.json`。

### 2.2 滚动与预览

- 夹具每档滚动 96 个物理像素。第一轮连续 16 档，尺寸从 **701×551** 变为 **701×2087**，恰好增加 1536px。
- 预览的可见图像宽度约 **244 个物理像素**。短图阶段保持宽度、增加高度；本次布局下底部贴近采集区下边，向上增长。
- **达到可见高度上限后，不再把整图缩到更窄**。第二轮 40 档得到 **701×4391**，预览只显示长图的一段尾部，顶部出现超出提示；绿色矩形标出当前采集帧对应的位置。
- 原生预览 HWND 在该轮增长中不变。其窗口范围接近整屏高度，实际绘制内容只占其中一段；不能拿 HWND 外框当作可见缩略图尺寸。
- 这是一种随当前采集位置更新的局部预览，不是始终展示整图的缩略图。尚未验证预览区自身是否支持鼠标浏览，不据此增加此类功能承诺。

证据：`scroll-00.png` 至 `scroll-16.png`、`scroll-preview.gif`、`extended-16.png`、`extended-24.png`、`extended-40.png`。

### 2.3 完成有不同出口

图片自身的拖动、鼠标锚点缩放及空格模式切换，见后续专项[长图结果编辑器研究](pixpin-image-editor-research.md)。本节原有“移动编辑窗口”观察不能替代图片视口交互验证。

**进入编辑**：实际点击编辑按钮后，退出灰色采集画面，打开可移动的独立图片编辑器。第一次原生外框 `[625,160,1935,1220]`，画布居中显示长图，周围是点状背景；标题说明空格切换编辑／拖动，底部显示 `缩放:40%`、`尺寸:701×2087`，标注工具条另附在窗口下方。拖动标题后，窗口与工具条一起移动。

PixPin **也会把整张长图缩小以适应编辑窗口**，不能将其描述为始终保持可读原尺寸。区别在于有明确的窗口、居中画布、缩放与原图尺寸反馈，而非几乎铺满桌面的容器中出现一条贴边窄图。

**直接复制**：第二轮点击采集条复制按钮，系统剪贴板序号改变，读取到实际 **701×4487** 图像，采集画面关闭；无需先进入编辑。复制前比 4391px 多出的 96px 来自本轮滚动控制观察。头尾抽样未见蓝边框、绿色框或工具条；本轮没有做整图参考像素比对，因此不将抽样写成完整拼接正确性验收。

证据：`06-after-edit.png`、`06-after-edit-windows.json`、`07-editor-moved.png`、`long-output-clipboard.png`、`long-output.json`、`long-output-head-tail.png`、`11-after-copy.png`。

官方教程中的开始／停止会返回可调整范围的停止状态，不能直接等同 Lexift 保留结果的暂停／继续。静态代码另有清空当前截图确认。此次没有完整执行停止确认链，不将 `10-stop-state.png` 当作已停止证据。`edit-transition-*` 是第一次未成功触发编辑时的诊断图片，也不作交接动画依据。

## 3. UI 与窗口职责

本机长截图不是一个大窗口中塞入所有内容。原生快照可辨认如下职责：

| 职责 | 本次原生证据 | 用户看到的作用 |
| --- | --- | --- |
| 采集边框 | 首轮 HWND 2295446，范围 `[296,256,1005,815]`，扩展样式 `0x800a8` | 持续标明真实采集范围；区内输入可到原应用 |
| 外围遮罩 | HWND 2820578，覆盖主屏，扩展样式 `0x80028` | 降低区域外干扰，不冻结区内内容 |
| 操作条 | HWND 1902726，扩展样式 `0x80088` | 紧凑、可操作的控制面；原生外框大于实际绘制条，不能直接用其宽度作 UI 尺寸 |
| 长图预览 | HWND 1837574，原生范围 `[1018,-5,1278,1445]`，扩展样式 `0x800a8` | 与操作条分开，蓝色外沿、绿色当前帧、局部图像预览 |
| 结果编辑器 | 独立 Qt 窗口及另一个工具条 | 图片视口、缩放、标注、后续输出 |

这些 Qt 窗口的角色和原生样式，加上实际原应用收到滚轮，支持“边框／遮罩／操作条／预览分离”的结论；尚不能恢复全部 Qt 子控件树。Lexift 可借鉴职责分离，但仍须遵守自己的辅助窗口与生命周期规则。

## 4. 静态处理链路

### 4.1 抓取与调度

`0x140213FD0` 在有效采集状态下裁切目标屏幕范围，调用 `PixScreenManager::grabScreen`，将 QPixmap 转为 QImage，调用拼接，再更新尺寸及反馈；失效分支停止 QTimer。该路径还存在自动滚动开关分支：鼠标在范围内时调用 `SimulateMouseScroll`，按采集轴向逻辑尺寸选取不同滚动量。

本机点击对应滚动控制后按钮变蓝，在没有再发送轮滚消息的观察段，原应用前进一行、结果增加 96px；因此不能再将当前安装版简单描述为“仅手动滚动”。本次没有验证持续自动滚动的稳定性，也不建议把自动滚动并入 Lexift 当前首版范围。

**尚未确认这条 `grabScreen` 的最终系统采集 API、实际定时器周期、完整线程归属及排队策略**。不能仅凭其他截图链路的导入表就认定长截图使用 WGC、BitBlt、Desktop Duplication 或 GPU。

### 4.2 位移估计与接受

调用关系：

```text
LongShotWidget 采集处理 0x140213FD0
  → PixScreenManager::grabScreen → QPixmap → QImage
  → 拼接入口 0x1403F1A10
      → 预处理 0x1403F14E0
      → 位移估计 0x1403F6530
          → 变化区域与掩码 0x1403F73A0
          → 多尺度候选搜索
          → matchImageFast 0x1403F7820
      → 半帧输入 0x1403F12C0，失败回退完整帧
      → PixLongImage::contactImage 0x1403F2930
  → 结果状态、尺寸、当前帧预览
```

- 预处理先统一 QImage 格式，经单通道图像转换，按轴向作归一化／缩小。入口传入 `512` 的预处理尺寸限制；不应未经校准就照搬到本项目。
- 位移估计不是“看到 OpenCV 字符串便推测模板匹配”：已恢复自定义 `matchImageFast`。它要求同尺寸单通道输入，在掩码有效的重叠像素中计数，**灰度绝对差大于 10** 计为不匹配，得分是“不匹配数／有效数”；无有效像素返回极大值。
- 上层存在粗到细搜索，分数不满足约 **0.3** 条件时拒绝；另有变化区域面积与位移范围限制。阈值属于该路径的实现细节，不代表其对所有输入具有已证实的准确率。
- 匹配位移映射回原图坐标。逻辑当前位置可以落在已有图像内，也能向头部或尾部扩展；并非每次来帧都追加，也不依赖滚轮档数直接拼接。
- 半帧输入构造按方向选前／后半帧并调整逻辑位置；构造失败确实回退完整帧。

### 4.3 分块、预览与输出

- `PixLongImage::contactImage` 校验固定轴宽与通道数、块范围、覆盖和不允许的空隙；维护多块 QImage，而非每次建立一张完整大图。块高度与每行字节数及预算相关，实际预算值本轮未恢复。
- `0x140218990` 根据当前逻辑位置、总长度及可见预览容量，计算预览起止段，调用长图区间取图，再传入预览组件，并保存前次视口状态。代码与实机看到的固定宽度、超长后展示局部内容相互印证。
- `LongImagePreview::initGeometry` 对应 `0x140208020`，选择屏幕及方向相关位置；侧边不足时存在内部预览回退。内部预览需要捕获排除，旧 Windows 不支持时会隐藏；不能给所有屏幕布局承诺预览一定在区外。
- `LongShotWidget::edit` 对应 `0x140211220`，导出图片、校验存活、创建图片编辑器，再 `deleteLater` 结束采集组件。该路径对超长图禁用编辑；二进制另有分块编码线程与超长保存分支。不能把首版普通长图编辑的行为推广为任意长度均可编辑。
- OpenCV／OpenCL 构建字符串仍不足以证明此链路使用 GPU；也没有证据证明其块不可变、每帧零复制或没有 UI 线程开销。

## 5. 重做前 Lexift 差距（历史基线）

以本轮工作树为准，旧验证的像素通过不能代替交互体验验收。

| 环节 | 当前 Lexift | PixPin 本次表现 | 建议 |
| --- | --- | --- | --- |
| 采集范围 | 隐藏全部截图画布，也带走边框 | 蓝边框与外围遮罩持续存在 | 单独保留实时透明范围反馈；不要显示旧冻结底图 |
| 控制面 | 固定约 296×360 逻辑像素卡片 | 紧凑横向条 | 控制与预览拆开，控制条可拖动，明确状态与完成入口 |
| 预览 | `thumbnail(220,200)` 适应整图，越长越窄 | 宽度稳定，限高后显示局部；绿色当前帧 | 改为有界局部预览、尾部跟随与当前采集位置标记 |
| 窗口位置 | 遍历工作区选可放位置，可能跑到另一屏 | 本次紧随范围旁 | 先在所属采集屏幕布局，再处理边缘与冲突 |
| 完成 | 几乎全工作区编辑器，整图适应后贴边细长 | 有边界、可移动、居中、有缩放／尺寸状态 | 重新设计图片编辑器容器、居中和视口反馈 |
| 输出路径 | 先进入长图编辑 | 可直接复制，也可进入编辑 | 将直接输出作为后续范围选择，保留标注编辑 |

源码定位：

- `crates/lexift-ui/src/annotation/screenshot_long.rs`：隐藏截图画布、控制窗口准备与布局。
- `crates/lexift-app/src/screenshot_long.rs`：调用 `thumbnail(220,200)`。
- `crates/lexift-core/src/domain/long_capture.rs`：缩略比例同时受宽高上限约束，600×6000 会缩成约 20×200。
- `crates/lexift-ui/ui/long-capture.slint`：预览和控制放在同一固定面板。
- `crates/lexift-ui/src/annotation/screenshot_long_editor.rs`：按鼠标屏幕打开近全工作区窗口并整图适应。

保留当前有价值的基础：独占采集、固定物理范围、最新帧合并、单配准任务、歧义拒绝、分块像素、原分辨率输出及旧任务隔离。下一轮应先修正范围层、预览视口和完成编辑器，再决定是否扩展自动滚动、横向、头尾裁剪等功能。不能把这次体验重做变成无边界功能移植。

## 6. 覆盖与清理

- 本次实际覆盖当前主屏、单区域纵向滚动、预览从首帧增长到约 4.5k 高度、进入编辑、标题拖动、直接复制。没有覆盖 100%／125% 双屏完整矩阵、横向、会员自动裁剪、阻塞采集、极端长度、完整拼接像素参考或持续性能统计。
- 图像内容是本次合成行号夹具；剪贴板被本次合成长图替换。没有读取用户图片历史、保存用户正文或修改 PixPin 保存设置。
- 本次临时夹具关闭，采集／编辑窗口已结束；保留原 PixPin 进程与此前已有悬浮窗口。REA 分析记录已导出，附件会话关闭。
- 纯研究与文档变更不运行无关 Cargo／Slint／Release 构建；检查文档链接、证据文件和差异格式。实现阶段仍须重新做相关自动化与原生验收。

## 7. 后续实现

上述差距表保留为研究时的历史基线。当前重做已接入持续透明范围反馈、紧凑可移动控制条、固定宽度尾部预览、当前帧标记、直接输出及有边界的结果编辑器。实现与实际覆盖见[功能说明](../features/screenshot-mode.md#手动纵向长截图)及[重做验证](../releases/screenshot-long-redesign.md)；此更新不扩大前述 PixPin 静态分析或运行观察的证明范围。
