# 录屏完成后的预览与回放

基线 `main 8c9b652`，分支 `codex/recording-preview`。本轮不暂存、提交或合并。原始视频、像素夹具、时序和资源证据保存在忽略的 `target/recording-preview/`，文档不包含用户图片、声音或个人路径。

## 行为与所有权

封尾后自动准备预览，首帧保持暂停、自动播放关闭、音量为原音量；无音轨禁用静音。窗口使用采集屏幕，显示完整等比视频，支持拖动、缩放、定位、暂停及保存。播放结束停在末帧，再次播放先定位首帧；定位拖动暂停，确认后恢复拖动前状态。保存和未保存关闭确认均先等待原生暂停；取消后仍保持暂停。

保存直接原子发布所属封尾 MP4，不重编码。取消保存或失败保留成品；确认丢弃通过独立领域事件结束，不能伪造保存成功。预览结束恢复截图前状态；录制过程中的取消仍返回原截图。图片历史和 R 区域不变。

Core 在原录屏会话内管理预览状态，播放／定位请求与录屏控制编号分离。原生回调逐项校验会话、操作、成品、实例和请求。UI 持有视图、进度草稿和临时交互，不持有路径；App 调度现有 ScreenRecordingPort。Platform 独占播放器线程、只读文件引用、Media Engine、D3D11 已接受帧缓存及 DXGI 视频子窗口。缓存仅保留当前完整 GPU 帧，不保存整段帧序列、不向 UI 复制像素。

Media Engine 的 S_FALSE 必须作为“没有新帧”处理，不能被 windows-rs 的 Result 抹成时间戳零。定位期间仅接受目标附近的新帧，再替换显示缓存；调整大小重新绘制已接受帧，防止晚到旧定位覆盖新画面。播放提交按原生呈现节奏，进度最多 10Hz；暂停不持续读取视频像素。依据：[Media Engine](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nn-mfmediaengine-imfmediaengine)、[OnVideoStreamTick](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nf-mfmediaengine-imfmediaengine-onvideostreamtick)。这些是 Windows 实现契约，不是 PixPin 后端结论。

隐藏准备完成后被动显示，不激活外部前台。实际视频子窗口完成 Present／DWM 交接后才退役范围、工具条和标注画布。准备失败先退役失败的隐藏窗口，保留原完成控制条和成品，支持预览重试或直接保存。可见播放器失败保留保存和关闭。保存／丢弃先停止输入，等待播放器 Shutdown、视频子窗口和文件引用释放，才销毁父窗口及录制成品；UI 不等待原生释放。

## 本轮发现并修复

- 进度条的开始和提交可在同一 UI 事件轮次到达。开始暂停不推进解码请求号，提交定位才推进，因此同一已呈现快照可以提交；原生旧帧仍严格按编号拒绝。补充确定性回归；原失败保留在 `endpoint-r4/`。
- 暂停状态缓存已接受的 GPU 帧，避免在窗口重绘时直接从播放器取到尚未确认的定位画面。
- 视频子窗口自行处理重绘且不进行 GDI 背景擦除；父窗口仅增加所属 CLIPCHILDREN 位，销毁时恢复。
- 正常帧 Present(1) 后不额外再等待一次 DwmFlush，避免双重垂直同步导致 60fps 回放被减半。交接栅栏仍保留。
- 紧凑窗口将保存和关闭置于第二行；标题显式位于顶部，避免 Slint 默认居中导致标题被视频遮挡。确认界面测量后定位，避免缩放变化后偏离所属编辑器。

- 带音轨 MP4 的 AAC 尾部填充可能长于视频。滑块最右端必须夹紧到所属录制帧数／帧率确定的最后一帧，不能按容器时长定位不存在的视频画面。首轮失败保留在 `final-matrix/`，修复后使用新构建复测。

- 标题拖动直接调用已经异步投递的原生桥接，避免额外 UI 排队改变鼠标锚点；标题命中范围显式覆盖标题栏。此前跨屏脚本超时及实际窗口几何均保留。

- 确认期间阻止重试／目标替换，确认取消后恢复尚未完成的准备或显示交接；确认回调和计时器另校验自己的窗口版本。未显示的预览不接纳保存，完成控制条同步忙碌态。
- 静音不推进视频请求号；第二次拖动可以接管尚未完成的定位，并保留原播放恢复策略。补充确定性的交错事件回归。

## 原生矩阵与独立检查

- `delivery/preview-matrix-result.json`：两屏各十轮，覆盖 30／60fps、标准／高清、四种声音模式、倒计时、暂停继续、播放／暂停、定位、末端定位和结束后重播、静音、保存取消、取消丢弃与确认丢弃。自动显示后实际前台不是预览；无额外画布点击或强制激活。保存轮次原成品与目标 MP4 SHA256 一致；所属临时成品在保存／丢弃后移除。
- `independent-checks.json`：矩阵保存的十个 MP4 完整独立解码，1920×1080、帧率与音轨符合实际请求。60fps 高清双声源另见 `live-final-125/`、`live-final-100/`；60fps 标准系统声文件另见 `formats-final/decoded.json`，均完整解码并检查 H.264 High 和尺寸。目标码率与文件平均码率不混用。
- `delivery/early-close-driver.log`：两屏真实点击封尾后仍在准备中的关闭，取消确认后可以恢复预览、播放并保存，无强制激活。
- `delivery/extras.json`：真实标题拖动、原生窗口缩放、双向跨 DPI、子窗口物理范围、进度条键盘操作与确认居中通过；采用原生回传的最终几何，不在移动尚未结束时断言中间矩形。
- `live-final-checks.json`：下层应用实际收到点击／拖动／滚轮，控制条位置保持；暂停标注、马赛克、放大镜及文字提交后直接完成。独立解码末帧分别检测到 637／379 个文字红色像素；控制条中心采样为 `(32,52,77)`，符合有损编码后的已知底图，没有控件混入。
- `region-complete.log`：实际复制 480×240 图片，完成录屏、预览和保存后，下一次 R 复用的真实剪贴板尺寸及像素相同。测试等待两屏完整反馈后才发 R，保留之前 `ready=false` 的提前按键失败。
- `ten-minute-seek.log`、`ten-minute-frame-oracle.json`：已有受控十分钟成品的暂停首帧、中段与尾部定位通过；GPU 读回的中／尾编号与独立解码附近帧编号匹配。播放器 Shutdown 后私有检查副本可删除，不以进度条位置代替图像核对。

## 声音测量与未通过的原始阈值

`audio-final-125/`、`audio-final-100/` 使用独立已知脉冲／闪光 MP4，直接测 WASAPI loopback 与视频表面 Present／DWM；两屏十秒均呈现 598 帧，播放前环境峰值为零，没有自动出声。原始回环界限为 129.85／128.78ms，**原始 50ms 检查失败，未改写为通过**。

独立的直接 WASAPI 渲染时钟参考在测量前后得到 107.20～120.94ms 的回环时标偏移。以整个参考区间计算不确定性，扣除后的上界为 22.65／21.58ms，见 `audio-final-summary.json`。这是校准后的时标代理结果，不能证明真实扬声器、麦克风或屏幕光子的同步。因此本轮不把“真实声学偏差≤50ms”标为验收通过，也未独立测量十分钟回放全程的声学漂移。十分钟录像既有录制端同步结果仍属于先前专项，不能替代本轮播放端测量。

早期硬截断 440Hz 夹具产生额外低阈值触发，改用独立合成、2ms 缓升降的 880／1760Hz 已知脉冲后，两声道各五次触发明确；保留所有早期原始失败，不修改产品音视频波形。测试代码没有向播放器增加固定音频或视频偏移。

## 资源、失败证据与覆盖边界

二十轮预览及另二十轮默认档均检查成品释放。`delivery/retired-windows.json` 包含隐藏窗口枚举，没有预览父窗口或视频子窗口；`acceptance-r10/retired-threads.json` 检查了 37 个进程线程，没有所属录屏／播放／音频工作线程；所属进程临时录制目录为空。最终通过真实托盘退出，所有受控源收到停止信号后退出，测试移动过的外部窗口按实例及当前几何匹配还原。

原生阶段的缓存和进程总内存分开报告：空闲采样 PrivateBytes 约 175MiB，工作集约 9MiB；逐轮总句柄曾增长并在空闲后回落至约 1590，不能宣称所有系统句柄回到冷启动基线。主线已有同类总句柄增长记录，本轮未逐个归因，不用工作集修剪证明引用释放，也不将未归因项武断归给分配器或 GPU。

保留首轮产品失败：同轮定位提交丢失、AAC 尾部不存在视频帧、标题布局／拖动排队、跨 DPI 原生尺寸同步。修复后均使用最终构建重测。保留脚本失败：源夹具覆盖预览、保存取消未等 Core 收尾、确认激活前提前断言、移动中间矩形断言、R 早于两屏反馈、复用证据文件名触发覆盖确认；后者采用新文件名及真实原生按钮收尾。一次麦克风启动发生原有音频层时钟不连续并正确拒绝开始，后续完整四模式矩阵通过，不静默降级。

准备／播放失败、旧请求与迟到结果、保存取消和丢弃由状态回归覆盖；本轮没有破坏真实 GPU、音频服务或系统编解码器来制造播放故障，也没有 HDR、物理热拔插及真实麦克风声学测量。组件截图因捕获排除与原生桌面截取口径不同，布局证据和 GPU 帧证据分别保存；追加的 `rendered-surface-checks.json` 在测试构建中读取实际交换链渲染缓冲，黑边、底图颜色及闪光位置断言均通过，避免只检查解码纹理，不能把可见窗口或黑色占位当作实际视频解码成功。
