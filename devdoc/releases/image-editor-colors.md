# 独立图片编辑器颜色调整验证

实施始于 2026-10-26，最终证据核对于 2026-10-27 完成。分支 `codex/image-editor-colors`，起点为当前 `main` 的 `cc34674`，包含计划之后已有的发布变更；未回退至旧基线。实施阶段未自动暂存、提交、合并或推送；验证完成后按用户于 2026-10-27 的明确授权提交并快进合入 main，不自动推送。证据存入忽略的 `target/image-editor-colors/`。

## 实现

- 三类独立图片编辑来源共用画布右键菜单：灰度、反色、九档亮度、九档对比度及恢复原始颜色。复用原生菜单，无新增工具条按钮或布局行。
- `Action::Reset` 一次清除四项颜色；复用共享历史，不修改几何、对象及显隐。默认颜色无变化不清除重做。
- 颜色应用和颜色历史复用已有图片候选、版本校验和原子安装；颜色变化保留工具与有效选择，方向／裁剪继续使用原有几何提交行为。菜单前提交文字／参数，原生输入控件保留自己的菜单。
- 新增恢复颜色文案同步十二种语言。像素算法和输出／OCR 资源传递沿用现有实现，不新增 Port、依赖、crate 或配置。

## 定位并修复的实际问题

完整原生操作发现：Shift＋F10 后，Ctrl＋Z 被解释为重做。`probe-shift-diagnostic.log` 与 `sticky-shift-diagnostic.log` 保留失败证据；后者明确记录 action=2，排除了仅凭输出猜测的做法。

原因是按下 Shift＋F10 时同步进入 Windows 原生菜单消息循环，Shift 松开未进入 Slint 的修饰键状态。当前编辑器改为在菜单键和全部修饰键释放后再打开菜单，支持两种松键顺序，不增加轮询或固定等待。失焦、指针操作及 Escape 会清理待打开状态。修复限定于独立编辑器菜单，不扩展通用窗口焦点策略。

早期脚本还有两项证据错误，已单独修正并保留原日志：把桌面截图保存到与复制成品相同的文件名，覆盖了像素证据；长图复制成功后按既有规则关闭编辑器，脚本却继续抓取已销毁的窗口。最终证据目录单独保存成品和桌面图，长图在全部编辑完成后才执行结束型输出。
