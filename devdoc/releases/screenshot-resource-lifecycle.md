# 截图窗口资源生命周期调查

基线源码为 `main 6f4883f`，工作分支为 `codex/screenshot-resource-lifecycle`。本记录区分 Lexift 的能力探测、第三方叠加层持有的对象，以及正式窗口退役。

## 原始问题与证据

录屏快捷键专项保留了二十轮后总句柄从 620 增至 743 的记录，涉及 ALPC、Mutant、Section。原始记录仍保存在 `target/recording-hotkeys/final/final-resource/samples.json`，本轮不覆盖。

本轮证据位于忽略的 `target/screenshot-resource-lifecycle/`。`artifacts.json` 保存已有应用和隔离测试二进制的哈希；正式基线和修复版均使用本轮重建的 Release。

## 初步原生隔离

以下各项在独立进程运行既有 Release 测试二进制，各 64 轮。它们用于缩小调查范围，不代替最终源码构建、五组完整界面矩阵或双屏性能验收。

| 隔离项 | 首轮／末轮总句柄 | 分类观测 |
| --- | --- | --- |
| 无 GPU 的空线程 | 186／186 | ALPC、Mutant、Section 稳定 |
| 裸 D3D11 设备，不使用 WinRT | 282／282 | ALPC、Mutant、Section 稳定 |
| 捕获后端，不创建帧池或会话 | 295／295 | ALPC、Mutant、Section 稳定 |
| 创建并关闭 WGC 帧池，不开始采集 | 298／424 | Mutant 7→70，Section 5→68；ALPC 稳定 |
| 实际 WGC 采集，不执行标注渲染 | 328／518 | ALPC 10→72，Mutant 7→70，Section 7→70 |

上述现象不能单凭句柄类型归给 Windows 缓存、显卡驱动或 Lexift 引用遗漏。仅能确认，在这个夹具中无须执行正式 UI 就能复现部分相同类型增长。后续以能力探测和叠加层开关两组隔离对照进一步归因。

## 本轮诊断改动

既有显式原生隔离测试新增可选环境变量 `LEXIFT_RESOURCE_BATCH_IDLE_MS`。启用后先预热一次，再运行三批、每批二十轮，在每批后保持 COM 消息处理并观察指定空闲时间。验收使用 `120000` 毫秒；第三批用于检查第二批之后的增长是否继续。

该开关仅存在于测试代码，不新增用户配置，不修改生产资源销毁策略，也不执行工作集修剪。默认未启用时保留既有 64 轮测试行为。

当前源码的 Release 测试构建已经完成，三批观察的进程内计数如下。每批均为二十轮，后接两分钟空闲；不将其解读为资源退役通过。

| 夹具 | 预热后 | 第一批空闲后 | 第二批空闲后 | 第三批空闲后 |
| --- | --- | --- | --- | --- |
| 帧池，无采集会话 | 304 | 343 | 379 | 419 |
| 实际采集，无标注渲染 | 328 | 377 | 424 | 464 |

帧池的 GDI／USER 恒为 4／2，实际采集恒为 9／6。完整日志在 `batched/`。两组仍持续增长，该轮没有“预热后缓存稳定”的证据。

外部分类器曾在夹具最后退出时读到零句柄，或在批次切换时读到下一批瞬时资源，因此上述表格使用进程内同步计数，不把那些外部快照视为准确的空闲阶段分类。失败数据继续保留。后续夹具增加 `LEXIFT_RESOURCE_OBSERVER_DIR` 测试握手：外部采样完成后写入所属阶段的确认文件，夹具才继续或退出，十秒没有确认则明确失败。`observer-self-test/` 使用零空闲时间验证三次握手及最后一次快照均有效，该自检不代替两分钟空闲实验；`observer-timeout.log` 则验证缺少采样器会非零退出。

## 归因与修复

- **Lexift 可避免的 ALPC 增长。** 不启动 UI、不创建帧池，只反复执行 WGC 能力探测，64 轮同线程与临时线程均为 6→69 个 ALPC 句柄；只构造捕获 Port 为 7→70。NVIDIA 叠加层关闭时，旧探测仍从 6→68。证据将问题定位到反复执行的探测路径，未进一步区分 Windows 内部的工厂激活与 `IsSupported` 调用。
- Platform 仅在首次探测成功后记住布尔值，失败或不支持仍可重试。不缓存 COM 对象，不跳过实际设备、帧池及会话的创建检查。修复版三组同样运行 64 轮，ALPC 分别为 6→6、6→6、7→7（`activation-isolation.log`、`capability-fixed-isolation.log`）。
- **另一路 Mutant／Section 增长来自 NVIDIA 叠加层。** 仅使用 Windows SDK 创建并关闭 WGC 帧池的最小夹具也会增长；重复对象名称的 GUID 在已加载模块中只匹配 `nvspcap64.dll`。关闭 NVIDIA App 的叠加层开关后，64 轮总句柄 313→313；恢复用户原来的开启状态后，307→430，Mutant 6→67、Section 4→65。重用工厂、显式关闭 WinRT 设备或每轮换用并回收新线程都未消除增长。证据在 `pool-guid-modules.json`、`overlay-toggle-restored.json` 和 SDK 对照日志。该增长没有在两分钟空闲后稳定，不能称为已验证稳定的缓存；Lexift 没有卸载外部 DLL 或强制关闭外部句柄。

| 场景 | 基线 | 修复版 |

基线主矩阵在 125% 屏执行；修复版操作组在 125%／100% 屏分别测量。录制取消另有双屏同口径的叠加层关闭对照。原始录制组、框选组及两个显示器的样本保留于 `target/screenshot-resource-lifecycle/`。修复版录制组的两次空闲总数为 703、766；Mutant 55→95、Section 50→90，与叠加层开启的独立复现一致。截图宿主和编辑窗口退役后没有逐轮累积；测试分开记录 USER、GDI、线程、PrivateBytes 和工作集，不以工作集变化证明引用释放。

副屏第一次逐像素校验失败（`final-r2-copy/2-1-*.png`），参考图和同坐标后置参考图均为全黑，实际剪贴板图包含夹具内容。诊断发现参考抓图未启用虚拟桌面范围。修订脚本记录参考、实际和后置参考，采用虚拟桌面范围、跨 DPI 绘制确认及精确 RGB 对比。`reference-monitor-check/check.json` 独立核实同一副屏坐标下旧参考为空、新参考覆盖完整 960×540。另一次主屏预热未保存差异图，原因不能追溯；不覆盖旧失败。首次修复版性能运行在发送截图热键前出现夹具绘制确认超时；Windows 确认文件替换受读端占用时，夹具在成功写入前已标记完成。修正为写入成功后再标记，原失败保留在 `final-perf/`，不计入产品时延。脚本的托盘自隐藏就绪失败也单独保存，未因此更改产品焦点或托盘策略。最终 `final-r3-copy/` 预热及两屏各 20 轮均为 960×540，所有剪贴板像素与对应参考图逐字节一致。

两版独立进程，按同一顺序在 125% 和 100% 屏执行，每屏预热一次、计入二十轮。无并行编译或性能测试。从实际 S 键按下开始，到两屏均记录完整框选反馈呈现；编辑从鼠标松手开始，到编辑焦点确认、画面安装、工具条出现及测试端 DWM 同步完成。后者含外部观察与同步开销。此处为驻留进程时延，不是进程冷启动。

## 原生操作与边界

- 125% 屏和 100% 屏均使用真实输入通过 R 复用新鲜底图、C 取色、复制及 PNG 保存。输出为 960×540，剪贴板和 PNG RGB 分别与独立参考逐字节一致。另验证贴图在截图取消后恢复原 HWND、录制进入实际首帧预览并确认丢弃。主屏证据在 `final-r3-regression/`，副屏证据在 `final-r7-regression/`。
- 保存脚本早期没有等待原生子控件准备，保留两次超时和取消结果。修订后检查所属对话框、可见文件名字段及保存按钮，再执行实际保存。副屏预览的初始按钮坐标被合成前台窗口遮挡；同一基线和修复版都可复现。缩小合成前台窗口露出标题栏后按实际关闭，期间未强制激活。该行为未因本次资源修复改变。
- 外部焦点对照中，实际鼠标从原始窗口切换至第二个合成前台窗口，基线与修复版均没有自动抢回焦点；两屏仍呈现框选反馈。`baseline-focus/` 和 `final-r6-focus/` 保存实际 HWND 和 `permitted=false`。两版都可由 Escape 取消截图，同时保留外部前台，属于既有行为。
- 退役样本仅保留单实例、托盘、Winit 事件目标及输入法窗口。原生录制取消日志还确认快捷键监听注销和所属录制请求退役。原生观察不把进程总句柄拆算为应用内部所有引用的计数；Windows 和外部模块的内部资源不由 Lexift 回收。

Lexift 的能力探测修复、截图窗口退役、像素与性能回归通过。本机 NVIDIA 叠加层开启时，录屏路径仍有已隔离归因的第三方句柄增长，不能认定原始总句柄问题在所有配置下消失。原叠加层设置已恢复；本轮没有改动显卡驱动、外部模块或用户配置。
