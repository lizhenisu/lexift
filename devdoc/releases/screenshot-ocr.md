# 截图 OCR 识别并复制验证

日期：2026-10-18。起点：`bd6f79e`。本轮不暂存、提交或推送，截图、夹具及日志位于忽略的 `target/`。

## 行为与实现

- 识别截图冻结底图的已确认选区，包含截图前桌面标注，排除截图新增标注。按钮在截图工具条各工具模式可用；贴图、普通标注和初始框选无此入口。
- 提交键盘调整、取消尺寸草稿、收尾文字／参数及手势后冻结选区与 OCR 策略；后台裁切并识别，经既有 ClipboardPort 复制非空文本。
- Core 截图阶段管理独立识别请求和不含正文的结果，复用 OcrPort，无自动翻译。成功、空结果、资源不可用、识别或复制失败均退出并恢复原标注，显示对应三秒 toast。
- 推理和空闲释放由原 OCR 运行时共用；资源变更在截图识别期间受保护。取消、关闭及替换使旧任务与结果失效。
- toast 采用既有辅助窗口和被动提示输入策略，底部居中、不抢焦点、不拦截输入；退出画布后仍可显示，到期销毁，新截图清理。

## 实机发现与修正

首次原生测试确认 OCR 文本复制和截图恢复成功，但未找到预期尺寸的 toast。进一步按新 HWND 追踪发现窗口实际宽度仅为 10px（125% 下为 13px），显示成底部细线，不能将此前“窗口可见”或指定尺寸的组件渲染当作实际呈现成功。

修正为采用既有 toast 宽度 Token，暴露内容宽高并设置原生窗口约束；隐藏阶段按目标 DPI 显式设置尺寸、测量文字并收敛高度，之后再定位和显示。显示流程回归增加宽度断言，实机脚本同时检查真实窗口宽高、工作区包含、已绘制像素、焦点、输入禁用和到期销毁。

第二轮按实际像素确认宽度正常后，又发现首次两次提示使用尚未更新的 WM_SIZE 高度定位，导致底部距离偏大。定位改用同一份已收敛的逻辑内容宽高及目标 DPI，不依赖延迟的原生尺寸读回；实机断言进一步要求底部逻辑间距为既有 16px Token，而非只检查位于工作区内。

跨 DPI 的隐藏布局还需一次事件循环才能接收原生尺寸事件，因此增加按窗口实例编号绑定的隐藏准备收敛：两次准备所得内容尺寸一致后才定位并显示；变化时继续现有 16ms 有界准备，关闭或换会话由所属 Slot 取消回调。该流程不使用显示后移动、持续置顶或长期轮询。
