# 截图首次准备优化验证

本记录保留上一轮双屏及冻结元素策略的历史证据。当前按点查询与多屏组同步已替代其中的前后元素采集，见[新验证记录](screenshot-point-query-performance.md)；以下数字不能直接用于当前三屏对比。

日期：2026-10-18—19。基于未提交的内部元素识别工作树继续修改；不暂存、提交或推送。证据、程序副本、合成夹具及日志均位于忽略的 `target/screenshot-startup/`。

## 实现

- 截图挂起增加 UI 完成确认，所属会话退休后不得启动采集；像素及整窗范围、后置元素结果分别投递。Core 只在当前 Selecting 阶段接纳一次元素结果，UI 校验宿主，按下冻结的目标不变，不重放滚轮。
- 首轮元素采集上限 80ms，优先触发点所在窗口，再按前后顺序处理。第一个优先窗口可使用剩余预算的一半，其余窗口分享剩余时间，避免复杂提供者独占或首个冷提供者被平均预算饿死；保留 8 窗口、2048 节点及 16 层限制。后置校验上限 250ms，在首帧派发后执行。
- 保留唯一 MTA 工作线程、最新待处理请求和取消；COM 客户端可提前初始化，树只在截图准备期间查询。几何和离屏属性使用 UIA BuildCache，身份、父关系及范围须前后一致，失败退回整窗，不替换底图。
- Windows 一次性抓图复用既有桌面实现。排除 HWND 必须不可见，原 GPU 表面必须退场；DwmFlush、抓图及拓扑校验在后台执行，不适用或失败回退 WGC。原标注仍从冻结文档合成一次。空文档直接裁切源像素，避免透明整屏栅格化和混合。
- 初始宿主直接测量、绘制 Slint 反馈，不先创建编辑纹理窗口；构造后立即尝试隐藏准备，未就绪才有界重试。两屏实际客户区反馈帧完成后，按 DPI 分批准备编辑资源，避免首屏预热阻塞另一屏。软件渲染通过宿主的客户区完成通知，GPU 渲染通过 AfterRendering 返回后的通知；均去重并校验实例，后续鼠标重绘不再排队预热。标签、提示、取色反馈继续同帧。
- 松手后退休初始宿主输入，保留其静态完整画面，直至全部编辑画布首帧完成再销毁；取消和失败仍立即清理所属窗口。临时纹理组件随准备结束销毁，不保留隐藏窗口。

## 正式性能比较

本机两屏：125% 的 `2560×1440` 与 100% 的 `1920×1080`，物理坐标分别从 `(0,0)`、`(2560,0)` 开始。采用同一个覆盖两屏的已知像素夹具，无编译负载，顺序运行各组。

- 每个程序各 20 次进程首次截图、20 次驻留重复截图。进程启动、标注工具条打开、夹具准备及取消稳定等待不计入准备时间。Lexift 计时起点为现有截图按钮的真实鼠标事件，PixPin 为 Ctrl+1 注入；不把脚本固定等待算作耗时。
- 三者均以真实桌面像素和前台探针停止计时，不等日志写入。两个屏幕的已知底图探针须已呈现；鼠标附近／左下角至少 3 个反馈探针须区别于源像素及其任意黑色遮罩衰减，避免把纯底图或蒙层误认为 Slint 反馈。两个源图探针排除黑色、白色或普通灰色未呈现表面。
- 原生底图交接只属于中间阶段，早于实际客户区反馈绘制。此前按交接标记得出的 207/198ms 等数据均不作为最终首帧结论；同样，简单“像素不同”会把蒙层算作反馈，不能用于最终统计。旧试跑文件保留在忽略目录，仅以下 `actual-*` 文件构成正式数据。
- 这是桌面自动化观察与原生呈现交接计时，不是光电或高速相机测量；三者使用同一探针条件；这是该夹具下的比较，不推导所有程序或硬件的速度排名。包含实际显示／输入检查，不能以 HWND 可见或黑色未呈现表面判成功。
- P95 使用 nearest-rank（排序后的第 19/20 项），中位数取中间两项平均。正式原始行分别为 `final-current-benchmark.jsonl`、`actual-baseline-benchmark.jsonl`、`actual-pixpin-benchmark.jsonl`，每文件 40 行；汇总见 `performance-summary.json`。

| 程序 | 首次中位数 | 首次 P95 | 重复中位数 | 重复 P95 |
|---|---:|---:|---:|---:|
| 修改前 Release | 1066.04ms | 1082.04ms | 1019.88ms | 1036.52ms |
| 最终 Release | 316.46ms | 396.82ms | 309.59ms | 327.94ms |
| PixPin 3.5.5.1 | 185.47ms | 236.28ms | 195.90ms | 275.32ms |

首次 P95 ≤500ms 已达到；**重复 P95 ≤300ms 尚未达到，超出 27.94ms**，不能写成全部性能目标通过。首次和重复 P95 相比保留副本分别下降约 63.3%、68.4%。本机选择 Slint 软件渲染，不能用 GPU 回调替代实际桌面结果。

### 阶段耗时

最终版 40 次对应日志见 `final-stages.log`。阶段存在包含、重叠关系，不能相加为端到端耗时。

| 阶段 | 中位数 | P95 |
|---|---:|---:|
| 整窗枚举及首轮元素前缀 | 85ms | 86ms |
| 准备开始至冻结像素就绪（含前项） | 140ms | 145ms |
| 准备开始至首帧派发（含合成） | 145ms | 150ms |
| 两屏 Slint 宿主构造 | 3ms | 3ms |
| 原生隐藏准备及显示尝试 | 52ms | 57ms |
| 后置元素校验，离开首帧关键路径 | 251ms | 251ms |

40/40 次使用快路径。冻结前节点数中位数为 58，校验后为 58；本轮实际遍历多个桌面窗口，首轮通常耗尽 80ms 预算。慢、阻塞提供者的合并和取消由自动化覆盖，不能把这组统计理解为所有程序的采集耗时。

额外测过兼容位图、逐屏 DIB、整体 DIB 读回原型各 20 次，API 路径中位数分别约 46.81/42.03/45.11ms。收益约 5ms，未引入额外映射缓冲实现；原型仅在 `target/`，未修改 OCR 抓图或渲染器选择策略。

### 松手进入编辑

同一控件夹具，双方各 5 次自由拖动后松手，计时到两屏编辑画布及工具条就绪、初始宿主已退场；不计 helper 的固定稳定等待。上一构建的数据见两个目录的 `edit-handoff.jsonl` 中最后一组 `manual-baseline-*`／`manual-current-*`。

旧版中位数 283.62ms（最大 324.84ms），新版上一轮交接检查中位数 307.00ms（最大 329.57ms），增加约 23ms。该组在客户区反馈完成接线前取得；最终版另测首次画面可操作后立即单击的 3 次交接，结果见下方补充。

初始宿主现在保留至全部编辑首帧，不能用“旧窗已消失”单独比较交接完成。该组小样本只用于检查是否把数百毫秒准备开销整体移到交接，不作为交接 P95 承诺。最终版的额外通知不会用于首帧计时终点，仍以实际桌面反馈为准。

## 回归与实机结果

- Core 全套 172 项通过；新增可选元素去重、编辑阶段及退休会话拒绝迟到结果。
- UI 全套 449 项通过、11 项忽略；包含初始反馈不依赖编辑纹理、交接保留画面、两屏交接去重／过期身份、按下后元素迟到不改目标、空文档像素及取消；补充聚焦截图宿主的 Escape 取消，原生／组件重复通知只处理一次，OCR 的聚焦按键路由保持原状。最终原生夹具另断言 Escape 后两个框选宿主均已销毁。Slint 编译通过；组件渲染覆盖 12 语言、浅深主题、100%／125%。
- App 截图 7 项、采集／导出 7 项通过，覆盖挂起身份、像素先返回、后置校验、快路径错误回退及输出隔离。
- Platform 采集相关 20 项通过、10 项忽略；宿主原生消息回归另 3 项通过；包括唯一工作线程、阻塞／取消／最新待处理、枚举过滤和快路径排除条件。原生单测验证排除窗口仍可见时，快路径在读取任何像素前拒绝。
- 最终 Release 一轮 9 个原生控件／自由框选用例均取得预期范围，复制图像尺寸及像素正确：125% 按钮／父区／整窗，100% 输入框／按钮／列表／父区，跨屏父区，自由拖动。滚轮、轻微抖动、按下冻结、C 取色、焦点及辅助窗口样式一并检查。证据为 `coverage.jsonl` 最后 9 行、对应 `*-hover.png`／`*-output.png` 及 `colors.jsonl`。
- 识别并非保证全覆盖：前一构建冷启动曾出现按钮退回整窗、输入框／列表退回有效父区；同一元素算法后续重跑也能完整识别。80ms 前缀未覆盖的节点不会凭空补入。不能用最后 9/9 宣称所有冷启动均完整识别，也没有得出同口径旧版识别覆盖率百分比。
- 浏览器原生回归本轮未完成：夹具在截图前已经显示黑色，源像素为 `#000000`（`browser-source-proof.jsonl`、`browser-source-before.png`），因此不能用其预期 `#F0D080` 的断言评价采集正确性。此前构建的浏览器按钮／父区成功记录保留，不冒充最终版通过。
- 最终 Release 两屏首次框选 C 色值及各 135 个网格格子通过；顶部检查 141,360 + 102,960 = 244,320 个像素，无白条、标题文字或偏移。见 `whitebar.log`、`whitebar-final.jsonl` 和 `whitebar-final-*.png`。
- 半透明外部窗口：两屏实际桌面与冻结取色均为 `#317E4B`。截图前绘制的半透明标注取色为 `#1C6B5B`，与实际显示一致，没有重复合成；原 GPU 表面清理后快路径成功。冻结后改变底下窗口颜色，两屏及标注处取色仍保持原值，退出后能看到已变化的桌面。见 `layer-results.jsonl` 最后 6 行、`layer-frozen-*.png`、`layer-*.txt` 和 `layer-test.log`。
- 编译门禁：相关 Core／App／UI／Platform 回归、Slint、`cargo fmt --all -- --check`、四个相关 crate 的 `cargo clippy --all-targets -- -D warnings`、Windows Release 构建及 `git diff --check` 通过。

聚焦 Escape 修复后，以普通顶层窗口夹具在首次反馈可见时立即单击，3 次进入编辑分别为 311.50/306.11/314.15ms，两屏像素正确；过程中没有等待元素任务或额外稳定 sleep。见 `immediate-edit.jsonl` 最后 3 行及 `immediate-edit-*.png`。

## 未覆盖范围

- 本轮启动按钮位于主屏，已验证框选阶段跨到副屏取色，未单独统计从副屏触发的 20 次首帧耗时。本机显示器没有负坐标排列；负坐标、裁切和跨屏几何由 Core／UI 自动化覆盖，不作为原生负坐标实测。
- 未对所有第三方 UIA 提供者、权限提升窗口、系统负载、HDR、独占全屏／受保护内容作速度或像素保证；复杂程序可能只得到整窗候选。未做原生 WGC 失败注入或最终版贴图场景的独立逐像素对比。
- 实机主题采用当前系统主题；12 语言、两主题和 DPI 组合来自组件渲染，不冒充全部原生实测。没有修改系统缩放、屏幕排列或用户配置。
- 初始失败探针及构建中试跑仍放在忽略目录，正式统计只使用上述三个 40 行文件。测试自己创建的 Lexift、控件／浏览器及像素夹具均关闭；原先运行的 PixPin 在比较后重新启动。
