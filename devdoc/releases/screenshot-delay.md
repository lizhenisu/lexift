# 延迟截图专项验证

日期：2026-10-23。分支 `codex/screenshot-delay`，实际从已有 rc.12 发布准备 `433f01c` 创建（其父为计划中的 `389b06b`），保留该发布准备；未暂存、提交、合并或推送。

## 检查范围

- Core：合法时长、忙碌拒绝（含历史直接输出）、重复请求、过期截止、取消与历史/R记录隔离。
- UI：单调截止投影、十二语言×浅深主题×100%/125%渲染、菜单键盘选择、工具条宽度。
- Platform：点击输入保持启用、禁止激活与后端样式重写保护、捕获排除。
- App：沿用取消任务与截图准备/输出回归。

## 原生预检

早期 Release 已通过菜单→3秒提示→首次框选。发现初始原生尺寸尚未生效导致提示位置偏移，改为先测量并使用明确物理尺寸定位；按钮高度显式30逻辑像素，组件以48逻辑像素布局（原生可见边界读取约46–48逻辑像素）。

提示设置捕获排除，因此 GDI 桌面截图显示的是其下方内容，不能把该截图误记为提示渲染失败或提示真实外观证据。外观使用组件渲染核对，原生测试须另检查窗口几何、输入及焦点。

### 最终二进制原生验证

2560×1440（125%）及1920×1080（100%）两屏，各验证3／5／10秒。通过实际点击将工具条移到目标屏幕，检查提示位于该屏幕工作区底部居中、紧凑高度、辅助窗口和禁止激活样式、原生捕获排除标志。

倒计时内点击独立像素夹具并打开其右键菜单，把红色底图改为绿色。进入框选后无需额外点击或强制激活，C 均复制 `#1EB446`；在此前提示中心位置取色同样为绿色，验证冻结底图不含倒计时。框选并复制的100×80图片也为正确绿色像素。

两屏均点击取消，原应用的实际前台 HWND 保持不变；等待十秒后未出现迟到框选，工具条恢复。补测立即截图菜单、原截图按钮及 R 复用，采用上次100×80区域，通过同一最终二进制验证。

实际观测的等待时间（菜单操作结束至出现框选宿主）为：125% 3125／5130／10166ms，100% 3151／5122／10163ms。六次截止任务迟到0.98–15.06ms，中位数9.69ms；随后底图准备到首帧交付100–122ms。观测等待包含输入脚本间隔及轮询，首帧交付也不等同两屏全部呈现；不能据此宣称整个准备耗时只等于计时器误差。

证据位于忽略的 `target/screenshot-delay/`：`native-final.log`、`native-final-results.json`、`native-final-binary.json`、`countdown-native-windows.jsonl`、`timing-final.log`、`timing-summary.json`、实际菜单截图及输出PNG。`extended/` 与 `native-extended.log` 保存立即入口/R补测，`render-final/` 保存组件渲染。

### 修复的交接竞态

到期后 UI 先进入 Preparing，50ms提示刷新回调可能早于统一采集入口运行。此前回调会清理激活上下文，导致框选前 C 无焦点。现将 Preparing 视为交接阶段，只停止刷新，保留上下文直到采集入口显式销毁提示并重新取得前台；新增回归验证该顺序。不得把先前只出现框选窗口的预检视为键盘交接通过。

### 未原生覆盖

物理负坐标屏幕、显示器移除、全部语言/主题的原生重复操作、准备失败注入、已有标注/贴图的逐像素恢复，以及保存/贴图输出未在本轮逐项原生复测；相关既有回归通过不代替这些实机结果。没有新增全局 Escape 或键盘钩子，也没有借助强制激活补救测试。截图、夹具和日志不进入版本控制。
