# 贴图锁定与鼠标穿透验证

日期：2026-10-25。基线：main 8016b4b；实施分支：codex/pin-lock-passthrough。验收时工作树尚未提交；后续 Git 交付按用户明确授权执行。

## 实现范围

右键菜单提供独立的锁定和穿透勾选，托盘提供取消全部穿透。状态只属于当前贴图实例；成功安装原生策略后才确认，恢复逐张处理失败。临时截图／编辑输入屏蔽与用户策略取交集。裁剪及改变显示尺寸的历史操作在锁定下停止，普通标注历史保留。文档、图片来源、历史记录和 R 不携带这两个窗口选项。

Windows 穿透复用同一 HWND 的原生 RGBA 分层呈现和现有输入桥接。恢复交回 Slint；尺寸、DPI 和主题事件合并刷新，无常驻刷新计时器。保留辅助窗口身份及贴图作为桌面内容的捕获身份。

## 发现的问题与修复

- 初始 HTTRANSPARENT／WS_EX_TRANSPARENT 和单独 EnableWindow(false) 实验不足以证明跨进程穿透。清空下层夹具日志后发现右键和滚轮没有到达，废弃该实验结论。最终使用分层呈现后，以另一个进程实际接收的左键、右键、拖动、滚轮和 Escape 事件验收。
- 编辑结束后的右键入口曾依赖 Slint 的残留鼠标捕获状态。最终原生右键直接打开同一个 ContextMenuArea，仍经过所属实例和交互版本校验，不合成重复点击。
- 像素对照发现编辑中的原生菜单输出没有先发布当前文档。菜单现在与工具条共用事务收尾和文档冻结，补充 UI 回归验证输出命令包含当前对象。
- 补测编辑中的锁定切换发现，鼠标模式会在策略处理中暂时失去原生输入；确认时即使策略值已在本地安装，也必须重新应用结束待处理状态后的输入能力。增加浏览编辑状态的切换回归，最终两屏实际验证锁定／解锁、穿透禁用及解锁后裁剪。
- 一轮恢复脚本把新贴图放在工具条上方，另一次在框选窗口刚显示、尚未报告完整首帧时立即断言隐藏，均修正为不遮挡的夹具位置和实际就绪条件。
- 恢复验收时 D 盘出现一次“设备未就绪”，该轮日志损坏，不算通过。重新写读检查、核对 Release 哈希并完整重跑。

## 最终 Release 实机

本机主屏 125%（120 DPI），第二屏 100%（96 DPI）。通过真实鼠标和键盘、真实通知区域图标打开托盘；未通过直接触发 Core 回调或强制激活贴图替代恢复。

- 编辑内切换：两屏均可开启／取消锁定，原生菜单勾选正确；编辑期间穿透项禁用，锁定时裁剪不可进入，解锁后可进入裁剪并取消，编辑会话保留。
- 普通贴图：两屏分别核对实际 DPI，锁定后拖动与滚轮不改变窗口矩形；标注和撤销／重做可用，裁剪按钮禁用，OCR 复制已知文字成功，PNG 保存成功。
- 穿透：下层独立进程日志实际收到左键、右键、拖动、滚轮和 Escape，贴图保留；多实例由真实托盘恢复，锁定保留，前台没有被切换到贴图。
- 截图：框选完整反馈后实时贴图隐藏；取消截图后仍保留穿透，再经托盘恢复。解锁后可重新移动，关闭实例成功。
- 提示与倒计时：两屏实测穿透提示的鼠标命中到达外部应用，不取得前台，约三秒后 HWND 销毁；10 秒倒计时取消后穿透仍保留，可经托盘恢复。
- 普通贴图像素：源图与锁定前后复制一致；撤销等于底图，重做、保存、恢复后复制等于同一版本标注结果。两种 DPI 的 12 项 RGBA 对照均通过，标注确实改变像素。
- 真实长截图：两屏分别从已知行号应用实际滚动，生成 600×1200px 贴图。锁定后拖动、滚轮被阻止，穿透与托盘恢复成功；恢复前后复制逐像素一致，并等于 600×3000 原夹具的前 1200 行，不含交互装饰。

主证据：target/pin-lock-native-verified.log、target/pin-lock-long-verified.log、target/pin-lock-extra-verified.log、target/pin-lock-edit-toggle-verified.log；实际菜单、托盘、锁定画面、PNG、剪贴板成品及窗口身份在 target/pin-lock-passthrough/native/、native-long/ 、native-extra/ 与 native-edit-toggle/。较早 debug 和失败脚本日志保留为诊断证据，不替代上述最终 Release 结果。

## 验证边界
