# Windows 长截图双向拼接验证

基线为 `5be1a1b`，实施分支为 `codex/long-capture-bidirectional`。手动采集可沿选定轴向两端扩展。采集 worker 仍只向下或向右发出自动滚轮，运行与未结算的滚轮都限制拼接为末端扩展。

## 实现与失败对照

- Core 保存首末确认帧，将新正文条带和行列索引插入对应边界。固定区域宽度在首次成功扩展时锁定。预览和成品共用条带顺序，两端裁剪重设对应锚点，固定区域各保留一次。资源预算计入双锚帧，首帧和裁剪后的同一帧只按一份保留资源计算。
- 早期 Release 在 Chrome 纵向平滑滚动中遇到不可配准的中间帧，立即清除了边界定位，导致正常滚动也无法扩展。首帧导出和静止端点的独立 Core 样本均逐像素通过，关闭平滑滚动的对照也通过。失败与对照分别保存在 `diagnostic-vertical/`、`diagnostic-first/` 和 `discrete-vertical/`。
- 采集 worker 依据像素版本处理上述过渡。后续样本可继续尝试与已确认边界配准。像素不再变化 180ms 后仍无法确认，或连续 1.5 秒无法确认时，隐藏绿框并要求重新找回边界。期间不执行裁剪或下一档自动滚轮，也不缓存额外像素。输出始终使用已确认的条带。
- 限高预览初次实测发现原生栅格缺少底部省略箭头，控制条也可能遮挡高预览。修复后原生和 Slint 反馈均显示相应省略端的箭头，纵向预览在空间允许时放到避开选区和控制条的位置。

## 自动化与构建

Core 28 项、App 6 项、UI 12 项及 Platform 2 项专项测试通过。覆盖双端扩展、固定区域、已知边界恢复、无效跳跃、历史定位、裁剪续接、过渡帧与稳定未知帧、滚轮方向、像素版本和限高预览的箭头及位置。双向提示同步十二语言。格式、严格 Clippy、Slint 编译及 Windows Release 构建通过。Slint 保留截图尺寸输入框的既有可访问文本警告。

扩大测试筛选时，`long_image_crop_outputs_exact_full_composition_slice_and_retains_effect_sampling` 在长图编辑器效果合成路径超时，中止该次运行。采集、坐标和 UI 专项随后单独通过，原始记录见 `tests-final.log`。

## Windows Release

最终构建 SHA256 为 `15d288f58d617d815fd0320a112d3b7e23a2bd7c28279c69054b2603c10c43f4`。

- 100% 和 125% 屏各通过 8 组 Chrome 原生脚本测试，使用默认平滑滚动。覆盖纵向和横向从中部向两端扩展、回到已拼接内容后使用 J／K 裁剪、裁剪后续接、向下和向右自动滚动，以及在首端拒绝启动自动滚动。实际剪贴板和 PNG 输出与对应参考图逐像素一致。原始结果见 `verified-chrome.log`。
- 两屏各通过 1 组 Excel 冻结首列测试。使用实际鼠标滚动向左追加，125% 屏增加 291 个物理像素，100% 屏增加 234 个物理像素。输出与参考图逐像素一致，冻结首列各保留一份。原始结果见 `verified-excel.log`。
- 两屏的限高预览均验证了上下省略箭头以及预览与控制条无重叠。实际窗口截图见 `verified-chrome/120-v-markers/preview.png` 和 `verified-chrome/96-v-markers/preview.png`。

原生验证范围为 Chrome 和 Excel 两种夹具、两种 DPI 的单屏选区。其他应用的滚动实现未覆盖。

脚本、已知参考图、实际输出、截图、日志和 Release 哈希保存在忽略的 `target/long-capture-bidirectional/`。
