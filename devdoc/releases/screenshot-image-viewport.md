# 长图编辑器统一图片视口验证

日期：2026-10-21。工作分支 `codex/screenshot-long-capture`，未暂存、提交、合并或推送。

## 变更与依据

依据 [PixPin 编辑器研究](../planning/pixpin-image-editor-research.md)，删除长图编辑器标题下的五个浏览按钮及其占位，保留 32px 标题、24px 状态、独立标注工具条，增加浅深主题点阵工作区。初始整图居中适应，小图不放大。

UI 的 `image_viewport` 负责物理缩放、平移、适应及正反坐标转换，`image_navigation` 管理实例所属的浏览手势和输入路由。原生和 Slint 路径共用模型，不再分别换算滚动偏移；图片、标注、文字窗口与光标使用同一变换。鼠标浏览只修改显示属性，不安排整图合成、复制像素或写入文档历史。

浏览模式左键拖图、滚轮鼠标锚点缩放，细增量累计至桥接的一档 60 逻辑像素；每档 1.15 倍，0.1%～1000%，跨越 100% 停靠。空格切换浏览与上次工具，初次恢复画笔；Ctrl+0 恢复整图适应。输入、输出及活动手势按所属状态屏蔽。Escape 取消平移并吞掉同次手势剩余移动；失焦／捕获丢失保留最后位置。关闭释放模型和回调，旧窗口不能修改替换实例。

此前只测标题栏拖动与坐标回调，不等于图片自由平移通过。原按钮式适应宽度、ScrollView 边界夹紧和滚动换算已撤销；历史验证记录保留其当时范围。

## 证据

本次脚本、日志、已知行号像素夹具、组件渲染和原生截图位于忽略目录 `target/screenshot-image-viewport/`。验证结果以下述最终记录为准；组件渲染不替代原生输入与输出像素检查。

## 实测发现及修复

1. Windows 的 Winit 后端把 Grab 和 Grabbing 都映射成四向移动光标。复用既有原生光标生成、窗口子类和销毁机制，加入两份 SVG 手形及 App 注入的视图回调；不增加 Core Port。纹理在构建时生成，移动时仅复用当前形状，按下／松开或 DPI 改变时才切换资源。最终两屏均读取到不同的张开／握住光标，保存了实际光标位图。
2. 跨屏后操作缩放手柄触发工具条重新定位，原生鼠标消息在 Registry 的只读借用期间重入。旧就绪判断只拒绝独占借用，随后写入引发 `RefCell already borrowed`。输入队列改为只有能取得独占访问时才同步投递，否则保留原实例及顺序延迟执行；补充只读借用重入回归。未通过捕获 panic 或忽略输入规避。
3. 原生重绘通知可能早于 Slint 的 DPI 更新，曾出现比例文字保持 43%，实际图片宽度从 260px 变为 208px 的错误。增加所属画布的 DPI 事件后同步，在事件传播完成后更新逻辑属性，保持模型内物理缩放。最终跨屏及缩窗均保持实际 260px；不是只检查百分比状态。
4. 初次组件渲染发现点阵只覆盖下半区，修正点阵行的高度与局部坐标。初次脚本也曾滚动到其他程序，后续强制检查滚动点属于自建夹具；这类诊断图不作为最终输出证据。文字输入先等待真实前台身份，再通过选中复制校验实际草稿，避免把窗口存在误写为输入成功。

## 性能观察与限制

输入到桌面探针像素变化：每屏 20 次，计时区间不含脚本的准备等待。

| DPI | 中位数 | P95 |
| --- | --- | --- |
| 125% | 19.82ms | 21.21ms |
| 100% | 33.74ms | 36.53ms |

原始记录为 `pan-latency.csv`。这是包含桌面合成和 GDI 读取开销的单像素响应观察，不是整帧 GPU 耗时或 FPS。最终版本若干进入编辑的实际首反馈记录约 90～130ms；未提供隔离负载、同口径的旧版本性能对照，不据此宣称提升比例。旧版本身没有图片平移，不能拿其空操作耗时比较。实现中没有新增刷新节流，浏览路径不排队整图合成。

未全面实测：触控板精细滚动、其他 DPI、极限 32 百万像素长图的性能、长时内存曲线、活跃 IME 跨屏及被其他程序主动抢走鼠标捕获。失焦、捕获丢失、过期回调有自动化覆盖；本轮原生操作使用 Windows 鼠标和键盘，不将其扩大为所有输入设备验收。
