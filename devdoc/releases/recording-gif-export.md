# 录屏 GIF 导出验证

## 范围与实现

基线 `main 50a8a8a`，分支 `codex/recording-gif-export`。保存入口提供 MP4／GIF，每次默认 MP4；GIF 固定 15fps、最长边 960px、不放大、最多 60 秒、无声音、无限循环。使用已确认整数帧范围，不使用拖动草稿，不修改图片历史和 R。

Core 的 `recording_gif` 定义格式、拒绝原因、输出尺寸、代表帧及绝对百分之一秒时间线。App 沿用录屏保存调度，UI 只提供阶段文字；Platform 的隔离保存助手取得路径及格式，再在所属后台 MTA 中解码和编码。路径不进入 Core／UI。完整 MP4 原样发布、裁剪 MP4 精确重编码均保留。

GIF 两遍直接读取原封尾 MP4，不先生成裁剪 MP4。Source Reader 只选择视频，保留源帧率，关键帧前滚后按实际 PTS 选择源帧。第一遍最多 60 张代表帧生成小样本与全局 WIC 自适应调色板，添加黑白；第二遍用同一调色板逐帧写完整不透明画面，处置方式 1，NETSCAPE 无限循环扩展。采用 NoCache 写入和同目录所属临时文件，封尾后原子发布；失败、取消清理临时文件，保留源录像和原目标。

受控缓冲估算包括当前解码样本、可见像素、缩放样本、调色板样本、索引图及 RGB666 映射；上限 64MiB。WIC／MF／驱动内部缓存、PrivateBytes 和工作集单列，不将该上限宣称为进程内存上限。取消在解码、行转换、调色板构建和编码阶段检查，原生同步调用不可中断时等待所属调用退役，不启动替代线程。

## 已定位并修正的问题

- WIC 自定义调色板与 `WICBitmapDitherTypeOrdered4x4` 不能直接组合，本机实际返回 `E_INVALIDARG`。保留原失败日志，改为 Core 纯整数 RGB666 最近色映射与固定空间 4×4 有序抖动，WIC 只负责多帧编码。接近已有颜色时抑制不必要的抖动，避免平坦背景产生棋盘噪点。
- RGB32 解码媒体类型继承视频有限范围，会将黑色抬到 16。显式协商 RGB 全范围，保留 BT.709 YUV 源解释；独立检查修正后的黑色为 0。
- 调色板代表帧使用面积平均时会稀释细小彩色文字；仅调色板的小样本改用最近邻，正式画面仍由原解码缩放路径产生。
- 分阶段进度必须允许从颜色分析的完成数重新计为编码阶段的 0；只在同一阶段要求单调，旧范围和请求仍严格拒绝。

### 正式双屏及独立解码

`final-ui/gif-result.json`：100%／125% 各 10 轮成功，覆盖 30／60fps、两档画质、四种声音模式、倒计时、暂停恢复、范围键盘微调、拖动取消、恢复完整范围、一帧范围和保存对话框取消。每次进入默认 MP4，实际切换 GIF 后文件名后缀同步更新。

`independent-final.json`：独立 FFmpeg 解码源 MP4，逐张比较 GIF 中的帧编号与选段抽帧计划，20 轮全部一致。Pillow 独立检查签名、全帧解码、尺寸、延迟、无透明索引、处置方式和循环；ffprobe 检查只有 GIF 视频流。60fps 一帧片段输出 20ms，误差约 3.33ms，满足 10ms 边界。

`final-first.png` 显示修正后的实际输出：受控纯色区域 5000 个像素均为 `(32,53,78)`，没有新增棋盘噪点。该图为 GIF 实际解码结果，不是 UI 原型图。

## 长片段、取消与失败验收

`long-ui/result.json` 及 `long-ui/independent.json`：两个屏幕分别导出一次动态和静态 60 秒 GIF，四份均为 960×540、900 帧、60000ms、无限循环。独立 FFmpeg 解码源 MP4，全部 3600 张 GIF 的画面编号与计划源帧一致，末张对应原选段最后保留帧。原录像约 60.367 秒，直接选择 GIF 时保持保存对话框并拒绝；改选 MP4 仍可操作，缩短确认范围至 1800 个 30fps 源帧后可导出。

| --- | ---: | ---: | ---: | ---: |
| 125% 动态 | 4,256,960 | 2045.04 | 10985.48 | 0.13 |
| 125% 静态 | 4,002,827 | 2015.99 | 10961.85 | 0.06 |

静态夹具首轮错误断言“全部解码 RGB 完全相同”，原始失败保留在 `long-ui.log`。源 MP4 为有损视频，且桌面底部有少量系统内容变化；首／中帧平均通道差约 0.02／0.015／0.087，而夹具编号完全相同。修正为核对冻结夹具身份及源帧对应关系；既有产物重新独立验证，不重新录制覆盖失败，也不声称 GIF 能消除源视频的量化波动。

### 原生门槛

`native-final/result.json`：非关键帧起点、完整标注录像、首／尾单帧、两源帧、三源帧、1cs 尾部借位均通过。320×180 小图不放大；102×1008 竖长源导出 97×960，覆盖奇数输出宽度。正负行跨度、可见范围及截断缓冲有平台纯回归。

`native-final/cancel-20.log`：颜色分析初期／中途、编码初期／中途及封尾前共 20 轮取消，原文件不变、临时产物退役、所属资源计数归零。请求取消至本轮资源退役 P95 **42.35ms**，包含原生调用返回时间；不是 UI 接收延迟。`cancel-summary.json` 保留逐轮数值。

`native-final/fault-write.log`／`fault-finalize.log`：复用受控配额 IStream，分别在中途写入、封尾触发真实原生写入错误，计数分别 3、2，测试正确返回失败。该项属于注入故障，未将物理磁盘填满，也不冒充真实磁盘满测试。

### 正式界面与保存

- `fault-ui/result.json`：分析中取消、编码中取消、导出中关闭后取消丢弃确认、重试成功。真实 Windows 共享冲突阻止最终发布，所属原目标哨兵与源录像均保持不变，临时文件清理。
- `dialog-extra/result.json`：错误扩展名保持对话框，不生成双扩展名；中文与 `.GIF` 接受，实际覆盖确认选择“否”保留哨兵，选择“是”发布成功。首次脚本因错误标签引起布局变化、点击旧按钮坐标而超时，日志保留；重新读取实际按钮几何后续验通过，未修改产品焦点策略。
- `helper-exit/result.json`：终止经 HWND／PID／映像身份核实的本次保存助手，主窗口重新可操作、源文件不变，重新保存 GIF 成功。原生对话框保持辅助窗口身份。
- `live-125/checks.json`、`live-100/checks.json`：原应用点击／拖动／滚轮、控制条拖动、暂停标注、马赛克、放大镜及暂停中提交文字末帧，实际 GIF 均成功。末帧红色文字区域分别仍有 258、62 个可辨红色像素，黑色为 0；颜色量化仍会降低细字细节，不宣称无损。
- `cross-dpi/extras.json`：真实标题拖动、窗口缩放、100%／125% 跨屏、原生视频子窗口几何、键盘定位和居中确认通过，随后实际保存 GIF。
- `region-final/checks.json`：先复制 480×240 截图区，再保存不同尺寸 GIF，之后 Alt+S／R 实际复制仍为原 480×240，像素一致。图片历史接线由 Core／App 回归检查，GIF 不生成图片输出完成事件。

## 内存与退役

60 秒场景受控像素峰值 **8,748,032 字节（8.34MiB）**，保守上界 **26,700,288 字节（25.46MiB）**。各段进程 PrivateBytes 峰值约 463～468MiB，包含 UI／播放器／MF／WIC 等原生资源，不能混写为 64MiB 内存。各段在编码初始化后约 2.5～5 秒达到平台，后续帧数继续增长时不持续保留整帧；逐点数据在 `long-ui/*-memory.json`。

`final-ui/gif-handles.json`：20 轮正式导出后空闲 120 秒，USER／GDI 回到本组起点 38／17；PrivateBytes 从最后一轮 280.9MiB 降至 49.6MiB，总句柄从 943 降至 819，起点 751。不能把仍保留的原生／进程基础资源宣称为全部归零。

扩展故障、长片段及文字验证后，`resources-final.json` 再记录退役及 120 秒空闲，PrivateBytes 约 178.3MiB、总句柄 908。`final-ui/retirement-checks.json` 和 `retired-windows.json` 核实无预览父／子窗口（包括隐藏）、无预览／导出／音频任务线程、无本进程临时录像；录制 Port 服务线程按运行时契约保留。两组 workload 不相同，不将其总句柄差直接归为泄漏或声称正常缓存已经逐句柄归因。关闭应用后所属进程退出，测试声音和桌面夹具也已停止，临时移动窗口按原身份及几何校验恢复。
