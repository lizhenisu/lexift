# 贴图统一隐藏／恢复验证

日期：2026-10-25。基线 `main/34692df`；功能分支 `codex/pin-visibility`。本轮实施不暂存、提交、合并或推送。

## 实现边界

- Core 以独立 `pin_visibility` 批次状态管理目标集合、编号和失败汇总，每个贴图的 `user_hidden` 与原有隐藏标注字段分开。批次不包含之后新建的贴图，逐张成功确认，失败不回滚其他成功项。
- 两个托盘入口共用业务可用性检查，并补充 UI 的准备、绘制和原生拖动状态。批次期间拒绝新图片任务，关闭和退出仍可执行；退出递增版本，迟到命令失效。
- 截图临时隐藏和用户隐藏合并为实际可见性判断，恢复截图不再无条件显示全部贴图。恢复保留所有显示／输入策略，不修改图片、文档、历史和 R。
- 显隐复用原 HWND、组件及原生输入接收器。隐藏取消捕获、菜单、提示和排队输入；公共输入队列支持取消当前批次剩余工作，同时保留将来输入能力。关闭仍退役接收器并销毁窗口。
- 隐藏时记录工作区；恢复不重置位置或物理大小，仅在工作区已变化且范围失效时使用既有夹紧。失败回退原几何和确认状态。

## 回归中发现并修复

原生恢复最初只重复执行通用准备，窗口会保留被动角色，导致之后右键菜单不能正常打开。现已在显示前复用原接收器完成既有交互桥接，不调用激活。组件回归模拟准备后的被动角色，并校验恢复仍使用同一个接收器；原生回归检查恢复后可直接右键操作。

测试工具的 Win+B、Enter 依赖 Windows 记住的托盘选择，连续执行可能打开主窗口。已改为按实际通知图标矩形操作；溢出区未打开时，通过系统 UI Automation 调用展开按钮，再右键真实图标。该逻辑只存在忽略的测试脚本中，不属于产品功能。剪贴板读取遇临时占用时重试；截图取色等待实际所属首帧激活，不靠固定等待或强制激活画布。

## 自动化与组件渲染

- Core：空集合、重复请求、多实例、新对象不加入旧批次、部分失败与重试、关闭、退出和旧结果；编辑／OCR／输出／策略冲突；文档、历史、锁定／穿透／透明度及 R 不变。
- UI：隐藏保留原实例，新贴图可见，失败保留隐藏并可重试，截图恢复和穿透恢复不显示用户隐藏的贴图；工作区变化、过期快照／回调、退出后排队命令；恢复不调用激活。
- 输入队列：隐藏可取消尚未执行和正在执行批次的剩余事件，旧原生排队事件丢弃，恢复后接收器仍可处理新输入。
- 托盘：保留原入口和首字母导航，新增两项映射，窗口重开隔离；十二语言 × 浅深主题 × 100%／125% × 四种可用状态，共 192 组组件渲染，证据为 `target/pin-visibility/render/`。已查看实际渲染，包含长德语文案。

最终回归：Core 243、UI 503、App 76、Platform 215，共 **1037 项通过、0 失败**；另有 111 项既有忽略项，未计为通过。日志为 `target/pin-visibility/tests-final.log` 和 `app-tests-final.log`。格式、严格 Clippy（相关四个 crate、all-targets）、Slint 编译及 Windows Release 构建通过，日志分别为 `format-final.log`、`clippy-final.log`、`release-final.log`。

## 原生实测结果

- 两屏各完成连续 **10 轮**真实托盘隐藏／恢复，检查 HWND 存活、实际可见性、物理位置和大小、前台身份、辅助窗口身份，以及锁定／穿透／透明度组合。恢复不激活贴图；正常贴图恢复后没有残留 `WS_EX_NOACTIVATE`。日志：`native-release.log`、`native-release-96.log`。这两个脚本在后续额外菜单操作中未完整跑完，不将整份脚本标为通过；已经完成的逐轮断言保留有效。
- 隐藏第一张后创建第二张，第二张正常显示且默认 100%，第一张仍隐藏。第二张实际 OCR 复制 `LOCK TEST 123` 后，第一张仍隐藏。两屏均覆盖实际裁剪贴图，以及 20% 透明度、锁定和穿透的普通贴图；裁剪贴图使用 60% 透明度并关闭阴影。
- 普通贴图两屏复制前后均为 320×160，逐像素一致；125% 裁剪贴图复制与保存 PNG 均为 192×112，和隐藏前完全一致。125% 贴图跨到 100% 屏幕后显隐，复制仍与原图一致。证据：`release/pixel-comparisons.json`、`release/native/`。
- 真实滚动长截图生成 600×1200 贴图，在两屏分别隐藏／恢复；实际复制与已知原图对应区域逐像素一致。保留包括部分越过工作区边缘的位置、透明度、锁定与穿透；托盘恢复鼠标输入后透明度仍保留。完整日志 `long-release.log`，像素对照 `release/long-pixels.json`。
- 用户隐藏后进入截图，C 取色为下层已知颜色 `#466496`；取消截图、取消延迟倒计时后保持隐藏，任务期间托盘恢复不可用。125% 屏幕完整链路已通过，100% 对应恢复与任务冲突另由自动化覆盖。
- 单独完成“隐藏贴图 → 截图 → 复制成功”实测，输出 250×100 全部为下层夹具颜色 `(70,100,150,255)`，没有隐藏贴图或交互装饰，原贴图仍隐藏。完整日志 `output-release.log`，图片 `release/output/captured.png`。
- 实际查看托盘菜单、关键桌面帧和已恢复贴图；正常关闭后所属 HWND 销毁。原生证据均来自上述最终 Release；调试构建的焦点排查另存，不混入 Release 通过项。

## 后续补验：100% 裁剪贴图保存

贴图旋转／翻转实施期间补查原菜单超时：实际 `WindowFromPoint` 返回下层测试夹具 `Pin policy fixture` 的 HWND，与夹具枚举结果一致。夹具设置了 `TopMost=true`，在两张贴图的原生菜单交接后遮挡第二张；这不是贴图菜单失去输入。脚本另有菜单尚未出现就发送 Escape 的问题，已修正为只关闭实际存在的菜单。

改用普通背景夹具后，对原 Release 重新执行“隐藏旧贴图 → 新建并裁剪另一张 → 恢复 → 复制／保存”。100% 屏幕输出均为 192×114，恢复前、恢复后复制及 PNG 的 RGBA 完全一致。证据：`target/pin-image-transform/legacy-copy-save.log`、`legacy-hit.json`、`legacy-pixels.json`、`legacy-binary-hash.json`。本节补齐上述保存末端缺口，不把此前失败脚本的其他未完成步骤计为通过；产品层级策略未因此放宽。
