# 窗口自动识别与一键框选验证

日期：2026-10-18。起点：`6e23b86`。本轮修改未暂存、提交或推送；源码与文案之外的夹具、桌面截图及日志均放在忽略的 `target/`。

## 实现与边界

- 首次框选悬停时，从冻结列表选择鼠标所在的最前普通顶层窗口。单击采用完整 DWM 可见窗口框架（含标题栏、不含阴影），裁切到捕获桌面后进入编辑。
- 按下冻结候选；任一轴移动超过按下屏幕的 4px 逻辑距离后，永久转为从原按下点自由框选。没有候选时保持原手势，零面积不提交；取消不留下候选、对象或历史。
- Core 提供 `WindowCandidate`、前景命中、稳定性比较和候选点击手势。UI 仅维护悬停并复用已有边框、遮罩、尺寸标签、像素放大镜及宿主身份校验；鼠标移动不做原生窗口查询。
- 当前截图实际使用排除辅助窗口的后台采集与原桌面标注合成，因此扩展既有 Port 的元数据快照方法 `screenshot_windows`（默认空列表），由 App 的截图准备方法组成 `ScreenshotCapture`。保留原像素路径，不改用单独 GDI 抓图。新能力没有新增 Port、依赖或 crate。
- Windows 复用后台采集的可见性、最小化、DWM 隐藏、物理范围与排除名单；过滤桌面、任务栏、菜单、透明及辅助窗口。过滤后才生成层级编号。准备前后变化或缺失的条目丢弃；枚举失败保留原手动框选。
- 本轮只采用冻结桌面的矩形内容，不补画被遮挡部分，不识别窗口内部元素，不跟踪后续真实窗口移动。编辑、OCR、普通标注及贴图不启用候选。

## 未覆盖范围

- 实机布局为 2560×1440／125% 与 1920×1080／100%；负坐标、捕获边界裁切及无候选由 Core／UI 夹具覆盖。
- 12 语言、浅深主题与两种 DPI 的提示矩阵属于组件渲染，原生流程使用当前中文主题；不是所有语言的原生验证。
- 窗口在准备中移动、枚举失败及取消通过可控制 Port 覆盖；没有强制制造系统枚举错误或抢占其他进程窗口。
- 不验证内部控件、UI Automation、多层候选切换、独立窗口截图或被遮挡内容恢复；不声称支持新一轮实时窗口查询。
- 没有重跑 OCR 端到端识别、全部绘制工具的原生交错、远程桌面或所有显卡驱动组合；共用框选与编辑路径以相关回归为依据。
