### 功能与 Shell

- 实际 PaddleOCR 在两个 DPI 显示器识别同一中日英及繁中文固定夹具，原文出现在 Popup；四方向跨屏选区均完成裁切和识别。
- Escape、右键及再次 Alt+T 取消通过，连续创建／销毁后未留下遮罩窗口。
- 标注在两个显示器创建透明画布及既有 GPU 宿主；矩形绘制可见，撤销恢复原像素，关闭／重开通过。GPU 专用窗口没有迁移到 Slint。
- 实际 Alt+Tab 和任务栏截图没有 Lexift 辅助窗口入口，未仅以扩展样式代替 Shell 检查。
- 功能截图及记录位于 `target/screen-host-native/full/`，执行日志为 `screen-host-full-desktop.log`；原生阶段日志为 `screen-host-desktop-runtime.log`。

### 未通过及未覆盖

- 当前用户配置的模型服务不可连接，Popup 正确保留识别原文并显示翻译失败；本轮没有验收真实模型的成功翻译或流式输出，相关状态／调用由既有自动化回归覆盖。
- 首轮脚本调用 `SetForegroundWindow` 被 Windows 拒绝，Lexift 主窗口仍在前台，此条件下合成 Escape 未取消遮罩；直接发送有效实例的取消消息及右键可取消。改用真实点击测试输入窗口并核对前台 HWND 后，主窗口仍打开时 Escape 回归通过。主窗口自身为前台的物理 Escape 行为尚未人工确认，不将这一差异归因于等待时间，也不宣称已解决。
- 本轮实际绘制／撤销使用既有 GPU 路径；全部标注编辑工具、放大镜、聚光灯和软件回退没有逐项实机遍历，相关自动化回归通过。

当前没有负坐标显示器；负坐标由手势、坐标、裁切和 HWND 回归覆盖。录屏按实际帧数和采样间隔报告，不能声称覆盖每个物理扫描帧。原生窗口准备失败及旧回调由自动化覆盖，不冒充实机故障注入。
