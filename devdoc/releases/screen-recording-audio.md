# 录屏系统声音与麦克风实施记录

基线 `main a7046a0`，实施分支 `codex/screen-recording-audio`。**本项正在实现与原生复测，不代表最终验收已完成。** 无声生产链路基线见[上一轮记录](screen-recording-mp4.md)。证据位于忽略目录 `target/screen-recording-audio/`，不纳入 Git。

## 范围和实现

- 每次录制默认无声。准备界面选择无声、系统声音、麦克风或两者；开始和暂停期间不可更改。配置请求串行，失败保留原确认模式，取消不等待 UI 线程上的原生工作。
- 默认常规设备角色 `eConsole`；准备只初始化端点，实际开始才调用 WASAPI Start。设备通知只置位并唤醒所属源线程，端点身份不进入文档、配置或用户日志。
- 每源一个 MTA 线程，事件驱动共享模式采集，源线程创建并释放全部 COM 对象。原生包先复制并 ReleaseBuffer，再通过所属 Media Foundation resampler 转为 48kHz 双声道 float。设备位置和转换后的样本序号分别保存，不能直接混用。
- 唯一录制工作线程合成音频并写入现有 Sink Writer；单源原电平，双源各 50%，最终夹紧。视频维持既有 H.264 参数，声音为单条 AAC-LC、48kHz、双声道、192kbps。无声文件没有音轨。
- 视频和音频以首个有效 WGC 帧的 QPC 为媒体起点。暂停共用活动时间线，继续使用新鲜时钟锚点。设备漂移通过有界插值校正，已定位的 loopback 空闲间隙保持静音，不保存大段零数组。未知不连续及失效中断，不无限补零。
- 完成先停止并排空声音，再与视频末帧覆盖区间对齐封尾。准备不再创建编码文件；取消、关闭及退出沿用资源退役确认，旧资源未释放时不替换线程重新开始。
- 各 PCM 队列最多 500ms；自有缓冲保守上界按 native-format 副本、MF 输入／输出、源队列、交接和编码输入共同检查，低于 8MiB。MF 内部缓存和进程 PrivateBytes 另计。

## 保留的失败与修复

1. 早期把设备位置直接与 48kHz 转换后帧数相加比较，麦克风出现 `expected=463, position=160`。改为保留设备原始位置，单独管理转换帧序号，使用采集 QPC 校时，增加原生格式转换检查。
2. 声源先于 WGC 原生资源准备启动，准备耗时会占满 500ms 音频队列。改为先建立捕获资源，再启动实际声源；没有放宽队列上限。
3. 真实系统声脉冲／闪光短片出现 55～95ms 偏差。视频曾从首帧处理完成时开始累计，音频按首帧采集 QPC 对齐。已统一为采集时间起点，**修复后的真实同步尚待复测**。保留 `ui-smoke/system-smoke.capture-sync.json` 首轮失败。
4. 首个 UI 冒烟短片有外部窗口遮挡夹具，不能用于“全画面纯夹具”和排除矩阵验收。后续测试须先记录并移开重叠窗口，结束后恢复；不将遮挡误报为录制装饰入图。
