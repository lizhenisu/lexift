日期：2026-10-19。功能分支 `codex/screenshot-region-history`。实施前已按授权将 `b404b34` 快进合入 main；验证完成后按用户授权提交并快进合入 main；不推送。

## 实现与边界

- Core 保存一份本进程内的几何记录及显示器物理范围集合。只有当前会话、操作编号匹配的图片复制、PNG 保存、贴图成功完成更新记录；使用输出冻结的最终区域。取消、失败、OCR、取色及迟到结果不更新。
- 新截图的准备结果携带实际捕获布局，物理布局集合相同才允许复用，忽略枚举顺序与逻辑 DPI。布局改变时禁用，保留记录供之后恢复原布局使用，不猜测裁切或挪动。
- 首次框选完整反馈就绪、所属宿主位于前台、没有按下手势时，无修饰键 R 发起请求。会话、宿主和递增编号贯穿 Core 命令及 UI 回调；待处理时屏蔽重复提交，拒绝后释放输入。
- 复用与鼠标框选共用提交收尾，取消按点查询、退役原宿主输入并保留完整画面直至编辑首帧。新冻结像素、空文档及原有编辑／输出链路继续使用；不新增图片存储、配置、依赖、crate 或 Core Port。
- 首帧创建前确定 R 提示是否存在，避免新增行仍沿用旧的测量高度。提示与原框选帮助在宿主内绘制，12 种语言同步。

## 保留贴图后的连续复用修复（2026-10-19）

### 复现与根因

用户报告“截图 → R 复用 → 贴图 → 保留贴图 → 再截图 → R”失败。上一轮关闭测试贴图再做下一次截图，漏测了贴图仍存在且持有焦点的实际链路；上文通过结论不能覆盖这个场景。

使用修改前项目 Release（SHA256 `354EA4E2A0FCE0C02667D2F5D22366EBEA96E9EC4CE0B79CC4FA7DF91A1766C4`）复现：贴图持有前台，下一次截图的 `show` 在创建宿主前执行 `set_frozen(true)` 隐藏它，Windows 把前台交回主窗口。首帧激活校验仍持有旧贴图身份，日志记录 `origin=47908932`、`current=72813126`、`permitted=false`；R 未到达截图宿主。区域记录不是本次失败点。

原始证据在忽略的 `target/screenshot-region-pin/baseline-*`，包括运行程序摘要、失败窗口身份及激活日志。基线首次仅保留贴图但不让其持有焦点时可以通过，不能据此否定用户反馈。

### 修复

- 增加 UI 宿主完整反馈就绪通知。全部宿主已完成反馈、原有一次性激活已执行后，截图所属回调才隐藏贴图。快速鼠标提交另有收尾，避免未等全组反馈就提交时遗漏贴图处理。
- 就绪通知校验会话和实际宿主实例，离开框选后丢弃；不放宽前台许可，不新增激活重试、全局 R、钩子或同进程窗口豁免。
- R 请求、应用及截图阶段变化增加低频诊断，只记录身份、阶段和可用性，不记录图片或正文，不在鼠标热路径增加输出。
- 保持几何记录、成功输出时机、布局失效和重启清空原规则。贴图窗口按原策略显示／恢复，实际拖动、焦点和生命周期继续复用原实现。
