# Windows Slint 软件渲染缓冲区崩溃验证

基线为 `main 31f31be`，实施分支为 `codex/slint-software-buffer-stability`。原失败证据见[贴图管理记录](pin-manager.md)和[退出稳定性记录](pin-exit-stability.md)。

## 根因与修复

- 原生失败日志记录了软件渲染器收到 `72,000` 像素、每行 `360` 像素的缓冲区时，布局已经要求 `450×250`。贴图和图片历史反馈都在设置尺寸后立即调用快照来推动布局。
- 最小复现使用实际 Slint 软件渲染器。在 `360×200` 的缓冲区先派发 125% DPI、暂不递交新尺寸，旧的快照调用触发同一断言。带符号调用栈定位到 `Window::take_snapshot`。回归验证新路径拒绝不一致的布局，尺寸对齐后生成完整像素，反向 DPI 切换及短文案也能重新测量。
- 两条提示路径共用隐藏窗口尺寸准备。按当前内容宽度计算换行和高度，等待 Windows 客户区、Slint 表面和布局尺寸一致后再呈现。过期原生尺寸事件不覆盖当前尺寸，提示实例失效后的完成回调不会显示旧窗口。贴图为原生分层窗口提供首帧时只做一次快照。

## 证据口径

- 当前基线的九次单次原生探测和一次小批量跨屏验证没有自然重现偶发崩溃。原自然失败的尺寸日志与本轮确定性快照重现分开保留。
- App 91、Core 390、Platform 239、UI 563 项单元测试通过，另有一项文档测试通过。严格 Clippy、格式检查和 Slint 编译通过。
- 证据存于忽略的 `target/slint-software-buffer-stability/`。包括基线原生日志、`snapshot-stack.log`、软件渲染器回归、构建哈希、双屏交互记录和桌面截图。

## 最终 Release 原生结果

- 使用默认软件渲染器。在 125% 和 100% 屏各执行 20 轮贴图右键开启穿透、显示提示、从托盘恢复鼠标操作和销毁提示的连续验证。贴图由 125% 移至 100%，再移回 125% 复测一轮，共 41 轮通过。每轮确认提示具有鼠标穿透和不激活样式，恢复后旧提示 HWND 已销毁。
- 检查两屏的实际提示截图。125% 提示为 `450×94`，100% 提示为 `360×75`。窗口、表面和布局尺寸对齐，双行文案完整呈现。
- 通过无图片剪贴板触发图片历史共用提示。Alt+S 使提示窗口在桌面像素冻结前退役，Escape 恢复贴图。最终从托盘自然退出并返回 `0`。
- 原生矩阵为 `release-final/result.json`，首帧证据为同目录下的 `desktop-*.png`，截图时序为 `capture-handoff.log`。Release 构建通过。
