# Windows 横向长截图固定列验证

基线 `25f3f58`，实施分支 `codex/long-capture-horizontal-fixed-columns`。横向采集复用转置工作帧和固定边缘匹配。首次追加时同时验证全帧及固定列候选，仅确认唯一的正文位移和固定边界。横向全帧及正文匹配均使用原分辨率 RGBA 比较。确认后固定范围保持到采集结束，预览和输出共用列序，采集内裁剪只移除正文。

## 自动化与构建

Core 26 项覆盖左固定列、右固定列、双侧、无固定列、首帧直接完成、局部预览、历史定位、左右裁剪、续接、固定列像素及宽度变化、纯色、歧义、取消与共享资源上限。App 5 项、UI 11 项及 Platform 的双轴原生滚轮结构测试通过。Slint 编译、格式检查、严格 Clippy 及 Windows Release 构建通过。Slint 仍报告截图尺寸输入框的既有重复可访问文本警告。

## Windows Release 实测

最终构建 SHA256 为 `b930c4b401c146bbb9d1c08aa7b4bb565faa9ccd44a99bde78a97add9294807a`。旧构建 `ac136457fa428e1f2addbc57412ccf20cc7e24750237e2dadefea275cf7af744` 在同一双侧固定列夹具首步停止，保留了原始 600×400 选区。新版在 100%／125% 两屏完成以下核对。

| 场景 | 两屏结果 |
| --- | --- |
| Chrome 左侧、右侧和双侧固定列 | 共六轮自动滚动到末尾，以画面不变停止。实测剪贴板分别为 1400×400、1380×400，双侧 PNG 为 1460×400，均与独立合成参考图的 RGBA 一致。 |
| Chrome 手动滚回、左右裁剪并续接 | 两轮按 `J`、`K` 后继续手动滚动。125%／100% 的剪贴板分别为 975×400 和 900×400，正文连续且两侧各一份。 |
| Chrome 预览 | 八轮均独立检查原生预览尺寸及绿框横向边界，与正文范围一致。Core 另行逐像素比对完整和受限预览。 |
| Excel 冻结首列 | 两屏均实际点击原生水平滚动条箭头三次。125% 屏保留 96px 冻结列，追加 291px，成品为 871×400。100% 屏保留 77px 冻结列，追加 234px，成品为 814×300。剪贴板与从工作表独立采样构建的参考图逐像素一致。 |

同一 Release 双屏回归无固定列横向采集及纵向自动滚动。横向的两份 1320×400 剪贴板成品逐像素匹配参考图。纵向六轮覆盖滚动到末尾、移出选区后续接及准备超时。

Excel 预试保留了窗口命中及参考区间失败记录。最终夹具只采样工作表内容，避开焦点浮层、当前单元格边框和底部滚动条。动态固定列、资源上限和重复纹理仅做自动化验证。Excel 自动滚动及其他应用的真实布局未实测。

原生脚本、参考图、成品、截图、日志和构建哈希保存在忽略的 `target/long-capture-horizontal-fixed-columns/`。
