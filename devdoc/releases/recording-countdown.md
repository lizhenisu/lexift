# 录屏倒计时开始

基线 `main cbc8cfa`，实施分支 `codex/recording-countdown`。原始证据存入忽略的 `target/recording-countdown/`，不记录用户图像或声音正文。本轮不暂存、提交或合并。

## 实现与交接口径

开始主按钮保持立即开始；准备阶段箭头提供立即、3／5／10 秒菜单。配置准备及手势期间不接纳请求，不记忆延迟。Core 原录屏生命周期增加提示准备、计时、退役及准备恢复阶段；会话、操作和递增请求隔离异步结果。App 使用可取消的 Tokio 单调截止任务，提示成功显示后才开始计时。到期需完成窗口隐藏及 DWM 交接确认才派发原生 Start。

倒计时使用已有截图提示视觉、被动可点击取消策略和捕获排除。工具条与画布临时隐藏前安装被动策略，恢复显示后重新安装所属窗口输入策略；不执行外部焦点激活。范围及已确认标注反馈继续使用现有原生呈现。取消恢复原准备位置和确认配置；旧计时任务不能启动新会话。到期重新沿用原生资源／设备验证，不改变编解码、音画同步或缓冲预算。

## 自动化与构建

单调时钟测试覆盖提前到期、重复请求、取消与退役竞争、旧请求、失败恢复及布局失效。十二语言、浅深主题、100%／125% 的提示与控制条组件渲染已运行并检查实际渲染图。Core／Platform／UI 回归、严格 Clippy 与最终 Release 的原始输出分别留在 `final-unit.log`、`final-clippy.log`、`final-release.log`。

## 原生验证

最终 Release SHA256：`D941B1C4D7E9581F5EB81F469FF016F1E4132F87BD65C6A81FED08FDC1239311`；基线 `baseline-cbc8cfa.exe` 为主线 `742E33E6096F2ACE8512646AD598B36AA5971E1D75DCFE40A1339A2289D26F74` 构建。

- `matrix/`：100%／125% 每屏的 3／5／10 秒各五轮开始及五轮取消，共 60 项。四种声音模式及四种帧率／画质组合均覆盖；取消后控制条原位置不变，原应用保持前台，外部 Escape 不取消。原生夹具的点击、拖动和滚轮计数确认输入确实到达下层应用。
- 30 个实际 MP4 全部独立解码通过。检查 H.264 High、1920×1080、30／60fps、绝对 PTS、完整帧数、AAC 音轨及尾部填充；解码编号的实际更新率均为 30／60fps。首帧编号与原生源提交时间及真正 Start 区间匹配，没有用倒计时前的静态冻结图当作首帧。声音四模式的音轨和解码经过实测；采集器仅在原生 Start 后创建的约束同时核查现有实现，不以静音片段宣称完成新的声学同步测量。
- `live-125/`、`live-100/`：60fps 高清双声源，准备中先绘制、倒计时取消、再次倒计时开始；继续验证控制条拖动、暂停标注、马赛克、放大镜、文字末帧和保存取消重试。末帧实际检测到 512／283 个文字红色像素，控制条和范围层抽样位置保持底图颜色。范围外采样与交互装饰不进入成品。
- `region/`：先实际复制 480×240 选区，再完成延迟录屏，下一次 R 复用后的真实剪贴板尺寸及像素与之前一致。视频没有改写桌面区域记录。
- 310 项 Core、229 项 Platform、554 项 UI、16 项 App 截图相关测试通过；Platform 118 项、UI 13 项显式忽略测试不算作常规通过。严格工作区 Clippy、格式、Slint 编译及 Windows Release 构建通过。

## 时序与性能

`countdown-timing.json` 使用单调截止任务的实际迟到值，另列窗口退役和原生启动；不是把结束倒计时当作有效媒体已经产生。

| 指标 | P95 |
| --- | ---: |
| 到期事件调度迟到 | 11.29ms |
| 到期事件到提示退役及准备画面恢复 | 32.66ms |
| 提示退役到原生 Started 通知 | 201.63ms |
| 原生开始到保守的首个编码样本上界 | 233.73ms |

各阶段存在不同起点，不能把重叠区间简单相加。30 次到期事件迟到的中位数为 6.69ms。基线与最终版无并行编译／性能测试，分别每屏预热一次、测量十轮立即开始；35ms 的真实按下时长及原有保守调度口径保持一致，独立解码不计入封尾。

| 屏幕 | 启动 P95 基线→最终 | 封尾 P95 基线→最终 |
| --- | ---: | ---: |
| 125% | 259.47→264.06ms（+1.77%） | 232.99→223.67ms（−4.00%） |
| 100% | 269.05→264.21ms（−1.80%） | 217.16→227.69ms（+4.85%） |

两屏均满足不恶化超过 10%。原始逐轮输入、资源和日志在 `baseline/`、`immediate/`，汇总为 `performance.json`。

## 生命周期、失败证据与范围

60 项交错操作覆盖超过 20 轮取消／开始，没有迟到的旧倒计时再启动新会话。结束后枚举所属 HWND，未残留录制控制、倒计时、画布或 GPU 范围窗口；`retired-windows.json` 中保留托盘、单实例、Winit 事件目标和系统 IME 等进程基础窗口，唯一可见目标为 18×18 的后台事件窗口。最终通过真实托盘退出，播放器及原生源按所属停止信号正常退出，移动过的外部窗口按实例及原几何校验还原。

记录 PrivateBytes、工作集、GDI／User 和进程句柄，不宣称所有进程句柄回到冷启动基线；主线已有逐轮句柄增长现象，窗口销毁及退出检查不能替代完整的句柄归因。工作集修剪不作为资源释放证明。

保留三类测试脚本失败：`smoke/` 取消恢复后外部仍拥有焦点，脚本错误地用 Escape 收尾原截图，改为真实工具条取消；副屏 `ImageGrab` 默认只截主屏，读取到零编号，独立首帧验证改用原生源时间／解码编号；全区域颜色断言把结束按钮处的系统光标误判为控件污染，查看真实首尾帧后仅排除已知光标位置，并继续检查控件区域。对应失败报告及图片均未删除，不把这些脚本失败记为产品修复。

显示器布局变化、提示准备失败、旧结果和取消竞争由 Core 自动化覆盖，本轮没有实际拔插显示器、切换音频端点或破坏 DWM 环境。麦克风真实声学同步、权限拒绝及设备失效沿用[既有环境边界](recording-audio-validation.md)，不把确定性模拟当作硬件实测。十二语言／浅深主题由组件软件渲染检查，原生交互实测使用中文及两种 DPI；未声称十二语言均逐项手动操作。
