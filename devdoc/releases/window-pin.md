# Windows 实时窗口贴图接入验证

基线 `362e958`，实施分支 `codex/window-pin`。本轮验证的是截图工具条、实际贴图窗口和普通贴图交接。原生技术夹具的结果仍见[独立 WGC 验证](window-pin-gate.md)。

## 接入与计量

- 截图编辑「更多 → 窗口贴图」按本次冻结窗口候选顺序取目标。WGC 绑定源 HWND、进程及线程，启动时复核物理边界和客户区；源窗口移动后使用同一客户区坐标，DPI 改变时重新映射。暂停原因包括最小化、选区越界及缓冲超限。
- WGC 双缓冲、局部读回、交接与视图缓冲合计估算不超过 128 MiB；驱动和进程工作集不计为同一口径。后台通知合并为单槽，UI 记录原生重绘帧，首帧与冻结交接额外等待 DWM 确认。冻结在同一 HWND 安装确认帧和空标注文档。
- Windows 原生脚本、合成源、剪贴板输出及日志在忽略目录 `target/window-pin/`。双屏性能由窗口显示后的桌面色块变化计数，遮挡用命中 HWND 核实；不是按提交频率推算。启动由点击菜单至 UI 呈现确认，退役由冻结输入至采集退出日志，含脚本检查开销。
- 对应原生命令为 `python target/window-pin/native.py <run>`、`python target/window-pin/edge.py <run>`、`python target/window-pin/browser.py <run>` 和 `python target/window-pin/matrix.py <run> 10`。应使用已登录的交互式桌面。

## 已有实测和失败保留

- `smoke-2/`：125% 主动冻结及 100% 源关闭自动冻结均成功，最小化保持旧画面，恢复后出现新画面，普通贴图均复制出 380×260。第一次脚本误找「复制图片」，而实际译名为「复制图像」；保留初始失败。
- `edge-cross-dpi/`：跨客户区和启动前源移动均拒绝，截图编辑保留；拒绝后原截图可复制。源缩小越界暂停，恢复后继续更新。托盘真实隐藏／恢复不抢前台，直接关闭退役采集但不关闭源。源从 125% 移至 100% 后冻结输出 304×208，逐像素匹配合成底图。
- `browser-probe-2/`：Chrome 动态网页及 Chrome 播放的合成 SDR 视频，在两屏分别通过动态更新、冻结、标注入口及原生 PNG 保存，成品 400×260。未使用外部播放器或用户视频。
- `delivery-smoke/`、`delivery-edge/` 和 `delivery-browser/` 在 4.5 秒性能矩阵所用构建复测上述链路。`delivery-ocr-2/` 在 125% 屏通过真实 OCR，把冻结画面中的 `WINDOW PIN 417` 写入剪贴板；首轮脚本在截图工具条完成退役前尝试操作贴图，保留超时证据。`confirmation-5/` 核对取消实时贴图确认后，原截图标注仍在实际复制结果中。
- 首轮 1080p 试跑约 22–24fps。调整采集节拍，以读回开始计算下次采样；Slint 直接上传预乘像素，由背景层处理透明部分。此前试跑和帧率未达标的记录仍保留。
- 节拍优化后的 `release-matrix/` 每屏各十轮，SHA256 `82ff9a7e050a0f45e854bb0fed47dd21c0070d4196522b2c0b69357d7e8a2b18`。125% 捕获区域为 1920×1080；100% 屏物理尺寸恰为 1920×1080，保留常规窗口边框后的测试选区为 1900×1020，源客户区为 1920×1080。

| 源 DPI | 无遮挡更新率 最低／中位数 | 完全遮挡更新率 最低／中位数 | 首帧 中位数／P95 | 冻结至退役 中位数／P95 |
| --- | --- | --- | --- | --- |
| 100% | 28.95／29.91 fps | 29.49／29.98 fps | 235.72／237.63 ms | 96.94／122.67 ms |
| 125% | 28.49／29.22 fps | 26.64／28.27 fps | 252.88／313.80 ms | 167.68／170.74 ms |

125% 完全遮挡的 2.1 秒窗口有一轮 26.64fps，未通过该轮 27fps 门槛。20 张贴图的 HWND 均在关闭后销毁；暖机后 USER／GDI 稳定为 38／18，进程总句柄 486→522。前次独立夹具已经归因的 NVIDIA 叠加层不能作为本次未分类计数的直接结论。

`delivery-matrix/` 使用 4.5 秒采样，每屏十轮，SHA256 `671e0d1c64490a9bb9c94e15154c71b48610e5b4c64eb627f1efafe3ce11c433`。100% 无遮挡最低 29.96fps、完全遮挡最低 29.51fps；125% 无遮挡有一轮低于 27fps（最低 26.22fps），完全遮挡有八轮低于门槛（最低 17.99fps，中位数 26.53fps）。保留两轮原始结果。之后发现脚本把测试名称中的 `failed` 误认作结束信号，部分原生采样与自动化重叠，不能作为干净的性能基线。

同轮 20 张贴图 HWND 全部销毁，USER／GDI 仍为 38／18，线程句柄类型计数保持 28。总句柄 486→520，其中 Mutant 和 Section 各增加 19，全部带 GUID `2627e361-24e2-4f14-99ed-a20d0685d8dd`，与独立夹具在 `nvspcap64.dll` 匹配的对象相同；ALPC Port 减少 4，其他类型计数不变。此归因仅针对该 GUID，不将 PrivateBytes 或工作集当作应用资源释放证明。

`timing-probe/` 对采集与 UI 分别计数，每屏三轮。125% 屏每轮成功读回 309–310 帧，提交 301–304 帧，确认重绘 277–282 帧。读回平均约 3–4ms，逐帧 DWM 确认平均约 9–10ms，且原先在 UI 线程同步等待。改为仅首帧和冻结需要 DWM 确认；其余帧在原生重绘后记录版本，冻结时只采用最后已重绘帧，不从待呈现队列取帧。

## 最终 Release

`fenced-quiet/`：编译与回归均退出后，两屏分别独立采样十轮，无遮挡及完全遮挡均各观察 4.5 秒。SHA256 `0ab0fd3905bc2a23cc693c58d32c4389be81499893ea2bf8a1bf00c49bda7f91`。

| 源 DPI／区域 | 无遮挡更新率 最低／中位数 | 完全遮挡更新率 最低／中位数 | 首帧 中位数／P95 | 冻结至退役 中位数／P95 |
| --- | --- | --- | --- | --- |
| 100%／1900×1020 | 29.95／29.99 fps | 29.75／29.97 fps | 235.80／245.38 ms | 118.10／122.33 ms |
| 125%／1920×1080 | 29.33／29.96 fps | 29.69／29.86 fps | 248.97／287.71 ms | 102.69／148.07 ms |

上述 20 轮均达到 27fps，关闭后所有贴图 HWND 消失。最终构建的进程句柄、NVIDIA 对象分类、USER/GDI 计数重现了此前结果。125% 屏每轮 DWM 确认耗时的中位数由约 2.55 秒降至约 5.86ms。另在同一构建使用 `fenced-smoke/`、`fenced-edge/`、`fenced-confirmation/`、`fenced-ocr/` 复测冻结、最小化、跨 DPI、显隐、取消确认、复制及 OCR；`fenced-browser/` 在双屏复测 Chrome 网页及浏览器播放的 SDR 视频，四次均成功冻结、打开标注并保存 400×260 PNG。

100% 屏只有 1920×1080 的物理范围；带边框窗口无法在该屏提供满尺寸客户区。尝试无边框源的全屏手动框选和候选单击，未能完成正式入口交接（见 `full-geometry-probe*/` 和 `full-candidate-probe/`）。该屏 1900×1020 的性能达标，1920×1080 不计为通过。独立播放器、HDR、受保护内容、各语言的原生交互、采集至呈现与恢复延迟的独立时钟测量未覆盖。

## 回归

最终 Core、App、UI、Platform 回归分别通过 351、86、557、238 项；专项覆盖候选遮挡顺序、错误回退、版本隔离、冻结数据引用及缓冲上限。格式、严格 Clippy、Slint 编译和 Windows Release 构建通过，新增九条文案已核对十二个翻译目录。
