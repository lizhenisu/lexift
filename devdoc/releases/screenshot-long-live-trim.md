# 长截图采集内裁剪验证

基线为 `016de88`，实施分支为 `codex/long-capture-live-trim`。裁剪以已呈现的当前正文范围为界。向回滚动只更新定位，裁掉尾部才更换追加锚点。固定页眉和页脚仍只输出一次。

## 验证口径

- Core 使用非周期像素行验证双向裁剪、历史定位、从新尾部继续、固定栏及像素边界。重复匹配、失效范围、过期命令和自动滚轮结算均有独立断言。
- App 通过替身连续帧验证旧预览请求被拒绝，并逐像素比较裁剪后的最终帧。UI 使用软件渲染验证十二种语言、浅深主题及两种 DPI。
- Windows 原生脚本使用 Chrome 本地已知行号页面和固定表头内嵌列表，通过实际鼠标及键盘操作采集控制条。验收对照最终复制或保存像素，并读取裁剪菜单的窗口捕获排除标记。

日志、脚本、生成的参考图及成品保存在忽略的 `target/long-capture-live-trim/`。采集汇总记录匹配、定位、预览更新、裁剪耗时及所属保留像素峰值。

## 回归定位

- 稀疏文字夹具复现了回滚时正向配准误认新增行。拼接器按已确认的正文维护行指纹，只有通过整帧原像素验证的唯一位置才提供裁剪。行索引不持有第二份已拼接图。
- 自动滚轮结算更新截图启动可用性时，原公共菜单清理会关闭尚未呈现的裁剪菜单。裁剪菜单改由所属采集会话和控制条实例管理，结算后且前台仍属于发起交互时才打开。保留 `trial-native-3/` 与 `final-native/` 的原始失败。
- 早期 PNG 夹具误用跨进程文本读取，并曾在最终路径发布期间打开文件。现通过原生编辑控件读取实际文件名并以可解码成品判断成功。保留 `trial-native-5/` 与 `release-native/` 的旧记录。

## 自动化

Core 长截图 21 项、App 采集 worker 3 项、UI 截图相关 65 项、Platform 窗口策略 20 项通过。UI 回归包含十二种语言、浅深主题和 100%／125% 软件渲染。Platform 的一个独立桌面夹具用例仍按既有规则标记忽略，生产 WGC 链路由双屏原生脚本覆盖。格式、严格 Clippy 和 Slint 编译通过。
