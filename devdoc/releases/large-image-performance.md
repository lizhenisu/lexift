# 大图编辑性能与内存验证

## 基线和最终构建

- 日期：2026-10-28，Windows MSVC，100%/125% 双屏；代码基线 `main` 的 `706cffa`，工作分支 `codex/large-image-performance`。
- 修改前 Release SHA-256：`3C4A52FED35F9A66E516D0ED9157880355D6E220C4EBD2FDE535102DDAD172CE`；最终交付：`FABC4A9EA1426ED0B032082E28223F150056B13453D0ECBD567C65EACDA721D5`。最终原生六组链路、大图输出和十轮首次打开均核对该哈希。
- 原始夹具、日志、脚本、截图及构建副本位于忽略的 `target/large-image-performance/`。`optimized/`、`final/`、`preliminary/` 是过程构建；正式结论使用 `delivery/`、`delivery-regression-*`、`delivery-large*` 和 `delivery-cold-quiet-*`。
- 实施与验证阶段未暂存、提交、合入 main 或推送；验收后按用户授权提交并快进合入 main。没有修改配置、依赖、crate 或 Core Port。

## 实现及取舍

- 内容与交互反馈分开失效，按源图、内容、DPI 分区、裁剪、方向、颜色和尺寸倍率验证缓存。worker 以共享不可变像素移交结果；独立编辑器只在内容身份变化时安装底图。
- 可重建内容缓存每个 worker 最多 32MiB；超出仍以原分辨率呈现并释放可重建缓存。过程构建曾无条件保留整图，增加大图常驻内存，故没有采用该版本。
- 单分区合成直接移交已有成品；全范围重采样前不再重复裁切。安装底图后及时释放移交缓冲，再安装控制层，避免大图交接期间无必要的缓冲重叠。
- 一个运行任务和一个最新待处理请求。普通反馈让在途帧完成，避免持续输入饥饿；候选取消/替换与关闭按所属版本协作取消，拒绝旧请求入队。退出不在 UI 线程 join worker。
- 公共 `CapturedRegion`/`ScreenCaptureFrame` 的 Vec 保留协议未整体迁移；原图在编辑、历史和效果采样包装间仍存在已有深拷贝，是剩余内存热点。没有声称已消除所有图片副本。

## 性能结果

### CPU 夹具

同机无编译负载顺序运行基线和交付 worker 的 CPU 夹具，每组预热一次、测量 20 次。固定非对称预乘颜色和透明像素，比较十组相同抽样校验和；独立像素验证另见下节。范围是全分辨率内容/反馈生成并返回拥有所有权的 Pixmap，**不含 UI/GPU 或桌面呈现**；主要覆盖相同内容的反馈更新，不能推广为每次文档修改均提速相同比例。

| 原图 | 倍率 | 基线中位/P95 ms | 交付中位/P95 ms | P95 变化 |
| --- | --- | --- | --- | --- |
| 1000×1000 | 1:1 | 1.16 / 1.26 | 0.42 / 0.54 | -57.7% |
| 1000×1000 | 1/2 | 14.27 / 14.78 | 6.11 / 6.16 | -58.3% |
| 2000×4000 | 1:1 | 13.08 / 13.85 | 3.31 / 3.49 | -74.8% |
| 2000×4000 | 1/2 | 116.34 / 129.61 | 51.92 / 52.30 | -59.6% |
| 4000×5000 | 1:1 | 31.74 / 33.75 | 12.77 / 13.04 | -61.4% |
| 4000×5000 | 1/2 | 322.90 / 374.08 | 139.78 / 149.15 | -60.1% |
| 5000×8000 | 1:1 | 59.84 / 60.34 | 30.82 / 32.36 | -46.4% |
| 5000×8000 | 1/2 | 617.20 / 707.03 | 651.41 / 701.67 | -0.8% |
| 600×32768 | 1:1 | 31.81 / 33.13 | 14.17 / 14.72 | -55.6% |
| 600×32768 | 1/2 | 303.06 / 308.71 | 125.67 / 132.60 | -57.0% |

20MP 半尺寸反馈 P95 降低约 60%，达到至少 20% 的完成条件；其他 CPU 场景均没有超过 10% 的退化。40MP 半尺寸行是纯算法/预览压力夹具，不能当作前端资源预算必然接受的请求。近 32768px 高度由纯 CPU 路径覆盖，不等于原生打开通过。

`delivery/cancel-quiet.log` 的 20 次纯重采样取消测量包含取消后线程退出和释放，P95 约 3.7ms，低于 100ms；不含不可中断的系统调用。证据 `cpu-delivery-comparison.json` 及基线/交付 `matrix-quiet.log`。

### 原生画面与输入

五组有效夹具（1MP、8MP、20MP、40MP、600×16000）分别重复打开/关闭 20 次。脚本保存桌面客户区截图，核对 HWND、工作区及辅助窗口身份。原生操作时间包含菜单、对话框、输入和截图等待，不把它减去固定等待后冒充渲染时间；最初基线打开批次与编译重叠，因此不据此声称原生打开的因果提速。

另在无编译负载时，基线/最终交替启动新进程各 10 次，测量首次打开 20MP 图片：基线中位/P95 为 1799.6/1857.2ms，交付为 1785.0/1852.3ms。范围从真实托盘操作到客户区截图，包含脚本/对话框开销，排除启动前置等待；**本轮没有证据证明首次打开显著提速**。

- 125%：20MP Enter 到桌面状态像素变化 369.6ms；WM_NULL 探针 92 次，P95 1.59ms，最大 18.28ms，超时 0。
- 100%：20MP Enter 到桌面状态像素变化 331.7ms；WM_NULL 探针 88 次，P95 3.90ms，最大 26.04ms，超时 0。

可见更新通过实际桌面状态栏像素变化确认，截图进一步核对完整图片与尺寸；检测有 50ms 轮询界限并包含截图开销，不是光子或 compositor 时间戳。WM_NULL 是原生消息响应探针，不等同所有鼠标/键盘动作的端到端延迟。证据 `large-pixel-comparison.json`、`delivery-large*/native/visible-resize-timing.jsonl`、`ui-message-response.json`。

## 内存、释放和预算

| 夹具 | 基线进程 PrivateBytes 中位 MiB | 交付中位 MiB | 交付范围 MiB |
| --- | --- | --- | --- |
| 1000x1000 | 76.9 | 80.4 | 75.3–81.8 |
| 2000x4000 | 293.3 | 323.3 | 322.0–326.4 |
| 4000x5000 | 670.1 | 705.6 | 660.3–890.7 |
| 5000x8000 | 1657.3 | 1734.0 | 1578.4–1734.2 |
| 600x16000 | 340.0 | 346.9 | 344.8–456.8 |

整组进程累计峰值工作集从 1925.2MiB 到 1792.7MiB。这是进程观测，受分配器、运行时及初始测量负载影响；PrivateBytes 中位值并未全面下降，**不宣称进程内存降低 20%**，也不将工作集下降当作引用释放证明。

- 32MiB 限制针对新增的可重建 CPU 内容缓存；源图、候选、已安装 Slint 数据及历史按不同所属关系保留。诊断分别记录源帧、内容、反馈字节；历史继续按唯一资源身份执行原有 20 条/512MiB 预算。
- 40MP 导入的进程占用可以超过 512MiB；历史缓存、长截图/尺寸处理缓冲预算与整个进程内存不是一个口径。本轮未放宽任何既有像素或预算常量，也未以增加拒绝范围代替优化。
- 自动化连续 20 次建立/取消预览，核对 worker 队列及源图弱引用全部释放；新缓存超过上限后正常输出且不保留缓存。候选替换、普通反馈进展和旧回调回归通过。
- Native 重复打开不累积存活编辑器；进程线程数波动而非逐轮增长。没有将分配器空闲页或两分钟工作集修剪当作源图引用释放证据；没有新增隐藏窗口。

## 遗留及未覆盖

- 修改前 Release 导入 600×32768 失败，现有证据不足以认定具体根因；保留失败日志，没有标记已修复。原生长图压力采用 600×16000；32768px 高度仅由纯 CPU 夹具覆盖，后续应独立排查原生呈现能力和交接。
- 本机构建未取得 AfterRendering 回调观测，不能把注册 notifier 当作首帧实测通过。已记录排队/CPU/安装阶段，以实际桌面像素检查补充可见性；精确 compositor、GPU 分配峰值及光子时间未测量。
- 没有诱发系统真实 OOM、穷举所有效果/主题/语言/来源的笛卡尔组合，或整体改写公共源图 Vec 所有权。原生负坐标显示器布局未改动，继续依靠已有 Core/UI 负原点回归。
- 原生可见更新与 WM_NULL 探针不是各操作的 20 次端到端百分位；性能验收的 20 次同口径百分位来自 CPU 夹具，首次打开另有每版 10 次交替进程测量。未夸大为所有操作或首次打开提速 60%。
- 验证脚本曾出现 SwitchParameter 变量同名、C# 绘图程序集引用及参考夹具路径迁移错误，均为测试工具问题，修正后重跑；过程失败未覆盖为通过。
