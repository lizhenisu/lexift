# Windows 实时窗口贴图技术验证

基线为 `5aef54b`，实施分支为 `codex/window-pin-gate`。测试代码只在 Platform 测试构建中编译。测试源、遮挡层和预览均由夹具创建，只采集合成色块与帧编号。

## 复现

在可交互 Windows 桌面、工作区足以容纳 1920×1080 源窗口时，从仓库根目录执行以下命令。双屏原点不同的机器按物理坐标调整 `LEXIFT_WINDOW_PIN_LEFTS`。

```powershell
New-Item -ItemType Directory -Force target/window-pin-gate | Out-Null
$env:LEXIFT_WINDOW_PIN_LEFTS = '0,2560'
$env:LEXIFT_WINDOW_PIN_EVIDENCE = (Resolve-Path target/window-pin-gate).Path
cargo test --release -p lexift-platform window_pin_gate -- --ignored --nocapture
```

缺省运行双屏各十轮，每轮分别测无遮挡与完全遮挡。设置 `LEXIFT_WINDOW_PIN_MODE=smoke` 可缩短为双屏各一轮。原始记录和摘要位于忽略的 `target/window-pin-gate/`，其中 `run.ps1` 可重跑并记录构建哈希。

## 实现与计量

- 独占 worker 复用现有 WGC 创建、D3D11 和局部读回。采集绑定到夹具的源 HWND，按客户区相对坐标及 DPI 计算当帧裁剪。最小化、选区越界和几何变化会使待呈现帧失效，恢复后等待新鲜帧。
- WGC 到帧通知合并唤醒。CPU 帧交接使用单槽覆盖，预览保留最后一次显示的画面。主动停止或源关闭后撤销通知和待呈现帧，worker 在所属线程关闭采集会话与帧池。夹具等待退役用于测量与断言。
- 窗口单次提交合成色块，避免在测试源逐块绘制期间采到中间态。结构化测试对整块裁剪做逐像素检查，用桌面实际像素确认预览和遮挡。动态性能按实际提交并完成 `DwmFlush` 的不同帧号统计。采集至呈现从 worker 取得帧计时，WGC 原始时间戳差值单列。桌面提交耗时与物理屏幕显示延迟分别处理。

## 最终 Release 结果

构建 SHA256 为 `69b2458cbf8befe8c41029ec7211fcdcb5f930e60985212f50b56d74e655ffc3`。两屏均通过局部像素、部分／完全遮挡、预览覆盖源窗口、移动、跨 DPI、缩放越界恢复、最小化恢复、源关闭和主动冻结检查。独立解码的冻结 PNG 分别为 1280×640 和 1600×800，RGBA 与合成参考逐像素一致。

| DPI | 无遮挡／完全遮挡最低更新率 | 首帧中位数／P95 | 恢复中位数／P95 | 停止退役中位数／P95 |
| --- | --- | --- | --- | --- |
| 100% | 29.968／29.969 fps | 224.4／237.0 ms | 33.1／68.8 ms | 29.3／31.4 ms |
| 125% | 29.968／29.965 fps | 263.5／272.4 ms | 25.7／59.2 ms | 29.4／31.6 ms |

40 组动态测量均通过 27fps 门槛。从取得 WGC 帧到预览提交及 DWM 同步的 P95，100% 屏无遮挡／完全遮挡分别为 7.19／6.35ms，125% 屏分别为 6.50／7.22ms。局部读回 P95 分别为 1.50／2.29ms、2.14／3.30ms。WGC 原始时间戳与提交时钟的差值在部分样本中为负，保留原始数据，呈现延迟采用单调的帧交付时点。CPU 帧与预览缓冲估算上界为 13.1／20.5MB，WGC 双缓冲与 staging 纹理估算为 19.9／21.7MB，测试源绘制和驱动内部资源另计。

额外 20 轮启动、冻结、取消和关闭重开通过。慢消费者触发了单槽覆盖，退役后夹具 HWND 销毁、worker 已 join、待呈现帧释放，关闭回调和到帧回调已撤销。分类采样中，后 20 轮的进程总句柄 380→400，新增项全部为 10 个 Mutant 和 10 个 Section，共用同一 GUID。该 GUID 在本轮比较的四个已加载模块中只匹配 `nvspcap64.dll`，与既有 NVIDIA 叠加层隔离结果一致。该区间 Thread、ALPC、USER 和 GDI 计数稳定。本轮保留驱动和叠加层设置。 [截图窗口资源生命周期调查](screenshot-resource-lifecycle.md)

首轮 Release 保留遮挡命中判定失败和时间戳差值，后续改用桌面像素及帧交付时钟。首次完整矩阵中，进程级 USER 计数在循环中下降，触发了要求绝对相等的断言。最终按确切 HWND、线程和待呈现帧检查所属资源，并单独记录全局计数。Platform 相关自动化 21 项、严格 Clippy、格式和 Windows Release 测试构建通过。

画面、性能和夹具所属资源门槛通过，可据此规划正式接入。受保护内容、HDR、其他显卡驱动和真实应用窗口未实测。NVIDIA 叠加层环境仍存在进程总句柄增长，正式接入时需保留该环境限制与资源观察。
