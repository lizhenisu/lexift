# 恢复上次关闭的贴图验证

基线为 `5791c6d`，实施分支为 `codex/restore-closed-pin`。用户关闭时保留最后确认的文档和物理几何，App 持有完整底图及必要采样的共享引用。旧窗口照常退役。恢复准备成功后分配新实例，沿用原图片来源并消费关闭记录。

## 自动化

Core 贴图 25 项、App 6 项、UI 贴图 16 项、托盘 11 项和 Platform 2 项已通过。覆盖关闭去重、失败重试、迟到窗口、共享像素所有权转移、锁定／穿透策略及托盘布局。托盘和贴图组件使用十二种语言、浅深主题及 100%／125% 软件渲染。通过格式检查、严格 Clippy、Slint 编译和 Windows Release 构建。

## Windows Release 实测

最终构建 SHA256 为 `7a590c0481553b1e3991000657a2efad0bde252886941d75cf0c8274c6ac5f12`。`native-dpi` 使用实际截图快捷键、鼠标、托盘菜单和系统窗口消息。100% 与 125% 屏分别创建普通截图贴图和真实滚动长截图贴图。四轮均验证原窗口退出、新 HWND、恢复前后窗口边界和内部可见像素一致，以及恢复窗口保有辅助身份且未取得前台焦点。两轮长图生成的贴图均按现有默认位置落在 125% 屏。

`native-comparison` 保留修复前的失败。100% 屏上后端在原生准备时产生了中间尺寸，旧代码随后将该尺寸作为恢复依据，导致脚本采样区从 453×294 缩至 354×228。修复后在原生准备完成时重新使用关闭时记录的物理内容尺寸，同一轮采样区恢复为 453×294。

`native-copy-item` 另外通过 Win32 读取实际菜单项矩形并点击「复制图片」。四轮均核对关闭前的剪贴板像素与参考图一致，恢复后的剪贴板 RGBA 与关闭前逐像素一致。早期仅发送方向键和 Enter 的脚本在关闭前未获得剪贴板更新，保留于 `native-copy`。

原生矩阵未覆盖显示器断开、贴图带裁剪草稿关闭和保存 PNG。迟到结果、失败保留及重试由自动化覆盖。

构建日志、原生脚本、截图与参考像素保存在忽略的 `target/restore-closed-pin/`。
