# Windows 横向长截图自动滚动验证

基线为 `f4f4296`，实施分支为 `codex/long-capture-horizontal-auto-scroll`。横向和纵向使用同一个控制条入口。横向每步发送一档原生向右滚轮，纵向继续发送一档向下滚轮。每次运行绑定确认方向和自动滚动代次，重新启动或切换方向前等待已发出的滚轮结算。拼接尾部对齐、逐步确认、稳定窗口和停止条件与纵向共用。

## 测量口径

App 记录的 `elapsed_ms` 从自动滚动 worker 接纳本代开始，包含目标获取和停留时间。`step_ms` 从系统接纳滚轮到首次有效追加，后续仍须满足 180ms 稳定条件。Chrome 夹具记录浏览器实际接收的横纵滚轮数量及可见列偏移，剪贴板和 PNG 分别独立解码并对照同一份合成列号图。

## 自动化与构建

- Core 25 项长截图测试通过，覆盖方向确认和切换竞争、代次隔离、尾部对齐、重复和历史帧、步进稳定时间、固定栏、裁剪及长度上限。App 5 项通过，覆盖过期代次、旧方向、停止后重复回调、输入失败、暂停和裁剪。Platform 通过原生输入结构断言，确认两个轴都只发送一档，方向分别为向下和向右，位移字段为零。
- UI 11 项通过。软件渲染覆盖十二语言、浅深主题、100%／125% DPI，以及横向待机、等待目标和工具条边缘布局。待机和等待时宽度稳定，切换轴使用同一宽度。`control-render.png` 保存代表性渲染。
- `cargo fmt --all --check`、`git diff --check`、相关 crate 的 `cargo clippy --locked --all-targets -- -D warnings` 和 Windows Release 构建通过。Slint 编译仍有截图尺寸输入框既有的重复可访问文本警告。本轮未改该输入框。

## 修改前后的原生证据

首个功能构建 SHA256 为 `6a44c0e0454d3edc3c333573160137e39a0bf86d599dc097f4c6bfb39f87928c`。

`output-check` 在 100% 和 125% 屏分别测试 Chrome 宽表格配置及内嵌横向滚动区，使用浏览器原生滚动行为。两屏均到达 720px 的最大滚动量后以 `Unchanged` 停止。125% 屏每轮接收 7 次横向滚轮，100% 屏每轮 9 次，纵向滚轮事件均为零。两张实际剪贴板图片和两份实际保存的 PNG 均为 1320×400，逐像素匹配参考图。保存窗口使用原生辅助窗口身份。

四轮完整输出共记录 28 次有效滚轮确认。首次有效追加为 397.33～459.21ms，单步注入至首次追加为 33.15～124.84ms，中位数 93.76ms。最后一档用于确认页面没有继续变化。

`lifecycle-verified/120-stop-button` 保留了实测的停止竞态。指针进入停止按钮时，Platform 已因离开采集目标停止，随后原点击按切换处理，启动了代次 2。按下时保存明确的开始／停止意图及代次后，`final-native/120-stop-button` 仍复现了 Win32 按下事件送达前已停止的顺序。UI 进一步使用现有物理指针查询和同一按钮的 Slint 布局，保留正被指向的停止按钮语义，直到点击完成或指针移出。Core 对过期代次及已完成的停止请求不执行新操作。

## 最终 Release

构建 SHA256 为 `ac136457fa428e1f2addbc57412ccf20cc7e24750237e2dadefea275cf7af744`。`final-r2` 在 100% 和 125% 两屏各通过九项真实输入用例。

- 两屏的短按停止和目标失效之后松手均未开始第二代自动滚动，手动续接后复制像素正确。移出选区、切换到另一个窗口及暂停均停止滚轮。切换前台时原生夹具确认另一窗口保持前台且未接收滚轮。取消后长截图窗口退役，原截图编辑器恢复，关闭后可重新开始采集。
- 滚回历史位置后启动会以 `Uncertain` 停止，目标未收到滚轮。使用 K 裁掉右侧并手动续接，125%／100% 屏的实际剪贴板分别为 850×400 和 800×400，逐像素等于对应列区间。
- 使用真实 HTML 宽表格结构和内嵌横向列表。两屏均滚到最大偏移 720px 后以 `Unchanged` 停止。剪贴板和 PNG 共四份 1320×400 成品，逐像素核对 RGBA，控制条及预览未进入结果。两屏的原生另存窗口通过辅助窗口身份检查。
- 十八轮横向用例记录 56 次有效追加。首次追加为 368.64～490.09ms，单步确认中位数 93.43ms，范围为 32.91～124.68ms。`.json` 数据保留每轮时序和实际停止原因。

`vertical-final` 在双屏各通过滚到底、移出后续接及准备超时，实测纵向剪贴板与参考行区间一致。测试未覆盖普通商用应用对原生横向滚轮的各自响应、极窄的物理工作区或达到资源上限的原生大图。布局、长度与拼接边界的自动化证据单独保留。

早期驱动曾按旧工具条偏移点击、在裁剪菜单就绪前发送 K，或过早读取剪贴板和窗口标题。首次保存脚本写到了上次使用目录，找回的 PNG 与参考图逐像素一致，已移入本专项证据。最终驱动按控件就绪与真实输出判定，保留原失败日志。

脚本、合成参考图、截图、原始阶段日志和构建哈希均存入忽略的 `target/long-capture-horizontal-auto-scroll/`。
