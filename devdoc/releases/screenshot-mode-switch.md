# Windows 截图采集内切换模式验证

基线为 `5b8b31c`。框选内可切换矩形、多窗口、多边形、选区加减及自由手绘。矩形确认后按原规则进入编辑，多区域批量保存使用独立入口。

多窗口切换只使用冻结时前后核对一致的窗口图层与真实桌面像素。普通截图回退、图层不一致或资源预算不足时保留其他模式。现有冻结画面、图层和遮罩分别由所属会话释放。

脚本、构建哈希、原始首帧测量和原生失败截图存放在 `target/screenshot-mode-switch/`。首帧定义为实际收到全部选区反馈帧，从发送截图快捷键起计时。

## 验证结果

- Core、App、UI 和 Platform 回归共 1258 项通过。新增测试覆盖过期切换、放弃确认和冻结时窗口图层变化。Slint 编译、格式、严格 Clippy 与 Windows Release 构建通过。
- Windows Release 在 100%／125% 屏分别从 Alt+S 进入，经过多窗口、多边形、选区加减、自由手绘并切回矩形。脚本检查了放弃确认及取消，确认框选 HWND 未替换，每次会话只有一次冻结采集。Debug 另观察到窗口证据不可用时，菜单只屏蔽多窗口。
- 两屏各以多边形输出验证实际剪贴板、PNG 和贴图再复制。冻结后移动了源窗口，逐像素核对原始选中颜色及轮廓外的零 RGBA。
- 每屏测量一次首次框选和九次热运行。100% 屏热运行中位数从 365.5ms 到 311.1ms，P95 从 391.2ms 到 360.4ms。125% 屏中位数从 341.7ms 到 310.7ms，P95 从 367.5ms 到 313.2ms。这是本机同口径观测。
- 本轮未单独实测跨屏轮廓输出、外部前台竞争，以及全部语言、主题和窄工作区的原生菜单。十二种语言通过编译期目录校验。
