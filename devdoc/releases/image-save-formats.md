# 图片保存格式专项验证

日期：2026-10-23。分支：`codex/image-save-formats`，基线 `d2f71c3`。未暂存、提交、合并或推送。

## 实现与修复

- 所有图片入口迁移到 `ImageSaveRequest`／`AnnotationSavePort::save_image`，显式提供 PNG／JPEG 和默认 PNG；JPEG 使用 WIC 95% 质量，预乘像素直接合成白底。
- 默认文件名移除调用方预填的格式后缀，由原生对话框补齐当前类型；不改动确认后的目标路径。事件订阅在对话框关闭时撤销。
- 原生测试发现 Windows 可把不匹配后缀追加成 `.png.jpg`：现同时校验编辑框输入及最终结果，不匹配时返回 `S_FALSE` 并显示本地化说明。修正文件名后可继续保存。
- 实测发现历史恢复编辑器的保存按钮原来仅判断桌面截图活跃状态，误入普通桌面导出且无对话框。补齐独立历史编辑器路由；最新 Release 已复测通过。
- 临时文件写入失败时先释放文件句柄再移除临时路径，避免 Windows 下因仍打开句柄而遗留文件。

## 后续修复：切换格式自动更新文件名

用户实测发现已带 `.png` 的文件名切换到 JPEG 后仍保留原后缀并出现冲突提示。原因是 `SetDefaultExtension` 只设置缺省后缀，不能替换编辑框中已有的后缀；首轮测试未核对格式切换后的真实编辑框文字。

- `OnTypeChange` 现在同步替换已知图片后缀，保留主体及目录，并清除上一条冲突提示；加入重入保护，更新发生在原生对话框内、覆盖确认之前。未知后缀仍保留校验，文件确认后不改路径。
- 新增大小写、中文、多点文件名、Windows 路径及 JPEG 别名的纯函数回归，隐藏原生对话框验证 `.png → .jpg → .png`。保存专项 8 项通过、2 项默认忽略；`type-switch-platform.log`。
- 单独测试二进制的原生 Port 验证双向改名、手工输入冲突、无后缀补齐、拒绝覆盖及重试；`type-switch-port.log`、`port-113206/`。读取真实编辑框使用 `WM_GETTEXT`，不把跨进程 `GetWindowText` 的空返回值当作文件名。
- 最新 Windows Release SHA-256：`99A73804CF62654E4738B88B959A05C889CB6F508276A11FE7B36CFF0D352A2C`。产物为 `target/release/lexift.exe`，实测副本 `target/image-save-formats/type-switch.exe`。
- 最新 Release 在 125%／100% 双屏实测 `.PNG → .jpg → .png → .jpg`、重复切换、手工输入 `.JPEG` 后切换 PNG，以及切换后取消。4 份实际输出均为 160×120，经 Pillow 独立解码并核对已知绿色像素；PNG 精确一致、JPEG 全图误差不超过 3。实际对话框切换前后截图及结果在 `switch-37808/`，汇总为 `type-switch-verification.json`。
- Platform 全目标 Clippy、格式检查及最新 Windows Release 构建通过。此次只修改原生对话框文件名同步，未重复首轮的全部长图、历史和标注组合；首轮 C4B953… 的 20 份输出证据仍单独保留，不冒充此次最新二进制实测。
