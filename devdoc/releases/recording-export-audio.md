# Windows 录屏成品声音验证

基线为 `main 9804b16`，实施分支为 `codex/recording-export-audio`。测试证据留在忽略的 `target/recording-export-audio/`。

预览的成品声音请求与画面定位代次独立。导出档位在保存请求中冻结，试听静音由播放器保留。半音量在裁切和保音高变速之后、AAC 输入量化时按 0.5 增益写入。移除音轨时不接纳音频流。两种声音修改均沿用现有 MP4 转码及原子发布，完整范围 1× 原声沿用原样复制。

录屏相关 Core 回归 44 项通过。原生合成夹具覆盖 30fps／1.5×、60fps／2×、首尾与画面裁剪。独立解码逐帧核对范围和帧号。半音量导出与原声导出的左右声道 RMS 比值约为 0.50，WASAPI 试听回环比值亦约为 0.50。移除音轨的 MP4 只有视频流，试听回环无测试声。详细数值见 `verified.json`。


使用十分钟脉冲与闪光夹具复核半音量、2× 和两种裁剪同时生效的结果。独立解码得到 8993 帧，三组音画偏差均约 7ms。回环及音量对照使用受控合成声源，未测真实声学链路。

## 最终 Release 窗口验收

最终 Windows Release SHA-256 为 `d311e57c7435e788eadab086b782a83c32044e4ea6634af93cfecf3aa0c2cfbd`。工作区回归、修正后的录屏 UI 回归、Slint 编译、格式及严格 Clippy 通过。菜单点选与键盘确认由组件测试覆盖，并渲染十二种语言、浅深主题、两种 DPI 和窄窗口。最初菜单说明与按钮边缘重叠，调整布局后复看最终渲染。

- 125% 屏真实录制后，在播放中切换到半音量并恢复原声，再选择半音量。组合首尾、画面裁剪及 1.5×，取消保存后重试，MP4 独立解码为 1056×594、28 帧，含 AAC 音轨。
- 100% 屏在播放中选择移除音轨，验证恢复及再次移除。60fps、2× 和两种裁剪组合输出 1056×594、41 帧，容器仅有视频流。取消和重试通过。
- 带声音源选择半音量后导出 GIF，独立解码为 960×540、14 帧，无音轨。默认原声、完整范围、完整画面和 1× 的 MP4 与封尾原件 SHA-256 一致。

脚本、时序、成品与哈希见 `ui-final/`。界面操作见[录屏成品声音](../features/screenshot-mode.md#录屏成品声音)。
