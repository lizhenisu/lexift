## 实现与失败收尾

- 现有截图状态机增加挂起、采集、呈现、App 提交及回退阶段；会话、操作号、底图版本和原窗口实例隔离结果。两屏完整反馈与 App 底图提交完成后才解除忙碌。
- App 保留最初桌面标注快照，刷新只调用一次新鲜像素采集，不枚举窗口或查询 UIA；原桌面标注按原快照合成一次，截图新增标注保留在文档中。
- 选区、比例、工具、对象、撤销／重做及工具条位置不重建；旧完整反馈通过移动所有权保留，供候选失败回退。正常贴图临时显像且保持输入挂起，用户隐藏贴图保持隐藏。图片历史窗口及通知在刷新阶段退役，期间不能重新打开。
- 刷新不进入撤销栈、不更新图片历史或 R。失败恢复旧帧后才显示三秒被动提示；其他输出失败沿用原有提示和重试行为。
- 若原生窗口自身已不可用，连旧画面也无法恢复，则终止所属截图并恢复此前状态，避免永久忙碌。此为不可恢复的窗口故障收尾，不把它描述为成功回退。

## 验证发现及修正

1. `Host::show` 只接受首次准备完成的宿主。刷新改为重新显示同一已准备窗口，保留实例和输入租约。
2. 原生编辑画布仍可能保留初始 bootstrap；不能用初次框选的完成标记确认刷新。刷新只对所属 HWND 关闭显隐过渡，在隐藏后退役 bootstrap，显示后安装同一版本的完整反馈，再进行一次组 DWM 同步。
3. 早期原生读回曾出现一个颜色通道相差 1，C 采样已经是新值。原失败截图和日志保留，未用固定等待或误差阈值判为通过。软件反馈的已知 RGBA／Alpha 回归及独立原生分层窗口对照均精确一致；对 Slint 重新显示后的 surface 再安装完整反馈，并补齐实际 DPI 的取色／尺寸资源准备后，最终两屏 20 轮均通过精确像素对照。没有把最初的显隐过渡猜测写成已证实的唯一根因。
4. 保留贴图组合中，C 曾到达所属键盘入口但取色反馈未就绪。现在安装候选前按每个画布实际 DPI／主题准备既有取色及尺寸资源；最终 Release 的可见、隐藏贴图及跨屏 C 均通过。键盘诊断只记身份、阶段、位置及布尔门禁，不记识别或图片正文。
5. 为新增刷新阶段补上图片历史的忙碌与通知清理；迟到回调先校验身份，再操作贴图或画布，避免影响新截图。

早期 `native-probe.log`、`native-final.log`、`native-verified.log` 等保留失败过程；最终通过证据为 `final-release-native.log` 和 `final-release/`。保存后立即发起下一次截图的脚本曾读到瞬时空前台，已改为按实际前台就绪判断；没有强制激活或补点截图画布。

## 最终 Release 原生验收

监视器物理范围为 `(0,0)-(2560,1440)`（125%）及 `(2560,0)-(4480,1080)`（100%）。使用合成颜色、文字及矩形夹具，真实 Alt+S、R、鼠标、托盘和原生保存对话框操作；没有脚本强制激活截图画布。

| 场景 | 结果 |
| --- | --- |
| 每屏连续 10 次，累计 20 次刷新 | 两屏画布均显示；工具条 HWND／位置保留；每次实际桌面内部 40×24px 区间逐像素等于新颜色，C 也读到同一版本 |
| 复制及原生保存 PNG | 两屏均为 320×240；独立读取实际剪贴板／PNG，全像素等于夹具，无边框、控制点、工具条混入 |
| R、刷新后取消、退出重开 | 使用当前冻结帧，既有区域继续可用；输出后原画布／工具条 HWND 确认销毁 |
| 可见贴图与用户隐藏贴图，两种 DPI | 可见贴图参与新底图及实际输出；隐藏贴图不出现，输出后仍隐藏，须托盘手动恢复 |
| 真实 OCR | 将 `INITIAL 1111` 改成 `REFRESH 2468` 后刷新，实际剪贴板为新文字；识别关闭截图，未用假 OCR Port 替代 |
| 跨 125%／100% 边界的选区 | 两侧 C 为同一新颜色；实际 320×240 输出全像素一致 |
| 刷新隐藏期间点击外部窗口 | 通过 HWND 可见性观察真实隐藏区间后点击另一进程的夹具窗口；完成后保持外部前台，外部 Escape 不退出截图 |
| 桌面原标注、新增截图标注与重做 | 原标注保留于新底图；刷新前撤销的新标注可重做；再次撤销／重做不会还原旧底图，实际输出包含两类应保留内容 |
| 辅助窗口身份 | 实际画布／工具条扩展样式保持 ToolWindow、非 AppWindow；复用原有无边框和一次激活保护 |

证据包括 `final-release/rounds.jsonl`、`keyboard-receivers.jsonl`、`window-events.json`、实际 PNG／剪贴板成品、桌面关键帧、OCR 已知文字结果和构建哈希。顶部无白条及聚焦无需补点的既有相关原生回归同时通过；没有据此宣称全部硬件组合均已覆盖。

## 耗时与资源

最终构建共记录 32 次刷新（包含基本 20 轮和组合场景）。计时以单调时钟的所属阶段日志为主；请求视图阶段发布到完成用相应日志时间关联，不冒充硬件按键到显示的全链路延迟，也不把脚本固定等待计入产品性能。

| 阶段 | 中位数 | P95 |
| --- | ---: | ---: |
| 刷新阶段发布 → 完成 | 228.4ms | 256.2ms |
| 隐藏确认 → 完成 | 216.8ms | 236.3ms |
| 新鲜像素采集（本机均命中 GDI 快路径） | 60.5ms | 74ms |
| 原桌面标注合成 | 4ms | 5ms |
| 后台准备合计，含端口及布局检查 | 97ms | 112ms |

总阶段最大 263ms；统计包含带原桌面标注的组合场景。完整交接仍包含反馈生成、安装、显示同步及激活，不用采集完成代替画面完成。原始摘要见 `final-summary.json`、`final-refresh-timing.log`。

本机 5,760,000 物理像素按十四份 RGBA 表面预留 **322,560,000B（307.6MiB）**，涵盖旧帧、候选、软件缓存、反馈、原生上传及回退重叠；保持原 40MP 及 512MiB 预算拒绝规则。这是保守的像素表面预算估计，不是对全部运行时分配的逐项实测。

外部进程采样得到 PrivateBytes 峰值 **418.8MiB**、工作集峰值 **478.5MiB**，含 OCR 模型、历史和窗口资源，不能与像素预算混为一谈。循环就绪后的 PrivateBytes 在两屏各自区间内仅波动约 0.1MiB，没有随刷新轮数持续增长；结束时约 178.6MiB。采样是离散观测峰值，不保证捕获所有瞬时分配。保留引用由各所属资源释放，未用工作集修剪代替清理。

## 尚未实机覆盖

- 刷新期间拔插显示器、修改实际 DPI、负坐标显示器布局：纯状态／几何／前后布局校验已覆盖，本机没有改动用户显示配置来制造这些场景。
- WGC 回退、原生采集／呈现故障注入：沿用既有适配及回归，候选失败和取消由可控测试验证，本次 32 次实际采集全部为 GDI；不把快路径成功说成回退实测。
- 保留贴图的每一种透明度／方向／置顶组合、全部标注效果及字体交错、硬件 HDR 色彩管理和实际 Alt+Tab 枚举未逐项穷尽。现有相关回归通过，新增逻辑没有改动其文档或像素处理顺序。
- JPEG 本轮没有重新逐项操作原生类型选择；保存共用已验证的确认底图，既有编码回归通过。尺寸草稿／比例锁定及取消发生于每个原生阶段的全部竞态未穷举，不能把 Core／UI 自动化说成全面原生故障验收。
