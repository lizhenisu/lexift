# 贴图透明度验证

日期：2026-10-25。基线：`main/fa0d21e`；工作分支：`codex/pin-opacity`。本轮不提交、合并或推送。

## 实现与问题修正

- Core 的实例交互策略增加受限五档透明度，复用请求、确认和失败回退；锁定、穿透及批量恢复使用同一策略并保留其他字段。
- 普通与编辑显示共用单份内容纹理，底图、标注和既有背景一起衰减。控制点、裁剪反馈和外部文字输入保持原显示。透明背景在既有上传缓冲内合成，不修改保留资源；切换透明度只改属性。
- 原阴影蒙版中心不透明，在低透明度时会挡住桌面；改为中心挖空的既有九宫格蒙版，保留外侧光晕。
- 原穿透快照直接提交 Slint 的直通 RGBA，低透明度下混色错误；抽取已有提示窗口的预乘转换，共用原地转换后再提交 Windows 分层呈现。自动化对照直接软件渲染和原生快照的预乘像素。
- 编辑空闲时临时禁用整个 HWND 会丢失输入焦点；策略等待由组件屏蔽，原生输入保留所属编辑窗口的上下文能力。绘制、裁剪、OCR 等既有互斥规则继续生效。

## 自动化与组件覆盖

Core 覆盖默认五档、非法数值、每实例隔离、无变化请求、失败、穿透恢复及关闭后的旧完成。UI 覆盖实际策略桥接失败、旧回调、编辑输入能力、文档／历史保持及输出仍携带原标注。

组件使用软件渲染，覆盖浅／深主题 × 100%／125% × 不透明／半透明内容 × 普通／编辑 × 五档，共 80 组。检查内容统一衰减、控制点保持不透明、阴影不随档位衰减、快照正确预乘。检查十二语言菜单与百分比翻译；德语、法语保留百分号前空格。

组件证据：`target/pin-opacity/render/`、`target/pin-opacity/render-contact.png`。原生脚本与像素夹具放在 `target/pin-opacity/`，不进入版本管理。

本轮回归：Core 239、UI 501、Platform 216、App 76 通过，共 1032 项；UI 11、Platform 99、App 1 项原有专项原生测试未在常规测试入口运行，不能计为本轮通过。严格 Clippy 覆盖 Core／UI／App／Platform 的全部 target；Slint 随 UI 编译通过，格式及 `git diff --check` 通过。日志为 `target/pin-opacity-tests-final.log`、`target/pin-opacity-app-tests-final.log`、`target/pin-opacity-clippy-final.log`。

## 验证中的修正与边界

- 开发期检查发现穿透 Alpha 格式问题和阴影中心遮挡，均修复后重新构建并用最终 Release 复测。
- 原生脚本最初固定取样坐标，在 DPI 改变后落进阴影；改为按实际内容范围取样。扩大背景夹具时曾遮住工具条，改为先移动工具条再启动夹具；跨屏拖动等待鼠标按下事件处理后再移动。脚本修正不改变产品输入逻辑。
- 截图框选中打开托盘后，下层置顶夹具可能接收其覆盖处的右键；本轮从未被夹具覆盖的画布位置右键取消，未使用强制激活。该现有跨应用置顶／托盘交互未纳入透明度改动，不代表任意外部置顶窗口组合均已验证。
- 十二语言通过目录和组件国际化检查；原生菜单实测为简体中文，未逐一切换十二种系统菜单。浅深主题和两种 DPI 有 80 组组件渲染；原生本轮为浅色与默认软件后端，未单独切换硬件渲染器。
- 失败和乱序由可控回调自动化覆盖，未人为诱发系统窗口配置失败。本轮原生保存重点为 PNG；JPEG 沿用现有编码回归，未额外重复 JPEG 对话框实机保存。工作区变化、所有效果工具和不同显卡组合未穷尽。
