# Windows 贴图管理窗口验证

基线为 `main f2c1a88`，实施分支为 `codex/pin-manager`。托盘入口和单张操作见[贴图使用说明](../features/pin-interaction.md)。

## 自动化

- Core 验证图片与文字编号相同时仍能独立操作，单张显隐与全局批次互斥，失败可重试，旧回调不覆盖新状态。实时贴图冻结后保留列表位置。桌面采集和退出使管理窗口及定位请求退役。
- 软件渲染覆盖鼠标选中、方向键、关闭确认和 Escape。生成 192 张布局快照，包含十二种语言、浅深主题、100% 与 125% 缩放、宽窄窗及确认面板开关。
- Core 390、App 90、UI 561、Platform 239 项通过，共 1280 项。格式、严格 Clippy、Slint 编译和 Windows Release 构建通过。Slint 仍报告原有截图尺寸输入的可访问名称提示。

## 原生验证记录

- 最终 Release 从实际 Explorer 通知区域打开管理窗口。混合图片、文字和实时窗口贴图时，验证单张显隐、单张穿透恢复、实时关闭确认与 Escape 取消，以及普通图片关闭后从托盘恢复。
- 管理窗口从 125% 屏拖到 100% 屏并缩窄，方向键仍可选择。定位边框与目标贴图的 DPI 和物理位置一致，接受捕获排除，保持前台窗口不变，计时后销毁。按 Alt+S 时管理窗口与边框退役，框选窗口获得焦点。取消截图后贴图恢复。
- 两个 DPI 各启动一次实时贴图。第二次通过关闭合成源窗口触发冻结，管理窗口保持原选中项。同一 HWND 可以隐藏、恢复，随后以普通贴图关闭。
- 初次脚本失败保留在原证据目录。通知区自动隐藏时，改用 Win+B 唤出通知区并匹配实际注册图标的无障碍范围。随后复现关闭确认弹出后 Escape 未退出确认。管理窗口现在允许用户点击后获得焦点，进入及退出确认时将键盘焦点交回列表。
- `native-interactive-pilot` 记录了通过 Alt+S 启动截图时的一次前台交接失败。管理窗口在快捷键上下文冻结前被销毁，框选仍持有已经失效的前台窗口身份。Core 现在先暂停管理操作，待截图进入准备阶段再退役管理窗口。截图继续使用原有的前台校验，管理窗口和定位边框在采集前退役。
- 两次 Debug 尝试在管理窗口打开前触发普通贴图路径的 Slint 软件渲染缓冲断言。原始证据见 `native-diagnostics.log`，原因未归因。另一次默认渲染器的 Debug 运行完成管理链路，最终 Release 使用默认渲染器完成上述实测。Femtovg 诊断运行停在上游框选交接，未覆盖管理窗口。十二语言和浅深主题通过软件布局渲染覆盖，未逐项切换原生系统环境。
- 应用退出码单列。最终 Release 在普通图片和文字贴图并存时，从托盘退出记录了 `Lexift stopped`，进程返回 `0xC0000409`。从未打开管理窗、打开后关闭管理窗、保留管理窗三组均复现相同退出码，原因尚未归因。见 `native-exit-*/exit.json`。管理窗口的主动关闭和截图前退役已独立验证。
- 最终 Release SHA256 为 `60748e26329a445a6f53e3d1cf2b9a42ddd668a2a62d7cdf1ef7cad823f7f6a9`，结果见 `native-release-verified/result.json`。
- 脚本、合成夹具、原始日志、布局截图及构建哈希保存在忽略的 `target/pin-manager/`。
