# 贴图编辑裁剪验证

日期：2026-10-21。实现分支：`codex/pin-image-crop`，基于 `main` 的 `d572948`。实现及验证完成后，按用户明确授权提交并快进合入本地 `main`；不推送。

## 实现范围

- 复用 Core 整数裁剪几何、同一文档历史及共享 Slint 四侧遮罩／控制点组件。工具条提供临时尺寸、取消和应用组，无独立裁剪窗口，无新文案、依赖或 Port。
- 显式保留完整可编辑底图、当前确认范围和显示像素。长图来源保留完整原图及原历史；普通截图不会把额外效果采样范围当作可编辑图像。
- UI 保留草稿和窗口几何；Core 管理候选请求、取消、渲染完成与呈现确认，App 后台合成。候选合成与窗口几何成功后才提交历史，取消和失败不修改确认文档。
- 裁剪范围变化立即使排队中的旧预览失效。回调按贴图、编辑操作、请求及呈现版本匹配；旧编辑结束不会取消新贴图的草稿。
- 隐藏标注仍裁切底图；完整合成后裁切，保留原始 DPI 分区、水印锚点和效果采样。视图缩放不改变输出尺寸，不修改 R 记录。

## 实测发现并修复

1. 跨 DPI 后，取消裁剪将一个 **299px** 高的原窗口反算成 **298px**。恢复同一范围时改用保存的两个原生尺寸，避免重复宽高取整；工作区不足时继续按既有适应和夹紧规则处理。失败证据保留于 `before-rounding-fix/`。
2. 保留精确尺寸后，发现填充图像的实际宽高比例可能因系统独立取整略有不同；按宽度比例推算 Y 坐标会将预期 **1400** 行裁剪为 **1401** 行。裁剪、普通绘制和文字正反定位改为按实际显示范围分别转换两个轴，物理缩放及效果参数仍保持原有源像素定义。失败证据保留于 `before-axis-fix/`；最终 Release 两屏输出切片及跨屏恢复均重新通过。

## 覆盖边界

- 原生实测为当前 Windows 的 100%／125% 两屏、浅色中文及自建夹具；其余语言和深色主题由组件渲染覆盖，不宣称全部原生操作。
- 负坐标、最小 1×1、八方向及越界几何由既有 Core 裁剪回归覆盖；本轮未更改显示器布局制造负坐标原生夹具，未穷尽极小窗口、裁剪期间工作区变化和最大 32 百万像素源图。
- 模糊、马赛克与放大镜通过真实合成像素回归；文字、水印和擦除的通用回归通过，但未穷尽所有参数在贴图裁剪后跨 DPI 的原生组合。未实测非 Windows 后端。
- 自动化日志位于 `target/pin-crop-*.log`；脚本、夹具、原生窗口位置、DPI、截图和输出均在忽略的 `target/pin-image-crop/`。功能说明见[截图与贴图](../features/screenshot-mode.md#贴图编辑裁剪)，历史规则见[标注历史](../annotation/annotation-history.md)。
