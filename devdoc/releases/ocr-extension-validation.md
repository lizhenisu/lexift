## 状态与资源生命周期

- 默认 `ocr_korean_auto=false`；旧配置缺失字段关闭，定向保存、失败回滚独立于其他草稿。
- Core 覆盖基础可用且无韩文时的默认请求、手动韩文及扩展自动模式的下载前置、冻结策略、取消与过期资源结果。
- 真实 ONNX 测试断言默认路径不加载韩文；开启扩展后加载，释放韩文保留基础 reader，释放全部后首次检查重新校验。
- 同一会话完整校验次数断言为一次；文件元数据变更及释放使缓存失效。本机单次完整检查约 1,008 ms，命中约 0.95 ms；该数据仅为本次文件系统和缓存条件。
- 真实 DLL 占用测试验证基础删除进入待重启状态；下一进程启动在加载 DLL 前清理完成。

## 批量与识别

资源构建脚本验证两个识别模型 batch 1/2/4、动态宽度与 CTC 字典维度。实际推理发现不同归一化宽度的填充会改变少量正文，因此最终只合并同宽度行，最多四行。按宽度处理后按原坐标还原顺序；多行输出预算 8 MiB，长行继续单行。

真实 batch 回归对两种识别模型的前 16 张验收图片比较同图单行与四行输出，并比较十行截图单行／分组的完整正文和顺序，均相同。基础模型人工模式覆盖现有 12 种语言；开启扩展的既有独立混合文字验收集通过。正文和图片不进入日志，识别质量边界仍见 [自动检测验证](ocr-auto-validation.md)。

## 性能测量边界

旧双候选基线保留修改前的测试二进制；相同 CPU、图片和两个推理线程，对比默认基础路径。每图热启动重复十次，Windows 进程 API 读取 CPU 时间、PrivateBytes 和峰值工作集。冷启动从创建推理 Engine 到完成正文，不包含资源校验、屏幕框选或翻译；资源校验另计。测试为开发构建，不能视为 Release 延迟保证；不将进程峰值工作集等同于峰值 PrivateBytes。

最终独立进程样本与阶段数据记录在 `performance-*.json`；资源检查另见 `verification.json`。基线未记录独立阶段 CPU 时间，因而该项目只报告新路径观测，不补造旧值。不同图片的冷启动均包含首次模型加载；缓存后的检测、识别、后处理分别记录。

| 样本 | 旧冷／热 ms | 新冷／热 ms | 热 CPU ms | 峰值工作集旧／新 MiB | 驻留 PrivateBytes 旧／新 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
