# Windows 录屏成品变速验证

基线为 `main 27938a8`，实施分支为 `codex/recording-speed`。原生夹具、视频、音频回环对照及日志位于忽略的 `target/recording-speed/`。

- 原媒体帧序号驱动首尾裁剪、预览定位和末帧。MP4 输出使用源帧率和绝对帧时间，GIF 使用变速后的 15fps 采样及百分之一秒时间表。
- MP4 的音频先裁成源 PCM 区间，再用波形相似重叠相加做保音高压缩。工作区保留一个采样包和 WSOLA 的有界前视，音频和视频沿用 8MiB／64MiB 预算。原样保存及取消仍沿用原生原子发布链路。
- 纯测试通过 43 项录屏相关用例，包含倍率帧序号、单帧、60 秒 GIF 边界和过期倍率确认。
- 十分钟合成夹具用 2× 和两种裁剪导出，独立解码 8993 帧。原录像三个闪光和脉冲的差值为 5／12／12ms，导出为 7／7／7ms，首尾变化小于 1ms。转码及封尾用时约 23.5 秒。短窗 RMS 检查最初把拍频误报为多个脉冲，修正重触发检测后对同一文件复核。原结果保存在 `long-detector-initial.log`，时间对照在 `long-sync.json`。

## 原生预览和编码

`gate.py` 以 30／60fps 各测试 1.5×、2×。每次使用非关键帧起点和画面裁剪，独立解码 MP4／GIF，逐帧核对编号和输出边界。两声道原频率为 440／660Hz，MP4 解码和 Windows 回环试听的检测值约为 440.37／657.53Hz。有效出声时长与理论值相差小于 50ms。详见 `verified.json`。

60fps 2× 首次测试将提交播放至末帧定位完成的总时长与理论媒体长度比较，受到播放启动和末帧定位影响。保留 `60-2-preview-first.log`，分别测量后实际出声约 720ms，理论约 717ms，起播至末帧就绪仍单独记录。

## 最终 Release 与窗口验收

- 工作区回归、Slint 编译、格式、严格 Clippy 和 Windows Release 构建通过。最终 `lexift.exe` SHA-256 为 `91b2621df44bd2228d2eae94be89e553cf9b8935ff784c154cdb8faa18032814`。
- 最初的 Slint 弹层可见但点击未触发选择。实机日志与软件渲染组件测试均复现。改为停留在现有预览窗口控制区的菜单层，点击回归通过。保留 `ui-final/`、`ui-retry/` 与 `ui-menu-test-2.log`，最终组件渲染见 `render-final/`，覆盖十二语言、浅深主题与 100%／125%。
- 最终 Release 在 125% 屏从真实控制区选择 1.5×，有声 MP4 保存为 1056×594。仅画面裁剪保留的 63 帧导出 42 帧，增加首尾裁剪后 41 帧导出 28 帧。在 100% 屏选择 2×，GIF 为 960×540，两轮分别导出 16 帧和 11 帧。组合轮在变速后执行定位再播放，成品均独立完整解码。
- 原生保存取消后保留倍率和裁剪，等待保存会话退役后重试成功。完整范围 1× 的 MP4 与原封尾文件 SHA-256 一致。原生脚本通过真实点击和 Core 接纳日志验证倍率，UIA 探针仅读到原生视频子窗口，未作为控件通过标准。双屏证据见 `ui-menu/` 与 `ui-combined/`。
- 60fps 的单帧选段在 2× 下独立解码为一帧 H.264 和一帧 GIF，尺寸均为 80×64。容器检查确认所有四组 MP4 保留源帧率及 AAC 48kHz 双声道，GIF 循环扩展为无限循环。见 `one-60-*.log` 和 `container-check.json`。

声音验证使用合成双声道和真实 WASAPI 回环。未使用真实语音进行主观听感评估，也未覆盖外部设备的声学同步。
