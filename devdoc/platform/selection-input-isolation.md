# 划词工具条输入隔离

## 2026-10-07 选区避让

工具条不再只按松开点加固定偏移。被动 UIA 取词同时读取同一 TextPattern range 的矩形，保留多行／多段边界；坐标向外取整，拒绝非有限、空和溢出矩形。超过 256 个矩形后使用整体边界。SAFEARRAY 通过 RAII 解锁和释放，任一范围的边界读取失败或格式不可靠时使用起止点回退，成功读取的文本不受影响。Alt+X 不额外读取矩形。

Core 的 Selection 增加物理坐标矩形和可选划词起点；手势完成事件、命令及 App 接线携带起止点。低级鼠标回调没有增加查询，原分发线程已有的按下点被直接传递。

UI 在松开点所在屏幕工作区内，按下方、上方、左侧、右侧优先级选择完整位置；同方向选择距松开点最近的候选。逐个避让选区，保留 8 个逻辑像素间距及工作区边距。扫描障碍边缘上的水平空闲区，避免三重候选网格；所有最终位置再次检查交叠。边界缺失时使用起止点矩形，双击／近点上下额外预留 24 个逻辑像素；该估计不能保证避开未知的多行文字。无完整空闲位置或工作区不可用时本次不显示。

准备过程保持隐藏，位置、尺寸和 DPI 连续两轮一致后才首次显示，跨屏 DPI 变化使前一轮失效。准备与稳定检查共用实例计时器和最多 20 次尝试；不轮询 UIA 选区。复制、翻译、渐隐、原目标校验及不激活策略保持不变。

### 验证记录

- 定位测试覆盖四向、多行、不连续选区、屏幕四边、100%／125%、负坐标、跨屏边界、双击回退、无可用空间；独立断言完整窗口及选区间距。
- Platform 测试覆盖向外取整、逐行保留、256 项边界、超限合并及无效输入；既有手势测试同时检查原始起点和终点。
- UI 回归在隐藏准备中改变 DPI，断言旧位置从未显示，稳定后仅显示一次；无空闲空间从未显示。保留旧实例、旧回调及准备失败回归。
- Debug 实机：Chrome 单行反向划词分别在 125%／100% 屏幕通过；Chrome／125% 和 Edge／100% 完成右下向左上的多行划词，实际窗口与夹具选区无交叠。截图同时显示选区和完整工具条。
- 上述实机均先放图片、再启动软件；工具条出现后图片格式及 sequence 未变化，Ctrl+C／X／Z／A／V 和原生工具条复制通过。多行夹具首次剪切断言因剪贴板 CRLF 和文本框 LF 长度差异失败；统一换行计数后通过，不将该夹具错误归因于应用快捷键。
- 最终 Windows Release 在 Chrome／125% 与 Edge／100% 复测反向多行划词、选区避让、图片剪贴板及上述快捷键通过。Workspace 测试 661 通过、95 忽略、0 失败；Workspace 构建（含 Slint）、全 Workspace Clippy、格式检查及 Windows Release 构建通过。
- 浏览器使用独立用户目录、本地自建输入页和强制可访问性参数。未实机覆盖 Word、VS Code、默认可访问性配置的完整浏览器矩阵、跨屏选区、负坐标、双击及极小工作区；这些场景中已有自动化覆盖的部分不等同于实机结果。没有用高速录屏证明首帧，仅由 UI 准备顺序测试和最终截图验证。

本轮构建、检查及截图保存在忽略的 `target/selection-avoidance-*`、`target/selection-*-toolbar-visible.png`，不纳入提交。

## 2026-10-07 修复范围

用户报告：鼠标划词、工具条出现后 Ctrl+C／Ctrl+X 无响应，点击工具条复制后恢复。补充顺序是先在剪贴板放图片，再启动软件，再划词并按 Ctrl+C。

本轮未稳定复现“快捷键完全失效”，不能认定已经证明用户现场的唯一根因。但确认了两个被动窗口准备缺陷：

1. 原路径在 HWND 未就绪时用 `show()`／`hide()` 准备窗口，早于不激活样式和指针接线，存在激活未配置窗口的风险。
2. Winit 显示或修改窗口属性时重新构造扩展样式，覆盖 `WS_EX_NOACTIVATE`。实际工具条显示后的扩展样式原为 `0x40118`，修复后为 `0x8040198`。该对比证明样式保护缺陷，不等于证明实际焦点转移。

没有发现鼠标被动取词注入 Ctrl+C，也没有修改全局鼠标钩子或转发键盘快捷键。

## 实现边界

- UI 的 `selection_toolbar.rs` 独立管理准备、显示、关闭、渐隐和指针转发。实例持有准备及延迟事件计时器，关闭时停止并清空。
- HWND 隐藏准备，最多 20 次重试、间隔 16ms；被动样式和指针子类成功后才首次显示。准备失败不显示窗口。
- 原生子类在 `WM_STYLECHANGING` 阶段保留被动窗口策略。主动交互窗口先切换子类策略，再设置交互样式，避免锁定文字编辑窗口。不事后强行恢复前台窗口。
- Core 请求携带原前台 HWND、焦点 HWND、进程及线程身份。Platform 在 UIA 读取前后校验；UI 在准备、显示、操作和渐隐时再次校验。失效请求和旧窗口不得操作重开的工具条。
- 原生／Slint 回调排队后转发 Core，避免持有注册表借用期间同步重入；同时检查实例、generation 和原目标。
- 鼠标取词继续只读 UIA，不操作剪贴板、不生成键盘输入。显式复制才写剪贴板；Alt+X 的原有剪贴板回退独立保留。
- 日志只记录策略、结果和单次耗时，不记录用户选中文字或剪贴板内容，不逐鼠标事件输出。

## 自动化验证

- Core：原目标在读取前／读取中变化时丢弃结果，全部身份字段参与校验；旧 generation 不恢复旧工具条。
- UI：Pending 从不显示；交互接线先于首次显示；准备耗尽后销毁；保留的旧组件和排队复制／翻译回调不能操作新实例。
- Windows：隐藏原生窗口模拟后端多次重写扩展样式，断言被动样式保留；切换主动交互后允许移除不激活标志。全过程保持隐藏且实际前台不变。
- `cargo test --workspace`：654 通过、95 忽略、0 失败。需专门实机环境或人工选区的忽略项不作为本轮通过项。
- Workspace 构建、Slint 构建检查、`cargo clippy --workspace --all-targets -- -D warnings` 及 Windows Release 构建均通过。

## 图片在启动前的实机顺序

WinForms 夹具先放入已知位图，再启动 Debug Lexift；Chrome／Edge 使用隔离用户目录、本地已知文本输入页及 `--force-renderer-accessibility`。先断言工具条实际显示、浏览器仍为前台、剪贴板 sequence 与图片格式未变化，然后执行快捷键。强制可访问性参数只用于测试，生产软件没有添加此参数；未开启该参数的完整浏览器矩阵未在本轮重验。

Edge／100% 首次运行 UIA 未取得 TextPattern／选区，工具条未出现，不能计为快捷键通过；相同夹具重试后通过。首次 UIA 可用性仍是兼容性边界。原版受控 WinForms 测试中 Ctrl+C／X 也通过，不能把修复后的通过当作已复现原故障的前后对照。

Windows Release 构建另在 Chrome／125% 重跑相同顺序，图片未被被动取词改动，Ctrl+C／X／Z／A／V 及工具条复制通过；首次操作前截图为 `target/selection-chrome-125-toolbar-visible.png`。

复制测试重新解析当前 HWND，并确认点击位置属于 Lexift，避免使用已销毁／复用的 HWND。记录实际 `GetForegroundWindow`、`GetGUIThreadInfo` 的 active／focus／capture 及 Ctrl 状态。WinEvent 的事件 HWND 有时指向工具条，而实际前台仍为浏览器，不能只凭事件 HWND 宣称抢焦点。

日志及截图在忽略的 `target/selection-*`，只含自建夹具内容。未记录用户剪贴板正文。本轮未实机重验 Word、VS Code、记事本、网页正文、双击选词及 Alt+X 人工剪贴板竞争矩阵；原有记录不等同于本轮结果。负坐标、极限关闭重开和应用退出仍需针对性实机覆盖，不宣称全部验收完成。
