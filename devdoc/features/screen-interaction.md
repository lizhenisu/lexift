# 共用屏幕交互宿主

## 边界

`lexift-ui::screen_interaction` 管理屏幕视图实例、物理范围、创建／准备／显示／呈现／退休阶段、输入队列和可取消定位任务。标注 `CanvasLayer` 与 OCR 遮罩分别持有 `Host<C>`，没有共享同一个 HWND，也没有合并业务 Registry。

标注对象、参数、撤销、编辑焦点、GPU 呈现器及连续采集仍归标注；OCR 资源、识别和翻译仍归现有 Core／App 路径。公共宿主不判断 Escape 应结束编辑还是关闭会话，调用方保留这个决定。

## 创建与呈现

- App 注入创建作用域。Slint 构造适配器时，Platform 的 Winit 属性钩子捕获隐藏、无边框、不主动激活和任务栏排除属性；嵌套或异常退出都会恢复作用域，不影响 Settings。
- 隐藏阶段设置原生辅助窗口策略、无边框保护、非客户区计算和精确物理范围。OCR 初始内容为冻结截图及暗色底图，标注初始内容为透明画布。
- 标注与 OCR 都在所有显示器准备通过后显示。标注删除了准备未完成时显示再隐藏的回退路径；失败销毁所属整组窗口。
- OCR 沿用可见绘制、后续事件循环和 DWM 同步交接；标注沿用原生分层位图及软件／GPU 呈现协调。两种呈现方式没有强行合并。
- `Host` 拒绝显示未准备的窗口，退休时使输入失效、停止定位任务并销毁组件。已有标注定位收尾仍归宿主任务管理，不用于等待首帧就绪。

## 输入、坐标与快照

原标注 `InputWork`、指针暂停和瞬态 `Slot` 已移至公共模块，旧标注模块仅保留导入兼容层。标注与 OCR 原生输入都使用所属实例的输入保护；排队工作在退休后失效，业务接收器继续校验会话及请求。

公共坐标函数转换屏幕物理坐标和窗口逻辑坐标。Core 的 `RegionSelection` 负责区域手势；标注对象变换与撤销事务仍独立。Core 的 `screen_snapshot::crop_frames` 提供多屏物理裁切、间隙填充、缓冲区长度及溢出检查；原 OCR 导出保留兼容转发，App 使用新入口。

Slint 的 `RegionPreview` 与 `ScreenInteractionHint` 只呈现选区、遮罩和提示。当前 OCR 使用它们；普通标注对象依旧通过现有渲染器绘制，不改变外观。未来标注内 OCR 可复用这些组件及区域结果，提交标注会话的稳定快照。

本次不更换采集后端，不新增 Port、配置、依赖或 crate，不接入标注 OCR 按钮。

## 验证

见 [共用宿主验证](../releases/screen-interaction-validation.md)。此前证据见 [OCR 首次显示验证](../releases/ocr-first-frame-validation.md)，历史采样未覆盖的边界不能当作当前验收结论。

## 模块所有权

标注实现集中在 UI 的 `annotation/`，OCR 独立宿主在 `ocr/selection`；设置桥接在 `ocr/provider`。这些目录调整不改变公共宿主、隐藏准备和首次呈现流程，也不合并两种业务会话。窗口 Bridge 的回调契约位于 `bridge/callbacks`，原生实现仍由 App 注入。
