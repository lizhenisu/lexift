# Settings 使用体验重构

## 目标与验收方法

覆盖常规、快捷键、划词助手、截图、翻译和 Provider 六页。以真实操作的可发现性、操作成本、视觉层级和错误恢复为准，不以页面能编译或截图数量作为完成依据。

- 常用设置直接可达，低频高级设置按需展开；保留各页独立职责。
- 同类控件的尺寸、文字中心、鼠标与键盘状态一致；焦点不能伪装成持续按下。
- 点击目标合理，长译文和窄窗口不截断必要说明；可滚动到全部设置。
- 即时设置、需要应用的草稿和独立凭证操作应明确区分。
- 普通可逆操作不增加确认；会丢失用户编辑或涉及敏感数据的操作需要适当恢复或确认。
- 弹层仅用于独立任务，不通过层层弹窗完成普通参数修改；取消、关闭和 Escape 行为一致。
- 全部 12 种语言、浅色／深色、100%／125% 缩放都应保持层级、可读性和输入能力。

## 2026-10-08：主动打开与关闭保护

- 用户主动打开 Settings 时，复用现有注入的窗口激活能力，将已有窗口带到前台；最小化窗口先恢复。不会重建窗口或重置草稿，不修改被动划词窗口的焦点策略。
- 普通即时设置直接关闭；尚未应用的连接、其他 Provider 中暂存的连接／模型参数、共用提示词、凭证输入及请求头输入会触发窗口内关闭确认。默认“继续编辑”，Enter 和 Escape 都不放弃草稿；只有“放弃并关闭”执行销毁。

- 销毁请求同时校验窗口 token 和关闭 generation，防止旧窗口确认或延迟任务销毁新实例。保持关闭后释放组件、草稿、任务和原生资源的策略。
