# 图片保存：PNG／JPEG

## 入口与策略

截图、长图采集中直接保存、图片编辑器、贴图、图片历史和普通桌面标注共用保存链路。原有保存按钮和快捷操作不变，工具提示与标题使用“保存图片”。

- 原生对话框提供 PNG 与 JPEG，每次默认 PNG，不记忆格式。
- PNG 保持无损及透明通道；JPEG 固定质量 95%，透明内容合成到白底，不提供质量控件。
- JPEG 默认扩展名 `.jpg`，接受 `.jpeg`，扩展名不区分大小写。切换 PNG／JPEG 时，自动替换已有的 `.png`／`.jpg`／`.jpeg` 后缀，保留文件名主体和目录；无扩展名由原生对话框补齐。选定格式后手工输入冲突后缀时仍在对话框内提示修正。
- 对话框确认后不修改目标路径；覆盖确认对应实际写入文件。取消或失败保留各入口原有重试与恢复规则。

## 资源与接口

历史恢复编辑器的保存按钮显式走独立图片输出流程，不依赖桌面截图处于活跃状态。

Core 的 `ImageFormat`、`ImageSaveOptions`、`ImageSaveRequest` 定义允许格式、默认格式、固定 JPEG 质量和本地化校验说明；继续使用 `ImageFilePort::save_image`。App 冻结最终合成结果并在后台调用 Port。UI 只提供翻译与事件，不编码图片。

Windows 复用 STA 原生保存对话框与 WIC。JPEG 将预乘 RGBA 直接合成白底后转换为 BGR，避免先还原 Alpha 引入边缘舍入；PNG 继续还原为直通 Alpha。原图、标注、采样数据、裁剪和历史均不改写。沿用 4000 万像素上限、取消机制、同目录临时写入及原子替换，关闭时释放 COM 和对话框事件订阅。

JPEG 压缩只影响保存文件。图片历史保留压缩前成品与完整可编辑资源；保存成功更新记录，取消和失败不更新。新截图成功保存仍按原规则更新 R；历史和长图结果输出不修改 R，普通桌面标注不新增图片历史。

验证见[专项验证](../releases/image-save-formats.md)。
