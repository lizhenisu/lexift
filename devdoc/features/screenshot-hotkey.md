# 独立截图快捷键

默认 **Alt+S** 直接进入首次框选，不先打开主页或标注工具条。Alt+A 继续控制标注工具条，工具条截图按钮及延迟菜单保持原行为。

## 设置与可用性

Settings 的快捷键页提供“截图”，与翻译、OCR、标注共用录制和保存流程，四键必须不同。修改时先注册新组合，成功后撤销旧组合；失败保持旧注册和配置。启动时新键最后注册，冲突不影响原有三键。主页分开显示真实生效的截图键和标注键；设置草稿不会作为生效按键。启动注册失败后，释放占用并在设置重新录入同一组合也会重试注册；已经生效的相同组合不重复执行。

Schema 11 增加 `screenshot_hotkey`，旧版本缺失字段使用 Alt+S，原设置保留。没有额外启用开关。Settings 录制期间，全局截图键交由录制控件处理，不进入截图；按键重复由既有原生机制抑制。

## 请求与恢复

原生回调携带触发时的前台身份及物理鼠标位置，由 Core 立即检查忙碌状态，再请求 UI 冻结文档。快照以请求编号隔离，区分已有工具条和无窗口后台来源；不模拟点击，也不借假工具条会话取得授权。

后台来源通过原生桥接取得显示器物理范围与 DPI，不创建工具条或画布。进入截图编辑后才建立正常编辑窗口。取消、失败或输出完成时，原先后台运行则继续后台；原有工具条、标注文档及历史则按既有链路恢复。显示器、焦点、贴图挂起、输出及选区历史继续使用共用截图流程。

截图倒计时／框选／编辑、长图、贴图编辑、独立图片编辑、OCR、导入、输出、显隐及策略处理忙碌时忽略请求；UI 额外检查绘制和拖动。不结束当前编辑、不排队补执行。用户切换外部应用后，仍受既有首次激活保护约束。同步收尾文字、关闭原画布时，只迁移本次文档确实拥有的前台身份；不会把已经切换的外部应用重新当作激活来源。
