# 长译文布局修复

## 原因与处理

原弹窗按字符数估算高度，忽略显式换行和实际字体宽度，并固定限制到 556 个逻辑像素。结果 ScrollView 未明确设置内容高度，内部 Text 又使用隐式位置和高度，可能在短视口中居中后裁剪。

现在按目标内容宽度通过 Slint 测量实际换行高度，原文卡片仍限制在 86–140 个逻辑像素，新增高度优先分配给译文。窗口最大高度由当前工作区和实际 DPI 决定；超过时滚动结果区，标题及操作按钮固定。译文与错误文本明确顶部对齐并设置完整内容高度。主窗口也补齐同样的滚动行为。

增高前按目标物理尺寸限制位置，跨屏后重新读取工作区并协调高度。测量任务由组件持有的单次计时器合并，读取当前会话状态；原生缩放期间不写回尺寸。原文草稿不会被测量任务暂时替换，避免反复触发布局或影响输入。

实机检查还发现复用软件缓冲区时可能保留旧的不透明边界缓存；新缓冲区渲染正常。物理表面尺寸或 DPI 变化时释放该弹窗相关的图形缓存并标记新表面失效，普通内容刷新和滚动不重复释放。没有重建渲染器、窗口或编辑实例。

## 验证记录（2026-10-07）

- 失败回归：大量显式换行文本在旧算法下得到 506 高度；新测量可达到测试工作区的 900 上限，并覆盖 480 的小工作区上限。
- 自动化覆盖中英混排、空行、长错误、宽窄窗口、结果滚动内容、主窗口及 100%／125% 软件渲染截图。相关 UI 全量回归通过。
- 实际 Windows App 使用本机临时 HTTP 夹具提供固定长译文，不依赖模型输出质量；经输入翻译、划词和 Alt+X 展示，确认首行及末行完整可访问，全文复制包含首尾标记。
- 125% 屏幕自动增长至工作区高度，移动到 100% 屏幕后重新限制高度与位置。截图：`target/translation-layout-native-*.png`；软件截图：`target/translation-layout-snapshots`。
- 最终 Release 实机确认同一弹窗由长译文切换到短译文后恢复为 420×336 逻辑像素；自动尺寸通知不会被误记为手动尺寸。UI 回归 334 项通过、10 项按原有条件忽略，UI Clippy（全部 targets，warnings 作为错误）、格式检查及 Windows Release 构建通过。
- 测试后恢复原配置及剪贴板，不改动用户模型。未实机覆盖负坐标、屏幕小于现有窗口最小尺寸、最大化及朗读播放；保留既有定位与手动缩放回归。Provider 和朗读实现没有修改。

```powershell
$env:LEXIFT_TRANSLATION_SNAPSHOT_DIR = "$PWD/target/translation-layout-snapshots"
cargo test -p lexift-ui
cargo clippy -p lexift-ui --all-targets -- -D warnings
cargo build -p lexift-app --release
```
