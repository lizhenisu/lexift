# Translation Popup sessions

The selection translation UI is a frameless, always-on-top Slint card managed by `lexift-ui`. Windows applies `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` before showing the card, then removes `WS_EX_NOACTIVATE` with an `SWP_NOACTIVATE` frame refresh immediately after the show completes. This keeps focus in the source application during passive display.

Slint creates the native HWND for a newly allocated top-level window on a later Winit event-loop turn. Passive preparation therefore reports `Pending` while the handle is unavailable. `PopupRegistry` retains the latest show request and retries after yielding to the event loop, then at 16 ms intervals for up to one second. Hiding or closing the session invalidates the pending generation. A temporary missing handle is not logged as a platform failure and never requires a second hotkey press.

Each Popup HWND installs one replaceable Win32 pointer bridge. It consumes mouse movement, leave, left-button, capture, and wheel messages before Winit and forwards them with `slint::Window::dispatch_event_with_result`. Client coordinates remain physical in `lexift-platform`; `lexift-ui` divides them by the live Slint scale factor, including wheel deltas, before dispatch. The first press uses a temporary `AttachThreadInput` connection to activate and focus the Popup, sends a position update before the press, and captures the mouse until release.

The HWND property `Lexift.PopupInputBridge` owns the bridge pointer and identifies an existing installation without relying on the unavailable `GetWindowSubclass` export. Reused HWNDs replace only the stored handler and reset transient pointer state. `WM_NCDESTROY` removes the property and subclass before releasing the bridge.

An unpinned window remains visible for passive reading, then closes on the next pointer press outside its bounds or on a subsequent foreground-window change. The initial foreground window is recorded when the popup is shown so passive display never dismisses it immediately. Pinning unregisters this monitor; pinned windows remain visible and always on top.

## Core ownership

`lexift-core` owns `PopupSessionId` and `PopupSessionState`. A session contains source and translated text, its user-selected source language, per-window target language, provider-detected source language, translation task, pin state, feedback, and speech state. `None` for the selected source language means automatic detection. The active unpinned session is reused by later selections and resets its source choice to automatic detection for every new capture. Pinning detaches it from the active slot, so the next selection creates another session while the pinned session keeps its source choice. Task IDs are checked per session, and results for superseded or closed sessions are ignored.

Changing either popup language only changes that session and immediately starts a new translation with the complete source/target context. It does not write Settings. An explicit source choice is preferred for source speech; automatic mode uses the provider-detected language. Copy and speech requests are explicit Core commands executed by adapters.

## UI and native lifecycle

Popup and Clipboard History share a 52 DIP header, 32 × 32 DIP action targets and 18 × 18 DIP SVG areas. Dedicated pin/close SVGs normalize their drawing bounds and stroke weight without changing other application icons. Both windows use the same eight-direction resize hit component; it renders no edge highlight and preserves the existing native resize/focus policy.

`PopupRegistry` runs on the Slint event-loop thread and maps session IDs to `TranslationPopup` windows. It creates windows only for live sessions and destroys each component after that session closes, including its pointer bridge, dismissal watch, pending show, drag, resize, and manual-size state. Fixed sessions keep independent windows until explicitly closed. New windows still use the pending-HWND retry path, so the first `Alt+X` displays the Popup. The registry applies Core snapshots, positions new windows by the selection anchor, offsets them from visible pinned windows, and clamps resized windows to the monitor work area. Each window attaches its own session ID to callbacks.

The card keeps source, language, and result sections visible. Source and result content grow within capped regions and scroll independently; the editable source area follows the text cursor and shows its vertical scrollbar only when needed. The compact language row reserves a fixed center swap area and divides the remaining width equally between source and target selectors. Provider detection remains session state for speech selection but is not rendered as a separate label.

### Popup visual refresh (2026-10-09)

The compact brand mark uses the existing translation SVG. Source content sits on a neutral surface; the result uses a restrained theme tint with a thin outline and a theme-colored section label. Both cards have 16-DIP corners. Language selectors sit directly on the shell, with hover and expanded feedback rather than a third filled card. Secondary action icons use the secondary foreground, while the translation action retains the primary accent and explicit hover/press feedback. All colors come from shared light/dark tokens. Window geometry, content measurements, native policies, drag/resize handles and translation callbacks are unchanged.

Local verification: `cargo test -p lexift-ui translation_layout_tests -- --test-threads=1` passes all three tests, including long-text scrolling and all eight resize handles. The render matrix covers light/dark, 340/420-DIP widths, 100%/125% scale, results, streaming, empty results and errors. Reviewed screenshots are in ignored `target/popup-visual-refresh/`; tests and strict UI Clippy logs are `target/popup-visual-tests.log` and `target/popup-visual-clippy.log`. These are software-rendered screenshots, not fresh physical-monitor or Shell verification.

The shared source/target language menu keeps its rectangular scrolling viewport 6 DIP inside the rounded shell. Rows have their own 6-DIP radius; scrollbar endpoints use the same inset. This prevents row and viewport backgrounds from painting through the shell corners, since the viewport clip does not follow the parent's rounded edge. Selection centering uses the inset viewport height. The added regression checks light/dark at 100%/125%, first/last selected rows, scrolling and row clicks (`target/popup-menu-tests.log`, renders in `target/popup-menu-corners/`).

The Popup's rounded opaque shell fills the native window bounds, so the interface reads as one window instead of a card inset on a white surround. Windows uses one outer-corner source: successful DWM setup lets the system clip the opaque surface; unavailable DWM rounding keeps a square opaque shell; other platforms use the Slint rounded shell. The title row is draggable below the top-edge resize strip, while the Pin and Close buttons remain interactive. The border provides eight invisible resize handles with directional cursors; hovering does not paint edge or corner accents. A handle only registers platform-side resize tracking; it starts no timer and schedules no paint. The center of the top 8-DIP strip uses Win32 `HTTOP` so DefWindowProc enters the non-client sizing loop directly, which is what lets Windows own its vertical-maximize preview. Other handles use upstream Winit's `drag_resize_window` with the matching `ResizeDirection`. Windows then owns the whole sizing loop and keeps the opposite edge anchored; the adapter never writes geometry during it. Slint's own window constraints (`min-width`, `min-height: resize-min-height`, `max-popup-width`, `max-popup-height`) travel through Winit into `WM_GETMINMAXINFO`, so size limits need no adapter code. During a native move or resize, Slint renders the Popup through the startup-selected renderer and follows the window geometry delivered by Winit. Only the software renderer installs the Win32 opaque background fill and release-time full-paint hook; FemtoVG relies on its own surface presentation. Cross-DPI movement and off-screen return must be checked before the mouse is released. While the handle that changes height is active, the source card follows the window height through `resize-changes-height`/`resize-fixed-remainder`; the rest of the card layout is the same as any other size change. That follow height is floored at `resize-min-source-height` and capped by `resize-max-source-height` (`window height - resize-layout-reserve-height`), so shrinking a tall Popup lets the result card absorb the change instead of collapsing the source card to nothing, and the card can never grow past the space the language row and the result card need. The cap has to live in the Slint expression because Windows shrinks the window itself in two cases the UI cannot observe in time: dragging the title row out of a top-edge snap restores the pre-snap rectangle, and a cross-DPI or cross-monitor move resizes the window, while both run inside a modal move loop that blocks the Slint event loop. The bridge therefore only re-clamps the saved card height after the mouse is released, which would otherwise leave the source card filling the whole window and push the rows below it out of view for the length of the drag. Popup size limits keep two invariants: the minimum height never exceeds the maximum, and the minimum never depends on the window's current height. It is the layout floor instead (`layout reserve + minimum source card`, 240 + 86 here, raised to the 336-DIP design floor), and every clamp goes through an ordering-safe helper because the release profile uses `panic = "abort"` and `f32::clamp` panics when `min > max`, so an inverted range must never reach the sizing loop. Deriving the floor from the live height (`window height - source card + minimum source card`) was wrong: a Popup with a short source text keeps its source card at the 86px minimum, so the derived minimum equalled the current height. After a vertical snap to the monitor work area that height was also the monitor maximum, which left Winit `WM_GETMINMAXINFO` bounds of exactly one value, and Windows then refused every height change: the four corners and the top edge looked dead while only horizontal drags still worked. The frame-copy and erase-fill implementations are historical diagnostics recorded in resize-performance.md. The background-band fill and release-time paint repair remain active only for software rendering. The native resize adapter still reports the final client size on release, including when the pointer did not move; cancellation, hiding, and destruction clear its transient state. The UI then applies the exact final size, refreshes the monitor work area from the Popup's current window center for cross-monitor clamps, and stores the manual size for the session. The adapter does not draw a preview and does not apply a full-height rectangle on release. Other resize directions and top-edge drags outside the trigger area retain Windows' normal anchored sizing behavior. The `WS_EX_TOOLWINDOW` style remains in place so the Popup stays out of the taskbar and Alt+Tab. After vertical resizing, the source editor grows only while the layout budget can still preserve the 44px language row and 104px minimum result card; any remaining height expands the result card. The same bound applies to the saved manual size and a reopened Popup, while shrinking keeps the source editor at least 86px high. Each session also stores the automatic-content baseline, so later text growth may extend its manual size while shorter content never reduces it. The record is discarded when the session closes or its window slot is reused. Interactive resizing writes no per-resize log line.

Both language selectors share one `PopupLanguageMenuWindow` instance at a time. It is created only when a selector opens and destroyed when the menu closes. The menu records whether its owner is the source or target selector, aligns to that control, shows up to ten rows, flips above the selector or reduces its scrollable height when the monitor work area is constrained, and never changes the translation card's size. Opening one side closes the other. Source options are automatic detection plus the reduced set accepted by DeepL as explicit source languages; target options retain their regional variants. Popup and Settings menus share the same menu typography tokens and snap scroll offsets to stable coordinates to keep Windows text rendering crisp across DPI scales.

While the language menu is open, dismissal monitoring moves from the parent Popup to the menu HWND. A click inside the menu selects a language for the owning session; a click elsewhere closes only the menu and then restores the parent's unpinned dismissal watch. Dragging, hiding, closing, or reusing the owning Popup also closes the menu and clears its scroll and pending native-window state. The menu uses the same delayed HWND preparation, native pointer bridge, DPI conversion, and tool-window ownership as translation windows.

Windows supplies passive/interactive style changes, native custom-title-bar dragging, outside-interaction monitoring, and a dedicated STA SAPI worker. The worker selects a matching installed voice by language when available, falls back to the system voice, replaces the current utterance on a new request, and reports completion or failure back to Core.

Popup sessions are intentionally in-memory only and end when their windows close or the process exits.

The Main and Settings components are also created on demand. Background startup creates no Slint window components. Closing Main with a working tray destroys the component while leaving the process, tray, global hotkey, and Slint event loop running; a tray or second-instance open request reconstructs Main from the latest Core snapshot. Closing or hiding Settings clears credential drafts and transient feedback before destroying it; opening Settings again reconstructs it from current state. Closing without a usable tray retains the existing exit behavior. Destroying the final window releases that window's renderer and its surface and GPU resources, when present; the process-level Slint/Winit event loop and allocator remain alive. After two minutes with no window components, the Windows adapter asks the OS to trim the process working set. This evicts resident pages but does not decommit private allocations or recreate the renderer backend, and pages may fault back in on the next UI request.

## Windows Shell identity: Settings only (2026-10-08)

Only the explicitly registered Settings instance may appear in the taskbar and Alt+Tab. Main, translation Popup (including pinned/editing), selection toolbar, annotation toolbars/editors/canvases, secondary panels, popovers, menus and native save/overwrite dialogs are excluded. This replaces the earlier Main + Settings exception.

UI owns the `WindowRole` and App maps it to Platform during hidden preparation; titles and UI language never identify Settings. Winit creation attributes default to `skip_taskbar(true)`. Main startup, tray/second-instance restoration and Settings opening use shared bounded preparation (20 attempts, 16 ms between retries), show only after readiness, and discard stale generations. Timers stop on close; callbacks hold no strong window reference. Preparation exhaustion destroys the hidden component. Activation and native frame/input behavior remain separate from Shell membership.

Platform `window_shell_policy.rs` owns one policy/subclass per HWND. Before backend extended-style writes, auxiliaries clear `WS_EX_APPWINDOW` and retain `WS_EX_TOOLWINDOW`; Settings does the reverse. Activation changes preserve the registered Shell role. `WM_NCDESTROY` removes the property/subclass and releases its state. The UI thread and native save STA also hold a thread-local `WH_CALLWNDPROC` guard, which prepares unregistered top-level windows before a showing `WM_WINDOWPOSCHANGING`; child windows are untouched. Native GPU/magnifier hosts explicitly install the same policy while hidden. The thread hooks observe only their own threads and are removed with their scopes. No periodic polling, post-click repair or window reconstruction is used.
