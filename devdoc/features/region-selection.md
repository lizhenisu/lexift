# 屏幕区域选择基础

## 职责边界

Core 的 `region_selection` 提供物理坐标矩形手势：开始、更新、四方向归一化、逐显示器裁剪预览、零面积不提交、确认及取消。`SelectionContext` 携带来源会话、请求编号和快照编号；结果不包含原生窗口或图像像素。

OCR 是当前唯一展示宿主。UI 创建每屏一个独立遮罩，转发原生物理像素指针事件，并将预览转换为该屏逻辑坐标。完成后提交 `SelectionSubmitted`，Core 校验上下文，再产生识别命令；App 校验快照编号并裁切自己持有的冻结图像。取消、替换或结束后释放整屏图像引用，识别只保留裁切结果。

未来标注工具条可复用手势及结果类型，从标注会话提供稳定快照并接入 OCR 区域提交，不需要再启动独立遮罩。此次没有添加标注 OCR 按钮，没有改变标注 Registry、撤销或采集生命周期；当前 OCR 入口只接受它自身登记的 standalone 上下文。

## 独立遮罩生命周期

窗口、输入和定位所有权现由 [共用屏幕交互宿主](screen-interaction.md) 管理；下述 OCR 首帧托底是该宿主的冻结截图展示策略。原生无边框属性在创建阶段即注入。

1. **隐藏创建**：先完成屏幕冻结，再创建 Slint 组件并设置图片及物理尺寸。
2. **原生准备**：App 注入独立准备回调；Platform 同步 Winit 无边框状态，安装 HWND 所属样式及非客户区保护，设置不激活、置顶、Shell 排除，使用 `SWP_FRAMECHANGED | SWP_NOACTIVATE` 设置精确客户区。
3. **初始画面准备**：同一冻结截图生成匹配 `#0008` 的暗色 BGRA 底图，所有显示器准备完成前不显示任一遮罩。
4. **显示与交接**：原生显示／首次可见绘制提供一次性底图。Slint 渲染通知只排入后续事件循环；还须发生可见 WM_PAINT，再通过原生消息和 DWM 同步释放底图。交接后调用既有完整画面修复，避免 GDI 托底与后端局部重绘相互覆盖。软件渲染器没有渲染通知时，以原生 WM_PAINT 返回作为替代边界。
5. **销毁**：完成、取消、失败或请求替换即销毁整组组件，停止准备计时并清理图片、输入钩子及所属子类。准备失败不显示未配置窗口。

取消监听只负责 Escape 等取消，不再修改外观。窗口不进入 Winit fullscreen，不通过持续轮询、固定等待时间或隐藏重开修复显示。渲染及输入回调同时验证请求与实际组件实例；原生延迟交接消息校验单调实例标识，避免 HWND 复用造成串扰。
